# LingBuilder 微信OCR识别模块（lingbuilder.ocr）

借用本机微信 4.x 自带 OCR 组件的离线文字识别。不随包分发任何腾讯文件：运行时探测用户本机已安装的微信，加载其 `mmmojo_64.dll`，由其拉起 `Weixin.exe --type=wxocr` 组件子进程，通过本地 IPC 完成识别。中文识别质量与微信截图文字识别一致。

## 前置条件

- 已安装 Windows 版微信 4.x（默认路径或标准安装路径）。
- 微信已下载 OCR 组件：在本机微信里使用一次「截图 → 文字识别」即可触发下载（`%APPDATA%\Tencent\xwechat\XPlugin\Plugins\WeChatOcr` 目录出现即已就绪）。未就绪时 `OCR_取微信状态` 的 error 字段会带操作指引。
- 仅支持 **64 位（x64）构建**：微信 4.x 只有 64 位组件；32 位程序中全部命令返回 0/空文本，错误信息提示切换 x64。
- 不需要微信正在运行，也不需要登录。

开发调试可用环境变量覆盖探测结果：`LINGBUILDER_WXOCR_DLL`（wxocr.dll 完整路径）与 `LINGBUILDER_WXOCR_DIR`（微信版本目录），两者需同时设置。

## 运行模型

- **懒启动**：首次 `OCR_识别` 自动探测微信并启动组件进程（握手超时 15 秒），之后组件常驻、单图识别通常秒级（超时上限 120 秒）。
- **断线自愈**：组件进程意外退出后，下一次识别自动重新拉起；也可显式 `OCR_停止` 复位会话。
- **识别结果**是受管句柄，必须 `OCR结果_释放`；行级坐标为原图像素坐标。
- mmmojo 模块加载后进程内不卸载（微信组件运行时约束），`OCR_停止` 只停组件进程不卸模块。

## 命令表

| 分组 | 命令 | 说明 |
| --- | --- | --- |
| 生命周期 | `OCR_取版本` | 模块版本与实现口径。 |
| 生命周期 | `OCR_取微信状态` | 探测本机微信与 OCR 组件（不启动进程），返回 JSON。 |
| 生命周期 | `OCR_取错误` | 当前线程最近一次中文错误。 |
| 生命周期 | `OCR_停止` | 停止组件进程并复位会话，下次识别自动重启。 |
| 识别 | `OCR_识别(图片路径)` | 识别图片全部文字，返回 OCR结果句柄；失败返回 0。 |
| 识别 | `OCR_识别字节集(图片数据)` | 字节集内存入口：传图片文件内容（PNG/JPG/BMP 等）直接识别，无需先落盘；组件直传不可用时内部经临时文件识别并即时删除。 |
| 结果 | `OCR结果_取行数(结果)` | 识别行数。 |
| 结果 | `OCR结果_取文本(结果, 索引)` | 指定行文本（索引从 0 起）。 |
| 结果 | `OCR结果_取全部文本(结果, 换行分隔)` | 全部行拼接；真=回车换行、假=空格分隔。 |
| 结果 | `OCR结果_取置信度(结果, 索引)` | 指定行置信度 0～1。 |
| 结果 | `OCR结果_取左/上/右/下坐标(结果, 索引)` | 指定行包围盒坐标（像素）；越界 -1。 |
| 结果 | `OCR结果_取宽度(结果)`、`OCR结果_取高度(结果)` | 原图尺寸。 |
| 结果 | `OCR结果_取JSON(结果)` | 完整结果 JSON：errcode、width、height、lines[]（text、rate、坐标、chars[] 字符级坐标）。 |
| 结果 | `OCR结果_释放(结果)`、`OCR结果_释放全部` | 释放受管句柄。 |

## 示例

```text
局部 OCR结果句柄 结果 = OCR_识别("截图.png")
如果 结果 != 0
    调试输出(OCR结果_取全部文本(结果, 真))
    OCR结果_释放(结果)
否则
    调试输出(OCR_取错误())
结束
```

更多示例见 `docs/modules/wechat-ocr/examples/`。

## 调用红线

以下五条都是真实工程复踩过的坑（构建全部报成功，问题只在运行期暴露），写 OCR 相关代码时逐条对照：

1. **遍历识别行要折算索引**。`计次循环首 (行数, 行)` 的计次变量**从 1 起**，而 `OCR结果_取文本/取左坐标/…` 的行索引**从 0 起**。直接把计次变量当索引，会静默漏掉第一条识别结果（屏幕上最上面那行文字），最后一次迭代还会越界（取到空文本、坐标 -1）。正确写法是先 `索引 = 行 - 1` 再取数据，或直接用本模块示例的 `计次循环 首尾 = 1 到 行数` + `首尾 - 1`。
2. **一条中文语句写在一个物理行内**。跨行续写（例如把一条 `调试输出(...)` 拆成三行）会被生成器整条降级成 `// 暂不支持的中文 C++ 语句` 注释，构建仍返回成功、诊断区一片干净，但那段逻辑没了。长文本用 `格式化文本("…{}…", …)` 一行写完。
3. **依赖时序的局部变量先声明后赋值**。带初值的 `局部 文本型 X = 某命令()` 会被提升到方法最前，于是「先判 `剪贴板_是否有图片()` 再取字节集」这类守卫会被跑到判断之前。只有与执行流无关的字面量初始化可以带初值。
4. **识别必须放在工作线程**。握手最长 15 秒、单图最长 120 秒，在窗口事件里同步调用会冻结界面且无法取消。用 `线程_提交完成(&工作处理器, &完成处理器, 参数)`（启用 `lingbuilder.threading`），工作处理器只算数据、完成处理器回界面线程写控件；工作处理器里禁止任何 `控件_*` 调用。
5. **`OCR_取错误()` 是线程本地错误**。必须在工作线程内就地读取，再随工作处理器的返回值带出，或用 `抛出(...)` 让任务失败后经 `线程_取错误(任务)` 取回；回到界面线程再读只会拿到空文本。受管句柄判有效只用 `!= 0` / `= 0`，用完必须 `OCR结果_释放`。

另外：本模块只有 64 位实现，工程的构建架构要是 x64（工作区 `.lingbuilder/build-configuration.json` 顶层 `architecture`）。启用本模块后 F5 会自动切到 x64；32 位构建里每条命令都只返回「仅支持 64 位程序」的中文错误。

## 边界与合规

- 本模块只做「识别用户提供的图片并返回文本/坐标」，不提供浏览器自动化、拖动或验证提交等后续动作。
- 微信及其 OCR 组件版权归腾讯；模块运行时借用用户本机已安装的微信，使用本模块产生的合规责任由使用者自行确认。
- 微信大版本升级可能改变组件行为；识别失败时优先 `OCR_停止` 后重试，仍失败请检查微信版本。
