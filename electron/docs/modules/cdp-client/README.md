# CDP 客户端模块 3.1 使用说明

`lingbuilder.cdp.client` 是 LingBuilder 内置的 Chrome DevTools Protocol（CDP）受管客户端模块。它让 LingBuilder 生成的程序通过 WebSocket 连接 Chrome/Edge 的调试端口，完成浏览器自动化、页面监听与数据采集。异步命令通过 `&处理器名` 在 UI 线程回调。

## 支持范围（阶段 3 完成）

已支持阶段 1/2 的多连接、页面自动化、Fetch、对话框、下载、上传、仿真与输出；阶段 3 的 Target/Session/Frame/ExecutionContext 注册表与自动附加、OOPIF/Worker 会话执行、Runtime binding、Overlay 高亮、多点触控、Debugger 断点/暂停/单步/调用帧/作用域、Performance 指标、Storage usage/清理、严格证书错误逐次裁决、版本化录制文件。

3.1 新增并补齐：性能长任务（堆快照/追踪/CPU 分析/精确覆盖率，输出落盘）、画面串流（帧解码落盘 + 串流帧事件）、录制自动采集（模块命令层挂钩）与确定性回放执行器。当前清单共 161 条命令、14 个受管类型。

## 性能长任务（堆快照 / 追踪 / CPU / 覆盖率）

- `CDP_开始堆快照(页面, "heap.heapsnapshot", &完成)` 拍摄 V8 堆快照，分块流式写入 `.heapsnapshot` 文件（Chrome DevTools Memory 面板可直接打开）；`HeapProfiler.reportHeapSnapshotProgress` 驱动 `CDP_取任务进度` 的百分比。
- `CDP_开始追踪(页面, 类别, "trace.json", &完成)` 启动 Tracing（`transferMode=ReturnAsStream`，`IO.read` 轮询流式落盘）；类别为逗号分隔文本，空使用默认 `devtools.timeline,v8.execute,disabled-by-default-devtools.timeline`。用 `CDP_停止任务(任务, &完成)` 结束采集，`Tracing.tracingComplete` 后数据写完触发“任务完成”。
- `CDP_开始CPU分析(页面, "cpu.json", &完成)` 启动 `Profiler` 采样，开始成功触发“任务已开始”；`CDP_停止任务` 发送 `Profiler.stop`，把 Profile JSON 写入输出文件后触发“任务完成”。
- `CDP_开始覆盖率(页面, "coverage.json", &完成)` 启动 `Profiler.startPreciseCoverage`（callCount + detailed）；`CDP_停止任务` 取回 `takePreciseCoverage` 结果写入 JSON 文件。
- 任务事件：`任务已开始`、`任务完成`（文本=输出文件路径）、`任务失败`；事件内用 `CDP_取当前任务()` 取任务句柄。任务命令不受 30 秒命令超时约束（大页面堆快照可能超过常规超时），断开连接会丢弃未完成任务并删除临时文件。
- 查询：`CDP_取任务状态`（已创建/记录中/已完成/失败）、`CDP_取任务进度`、`CDP_取任务结果路径`。

## 画面串流

`CDP_开始串流(页面, 输出目录, 参数JSON, &帧处理器)` 启动 `Page.startScreencast`：每帧 base64 解码后原子写入输出目录（文件名 `串流帧_000001.jpg/png`），随后发送 `Page.screencastFrameAck`（不 ack 浏览器会停帧）并触发“串流帧”事件——文本=帧文件路径、详情=帧元数据 JSON（含 offsetTop/pageScaleFactor 等）、辅助数值=帧序号。

参数 JSON 字段全部可缺省：`格式`（jpeg/png，默认 jpeg）、`质量`（0-100，默认 60）、`最大宽度`、`最大高度`、`每N帧`（1-60，默认 1）。高频页面务必用 `每N帧` 降帧，避免事件队列（65536 上限）被帧事件挤占。`CDP_停止串流(页面)` 停止；页面释放或断开连接自动停止。

## 录制自动采集

`CDP_开始录制` 期间，该页面上的模块命令会**自动固化为结构化步骤**（无需手工 `CDP_记录步骤`）：

- `CDP_打开网址` → `导航`（网址）；`CDP_刷新页面` → `刷新`
- `CDP_点击元素` → `点击`（选择器）；`CDP_输入文本` → `输入`（选择器、文本）
- `CDP_按键` → `按键`；`CDP_组合键` → `组合键`；`CDP_插入文本` → `插入文本`
- `CDP_鼠标单击` → `鼠标点击`（横/纵坐标、按钮、次数）；`CDP_鼠标滚轮` → `滚轮`；`CDP_鼠标拖拽` → `拖拽`
- `CDP_执行脚本` → `脚本`（代码）；`CDP_设置元素文件` → `上传文件`（选择器、文件）

自动采集发生在命令层（受管客户端自身动作），不解析浏览器原生输入事件，步骤天然结构化；含 password/token/secret/authorization 关键字的步骤数据整体脱敏为 `${SECRET:REDACTED}`。回放执行期间不重复采集。手工 `CDP_记录步骤` 仍可用于补充自定义步骤。

## 确定性回放执行器

`CDP_加载回放(连接, "操作录制.json")` 解析 `lingbuilder.cdp.recording`（schemaVersion 1）文件得到步骤列表；`CDP_执行回放(回放, 页面, &完成)` 在指定页面上按顺序重放：

- `导航` 步骤经 `Page.navigate` 并等待 `loadEventFired`；`点击`/`输入`/`上传文件` 步骤按选择器重新查询元素（滚动进入视口、聚焦后逐字符输入）；`按键`/`组合键`/`鼠标点击`/`滚轮`/`拖拽`/`插入文本`/`脚本` 步骤重新派发同参数输入。
- **失败即中止**：任一步骤发送失败或导航等待超时，立即结束并触发“回放失败”事件（文本=摘要 JSON：总步骤/已执行/失败步骤/状态，错误保留原文）。
- 全部步骤完成触发“回放完成”事件；`CDP_取当前回放()` 在完成处理器内取回放句柄，`CDP_取回放状态` 返回 `执行中 第N/M步` 等进度。
- `CDP_停止回放(回放)` 请求停止：当前步骤完成后不再继续，状态“已停止”。
- 页面释放或连接断开时回放自动失败，不会悬挂。确定性边界：回放重放的是「意图步骤」，页面内容与录制时不同时按选择器重新定位，不做逐像素会话还原。

## 多开与连接

CDP 模块支持同时连接多个调试端口。每个 `CDP_连接` 调用创建独立的受管连接（独立 WebSocket、独立消息编号、独立回调表），连接之间互不干扰；`CDP_取连接数量()` 可查询当前并存连接数。

```lcpp
CDP连接 连接A ＝ CDP_连接("http://127.0.0.1:9222", &连接A就绪)
CDP连接 连接B ＝ CDP_连接("http://127.0.0.1:9333", &连接B就绪)
```

## 安全边界

- `CDP_连接` 只允许本机 `127.0.0.1`、`localhost` 或 `::1`；连接远程地址必须显式使用 `CDP_连接远程`，并自行确认目标主机与网络链路可信。
- 调试端口拥有浏览器完整控制权。请只对自己显式以 `--remote-debugging-port` 启动的浏览器开放连接。
- Cookie 读取结果属于敏感数据，不得写入日志或项目分享包。

## 启动浏览器调试端口

```text
chrome.exe --remote-debugging-port=9222 --user-data-dir=C:\CDPProfile
msedge.exe --remote-debugging-port=9222 --user-data-dir=C:\CDPProfile
```

headless 模式：追加 `--headless=new --disable-gpu`。

## 调用方式与处理器

全部异步命令提交后立即返回（`逻辑型` 表示是否成功提交），结果通过完成处理器通知。处理器内使用 `CDP_取当前事件类型()` 判断成败，用 `CDP_取当前事件文本()` 读取结果，用 `CDP_取当前错误()` 读取中文错误（保留 CDP 原始信息）。

事件类型清单：`已就绪`、`连接失败`、`已断开`、`页面就绪`、`页面失败`、`加载完成`、`页面销毁`、`命令完成`、`命令失败`、`网络请求`、`网络响应`、`网络完成`、`网络失败`、`请求被拦截`、`需要认证`、`对话框出现`、`下载开始`、`下载进度`、`下载完成`、`下载取消`、`新页面出现`、`控制台`、`页面异常`、`任务已开始`、`任务完成`、`任务失败`、`串流帧`、`回放完成`、`回放失败`。

## 命令超时

每个连接的异步命令默认 30 秒超时（导航与就绪等待使用两倍上限），超时以“命令失败”事件通知并保留原始命令名。`CDP_设置命令超时(连接, 毫秒)` 可调整（1000-600000）。

## 请求拦截（Fetch 域）

`CDP_拦截开始(页面, 网址模式, &处理器)` 后，匹配模式（如 `*://api.example.com/*`，`*` 匹配全部）的请求会暂停并触发“请求被拦截”事件。**拦截期间浏览器网络挂起**，处理器内必须尽快用 `CDP_取当前拦截()` 取得的句柄做一次裁决：

- `CDP_拦截继续(拦截)` —— 原样放行；
- `CDP_拦截改写(拦截, 网址, 头JSON)` —— 改写 URL 和/或请求头后放行（头为 `[{名称, 值}]` JSON 数组整体替换）；
- `CDP_拦截模拟响应(拦截, 状态码, 头JSON, 响应体)` —— 不发往服务器直接返回 mock 响应；
- `CDP_拦截终止(拦截, 失败原因)` —— 以网络错误终止（Failed/Aborted/TimedOut 等）；
- “需要认证”事件用 `CDP_拦截应答认证(拦截, 用户名, 密码)`，用户名为空表示取消。

快照：网址/方法/请求编号用 `CDP_取当前网络网址/方法/编号`，请求头 JSON 用 `CDP_取当前事件文本`，详情（请求阶段/响应阶段）用 `CDP_取当前事件详情`；请求体用 `CDP_取拦截请求体(拦截, &完成)`。页面释放时未裁决拦截会自动终止。`CDP_拦截停止(页面)` 停止拦截。

## 对话框与下载

对话框：`CDP_绑定对话框事件(页面, &处理器)` 订阅 alert/confirm/prompt/beforeunload；**对话框打开期间页面脚本阻塞**，处理器内必须尽快 `CDP_应答对话框(页面, 接受, 提示文本)`。快照：`CDP_取当前对话框消息/类型/默认文本`。未绑定时运行时自动拒绝。

下载：`CDP_设置下载目录(连接, 目录, 真)` 允许下载到已存在的目录，`CDP_绑定下载事件(连接, &处理器)` 订阅下载开始/进度/完成/取消。快照：`CDP_取当前下载文件名`、`CDP_取当前下载进度`。

## 文件上传与等待

`CDP_设置元素文件(元素, 文件路径, &完成)` 为文件选择控件设置上传文件（文件必须真实存在）。`CDP_等待加载(页面, 事件类型, 超时秒, &完成)` 等待生命周期事件：0=load、1=DOMContentLoaded、2=networkIdle、3=networkAlmostIdle。

## 设备与网络仿真

`CDP_设置视口(页面, 宽, 高)`、`CDP_设置UserAgent`、`CDP_设置触摸`、`CDP_设置地理位置(页面, 纬度, 经度)`、`CDP_设置时区`、`CDP_设置语言`、`CDP_设置暗色模式`、`CDP_设置CPU节流(页面, 倍率)`、`CDP_重置仿真(页面)`；网络：`CDP_设置离线`、`CDP_设置限速(页面, 延迟毫秒, 下行, 上行)`（字节每秒，-1 不限）、`CDP_禁用缓存`。

## 阶段 3 Target、调试与安全

- `CDP_设置自动附加` + `CDP_绑定目标事件` 管理 OOPIF 和 Worker；用 `CDP_枚举目标JSON`、`CDP_附加目标`、`CDP_会话执行脚本` 操作独立会话，不能把 Worker 伪装成页面。
- `CDP_添加页面绑定` 接收页面 `Runtime.bindingCalled`；事件载荷从 `CDP_取当前事件文本` 读取。`CDP_高亮元素` 使用 Overlay，`CDP_派发触摸` 接收最多 16 个触点的严格 JSON。
- Debugger 使用 `CDP_启用调试器`、`CDP_设置断点`、暂停/恢复/单步；暂停事件中用 `CDP_取当前调用帧数量` 和 `CDP_取当前调用帧` 获取 generation 受限句柄，恢复后旧句柄失效。
- Storage 清理必须调用 `CDP_清理来源数据` 并传 exact origin、allowlist storageTypes 和显式确认。
- 证书错误接管只能使用 advanced 命令 `CDP_开启证书错误接管`：白名单必须是 exact origin、期限 1–600 秒，每个错误必须用 `CDP_裁决证书错误` 单独决定；未应答、超时、关闭或断线一律取消，不提供通配符或全局忽略开关。
- `CDP_开始录制` / `CDP_记录步骤` / `CDP_停止录制` 写入 `lingbuilder.cdp.recording`、`schemaVersion:1` JSON；敏感字段会替换为 `${SECRET:REDACTED}`。当前 `CDP_加载回放` 只建立受管回放状态，确定性执行器仍在实施。

## 本机无头浏览器（真无头，零窗口）

`CDP_启动浏览器(参数JSON, &就绪处理器)` 自动查找本机 msedge/chrome，以 `--headless=new --remote-debugging-port=0 --user-data-dir=<独立临时目录>` 创建**独立浏览器进程**，等待用户数据目录里的 `DevToolsActivePort` 写出实际端口后自动建立 CDP 连接，返回受管连接 ID。参数 JSON 字段（全部可缺省）：`可执行文件`、`用户数据目录`（父目录）、`额外参数`（追加命令行开关）、`起始地址`（默认 about:blank）、`等待超时毫秒`（2000~60000）。返回 0 时立即用 `CDP_取最后错误()` 读中文失败原因。

- 截图/PDF/网络拦截/脚本求值全部真实可用（与有头浏览器同一渲染管线，仅无窗口）；需要页面图像或 PDF 的后台任务请走这条路，而不是 EdgeView 无头实例（隐窗宿主不渲染像素）。
- `CDP_停止浏览器(连接)` 先 `Browser.close` 优雅退出、3 秒超时强制终止，并清理独立用户数据目录；`CDP_停止全部浏览器()` 批量回收；进程退出自动回收，不留孤儿进程。
- 控制台项目可直接使用：入口自动创建的无头泵窗口承接就绪/完成处理器，配合 `EdgeView_泵消息(毫秒)` 或 `线程_等待` 轮询即可（同步失败原因用 `CDP_取最后错误`）。
- 独立浏览器进程与 WebView2 进程内实例（EdgeView 模块）Profile/Cookie 互不相通；代理、UA 用 `CDP_设置UserAgent` 与额外参数 `--proxy-server=...` 配置。

```text
无头连接 = CDP_启动浏览器("{""起始地址"":""https://example.com""}", &浏览器就绪)
```

## 依赖与平台限制

- 目标平台：Windows MSVC（win32 与 x64），依赖 `winhttp.lib`、`crypt32.lib`（系统库）。
- WebSocket 通过 WinHTTP 协议扩展实现，不引入第三方运行库；JSON 编解码内嵌在模块运行时中。
- 浏览器要求：Chrome/Edge 78+ 或同源 Chromium（含 FBro 内嵌浏览器，可用 `FBro_取调试端口` 获取地址后连接）。
- 已知限制：拦截与对话框事件期间浏览器/页面会挂起，处理器必须尽快裁决；网络事件高频页面下事件队列超过 65536 条会丢弃最旧事件；`CDP_绑定新页面事件` 的“新页面出现”包含 `CDP_新建页面` 自己创建的标签页；headless 模式下部分浏览器窗口边界（`CDP_设置窗口边界`）不生效。
