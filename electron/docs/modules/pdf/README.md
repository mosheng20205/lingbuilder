# PDF 文档模块 1.0 使用说明

PDF 文档模块（`lingbuilder.data.pdf`）基于 PDFium 158（Chrome 同款 PDF 内核，Apache-2.0）提供 PDF 读取与加工：逐页/全文文本提取（行序重建）、无文本层判断（扫描件分流 OCR）、页面渲染 PNG、内嵌图片提取、拆分与合并、转 Word 文本流，以及经本机 Office/WPS 的外部文档转 PDF。

## 运行时资产（lingbuilder.pdf.sdk）

本模块是 **x64 专用**（与 OpenCV 模块同策略），运行时需要两个 DLL 位于 exe 同目录，由 `lingbuilder.pdf.sdk` 受管资产模块提供并经哈希校验后自动物化：

- `pdfium.dll` — PDFium 158（文本/渲染/图片/页面操作内核）
- `LingBuilderPdf.dll` — LingBuilder 稳定 C ABI 桥（动态加载 pdfium，不静态链接）

`PDF_是否可用()` 可在运行时探测资产是否就位。

## 文本提取与行序重建

PDF 内部只有「带坐标的字形」，`PDF_取页面文本` / `PDF_取全部文本` 按 **y 聚类成行、行内按 x 排序**重建阅读顺序——双栏 PDF 也能得到正确的行序；西文词间距过大会补空格，CJK 不补。

```lcpp
局部 PDF文档 文档 = PDF_打开("资料/合同.pdf")
如果 文档 != 0
    如果 PDF_是否有文本层(文档, 1)
        调试输出(PDF_取全部文本(文档))
    否则
        调试输出("扫描件：无文本层，请配合 OCR 模块识别")
    结束
    PDF_关闭(文档)
结束
```

**扫描件分流**是核心设计：`PDF_是否有文本层` 为假说明该页是扫描图片，直接提文本得到空——正确路径是先 `PDF_渲染页面PNG` 生成图片再交给 OCR 模块（`lingbuilder.ocr`）识别。

## 渲染与图片

- `PDF_渲染页面PNG(文档, 页号, 缩放倍率, 输出路径)`：缩放 0.1～8（1≈72dpi、2≈144dpi），白底 RGB；上限 6400 万像素。
- `PDF_取图片数` / `PDF_提取图片`：按页面对象顺序提取内嵌图片为 PNG。

## 拆分与合并

- `PDF_拆分页面(文档, 起始页, 结束页, 输出)`：页码区间导出为新 PDF。
- `PDF_合并文档(甲, 乙, 输出)`：两个已打开文档顺序合并。

## 转换

**`PDF_转Word文本流`**（内容级）：PDF 文本按行聚类成段落写成可编辑 .docx，每页前插入「— 第 N 页 —」分隔。定位是**内容可编辑、版面近似**——复杂排版请在 Word 中调整；图片与表格结构不迁移；无文本层明确报错并提示改走 OCR。

**`PDF_外部文档转PDF`**（高保真，Tier C COM 链）：把本机 .docx/.xlsx 经 **Office/WPS 自动检测链**（Word → WPS / Excel → WPS 表格）转成 PDF。转换在独立脚本进程（cscript）中执行——引擎崩溃不拖垮主程序，单文件 180 秒超时；未装 Office/WPS 给明确中文提示。`PDF_取Office转换引擎()` 返回当前可用引擎名。

与 Word 模块的分工：`Word_导出PDF` 服务于**本模块生成的文档子集**（免装 Office）；`PDF_外部文档转PDF` 服务于**任意 docx/xlsx 的保真转换**（需本机 Office/WPS）。

## 命令与返回值

22 条命令分七族：文档生命周期（打开/打开字节集/关闭/释放全部）、页面信息与文本（页数/宽/高/页文本/全文本/是否有文本层）、渲染（渲染PNG/图片数/提取图片）、页面（拆分/合并）、转换（转Word文本流/外部文档转PDF/取Office转换引擎）、诊断（取错误/取版本/是否可用）。

失败时返回 0/假并更新线程级中文错误，`PDF_取错误()` 读取最近一次错误。加密 PDF（需要密码）与损坏文件都会被明确拒绝。
