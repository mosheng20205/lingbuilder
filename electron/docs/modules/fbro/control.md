# FBroBrowser 控件与进程模式

## 设计器控件

控件类型为 `FBroBrowser`，所有在 `.lcpp` 中传入控件的参数都必须使用裸控件名，例如：

```text
FBro_导航(浏览器1, "https://example.com")
```

不要写成 `FBro_导航("浏览器1", ...)`。编辑器、诊断、补全和 C++ 生成器会把该参数识别为 `controlRef`。

主要属性：

| 属性 | 说明 |
|---|---|
| `url` | 初始地址。建议使用完整 `https://` 地址。 |
| `processMode` | `in-process`、`independent-embedded` 或 `independent-window`。 |
| `cacheDir` | 独立 Profile/缓存目录；多实例应使用不同目录。 |
| `userAgent` | 创建前使用的 User-Agent。 |
| `enableJs` | 是否启用 JavaScript。 |
| `enableDevTools` | 是否允许开发者工具。 |
| `loadImages` / `enableWebGL` | 图片与 WebGL 开关。 |
| `muteAudio` | 是否静音。 |
| `proxyMode` / `proxyServer` | 系统、直连或自定义代理。 |
| `fingerprintProfile` | 结构化指纹 JSON；需要有效 VIP 授权。 |

## 进程模式

- `in-process`：浏览器与主程序共享进程，启动简单、开销较低；不能与 CEF3 150 进程内 ABI 混用。
- `independent-embedded`：每个浏览器使用独立 FBro Host，但页面仍嵌入设计器窗口，适合多个浏览器并存。
- `independent-window`：每个浏览器使用独立顶层窗口，适合需要完全隔离窗口生命周期的场景。

独立模式为每个实例分配独立 Profile、回环 WebSocket、Token、日志目录和 CDP 端口。不要手工复用这些运行时目录或端口。

## CDP 调试端口

两种宿主模式都能用 `FBro_取调试端口(控件名)` 取得本机回环 CDP 调试端口，供 CDP 模块连接：

- 独立进程：Host 启动时按 `enableDevTools` 决定是否预留端口。
- 进程内：程序初始化 FBro 运行时时按项目内进程内控件的 `enableDevTools` 属性决定是否预留回环端口——任一进程内控件启用开发者工具（缺省为启用）即开启；全部关闭则不预留。CEF 的调试端口只在初始化时生效，无法事后补设或关闭，因此没有运行时设置端口的命令。`FBro_取调试端口` 返回 0 表示尚未初始化、未启用开发者工具或端口预留失败。

调试端口只在本机回环使用，不要暴露到公网。

## 事件绑定

```text
FBro_绑定事件(浏览器1, "加载状态改变", &浏览器1_加载状态改变)

事件 浏览器1_加载状态改变()
    如果 (FBro_是否加载中(浏览器1) == 0)
        调试输出(FBro_取标题(浏览器1), FBro_取地址(浏览器1))
    如果结束
结束
```

处理器引用必须使用 `&处理器名`，不能加引号。多个浏览器应分别绑定自己的处理器，避免把事件状态误读为另一个实例。

## 容器与布局

`GroupBox` 是适合多浏览器示例的绝对布局容器。浏览器控件设置 `parentId` 指向分组框，坐标仍使用窗口坐标，便于原生 Win32 生成器确定性重建。每个浏览器实例应使用不同的 `cacheDir`。

## 响应正文替换

`lingbuilder.fbro.browser` 提供两类互不替代的响应改写能力：

| 命令族 | 授权 | 语义 |
| --- | --- | --- |
| `FBro_替换资源响应内容` / `FBro_替换资源响应文件` / `FBro_清除资源响应替换` / `FBro_清空资源响应替换` | 需要 FBro VIP | 按地址精确匹配，把命中资源的整个响应替换为文本或本地文件（类型与状态码可由规则指定）。 |
| `FBro_替换资源响应文本(控件名, 查找内容, 替换内容)` / `FBro_清除资源响应文本替换(控件名)` | 无需 VIP | 对之后加载的全部资源正文做 UTF-8 字节级流式查找替换（二进制安全、跨块匹配、替换内容为空表示删除），只改正文，不改响应头和状态码。 |

非 VIP 查找替换基于官方 `FBroHsResponseFilter`（`FBroHsResponseFilter_Create` 包装安装，与火山「资源篡改实例」同款路径），重复调用以最后一次为准；正在传输中的资源沿用其安装时复制到的配置。同一请求内与 `FBro_读资源响应正文` 并存时，正文捕获记录的是服务器原始正文。

时序约束：`创建完毕` 事件内浏览器尚未就绪，`FBro_导航` 会静默失败。正确写法是「创建完毕」内绑定 `浏览器创建完成` 事件、下发替换配置，在创建完成处理器内再导航；首个页面的响应即被改写。已加载页面不受后续配置影响，重新导航即可见效。

```text
事件 _窗体_创建完毕()
    FBro_绑定事件(浏览器1, "浏览器创建完成", &浏览器1_创建完成)
    FBro_替换资源响应文本(浏览器1, "原始价格", "会员价格")
结束

事件 浏览器1_创建完成()
    FBro_导航(浏览器1, "https://www.example.com/")
结束
```

## 输入注入

`FBro_发送鼠标单击事件`、`FBro_发送鼠标移动事件`、`FBro_发送鼠标滚轮事件`、`FBro_发送按键事件`、`FBro_发送触摸事件` 把合成事件派发给浏览器宿主的内核输入管线，等效真实用户输入（页面收到的事件带 `isTrusted`），与 `FBro_执行JS` 里 `dispatchEvent` 派发的合成事件有本质区别：前端框架和反自动化脚本通常只信任前者。

- 按钮类型：0=左键、1=中键、2=右键；双击传 `单击次数` 2。
- 按键事件类型：0=原始按下、1=按下、2=释放、3=字符输入；输入文本通常成对发送「按下/释放」或直接发类型 3 的字符。
- `字符编码`/`未修改字符编码` 为宽字符拆分编码：低 8 位为低字节，高 8 位为高字节（ASCII 直接传同值即可）。
- 触摸事件压力范围 0~1，旋转角度单位为弧度。

```text
' 点击搜索框并输入关键词后提交
FBro_发送鼠标单击事件(浏览器1, 0, 320, 180, 0, 假, 1)
FBro_发送按键事件(浏览器1, 3, 0, 0, 0, 假, 76, 76, 真)
FBro_发送按键事件(浏览器1, 1, 0, 13, 0, 假, 13, 13, 真)
FBro_发送按键事件(浏览器1, 2, 0, 13, 0, 假, 13, 13, 真)
```

三种进程模式（进程内、独立嵌入、独立窗口）都支持输入注入；独立进程模式经受管通道转发到 Host 内执行。

## 填表自动化

`FBro填表_*` 命令族基于 CSS 选择器操作框架内元素，与易语言版填表框架 22 条公开命令一一对应。
首参数为 `FBro框架_取主框架(控件名)` 等命令返回的框架句柄；`序号` 从 0 起，匹配选择器的第几个元素。

- 写入族同步发后即忘：`点击元素`、`滚动到元素`、`聚焦元素`、`赋值`、`置选择框`、`置选择项`、`置内文本`、`置外文本`、`置内代码`、`置外代码`、`置属性`、`触发事件`。
- 读取族内部等待任务完成后返回 JSON（如 `["值"]`）：`取值`、`取坐标`、`取选择框`、`取选择项`、`取内文本`、`取外文本`、`取内代码`、`取外代码`、`取属性`、`元素是否存在`。
- 选择器与文本参数中的半角双引号由桥接层自动转义（与官方语义一致），无需手工处理；`触发事件` 的事件名如 `onclick`、`keydown`、`change`、`input`。

```text
框架 ＝ FBro框架_取主框架(浏览器1)
FBro填表_赋值(框架, "#username", 0, "lingbuilder")
FBro填表_赋值(框架, "#password", 0, "******")
FBro填表_触发事件(框架, "#login", 0, "onclick", 13)
调试输出(FBro填表_取值(框架, "#username", 0))
```
