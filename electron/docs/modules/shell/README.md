# 系统外壳模块使用说明

模块 ID：`lingbuilder.system.shell`
目标：Windows Win32、Windows x64（MSVC）
依赖：无额外 DLL

本模块提供打开文件/网址、资源管理器定位和常用系统目录读取能力。所有路径参数和返回值都是 Unicode 文本。

## 命令

| 命令 | 返回值 | 说明 |
|---|---|---|
| `系统_打开(目标)` | 逻辑型 | 用系统默认程序打开文件、目录或网址；`ShellExecuteW` 未成功启动返回假。 |
| `系统_定位文件(路径)` | 逻辑型 | 在资源管理器窗口中选中并显示指定文件。 |
| `系统_取运行目录()` | 文本型 | 返回当前运行 exe 所在目录，**不带尾部反斜杠**；取不到时返回空文本。 |
| `系统_取临时目录()` | 文本型 | 返回当前用户临时目录，**带尾部反斜杠**（`GetTempPathW` 原生行为）。 |
| `系统_取桌面目录()` | 文本型 | 返回当前用户桌面目录，不带尾部反斜杠。 |
| `系统_取文档目录()` | 文本型 | 返回当前用户文档目录，不带尾部反斜杠。 |

## 目录语义

`系统_取运行目录` 返回的是 exe 文件所在目录（易语言「取运行目录」的对应物），例如 exe 位于 `D:\工具\我的程序.exe` 时返回 `D:\工具`。它**不同于进程当前工作目录**：快捷方式、由其它程序带工作目录启动时，两者可能不一致；需要“exe 旁边的数据文件”时一律用它，不要用相对路径。

三个目录读取命令的尾部反斜杠行为不同：`系统_取运行目录`、`系统_取桌面目录`、`系统_取文档目录` 不带，`系统_取临时目录` 带。拼接子路径时建议统一走 `路径_合并`，不要手工补斜杠。

## 完整示例

```lcpp
// 需要同时启用 lingbuilder.fs.path（路径_合并）。
// 读取 exe 同目录下的 配置.ini。
局部 文本型 配置路径 = 路径_合并(系统_取运行目录(), "配置.ini")
调试输出(配置路径)

// 打开 exe 所在目录。
系统_打开(系统_取运行目录())
```

## 平台限制

- 仅 Windows；内部依赖 `ShellExecuteW`、`GetModuleFileNameW`、`GetTempPathW` 和 `SHGetKnownFolderPath`，全部为系统自带 API，无额外运行时 DLL。
- `系统_取桌面目录`、`系统_取文档目录` 依赖 known folder API，重定向到其它盘的用户配置同样生效。
- `系统_打开` 交给系统默认程序处理，本模块不校验目标是否存在；打开失败（如协议无关联）返回假。
