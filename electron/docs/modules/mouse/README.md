# 鼠标输入模块 2.0 使用说明

`lingbuilder.input.mouse` 是一个模块，内部固定分为三类：全局真实输入（前台）、窗口消息输入（后台）和 UI Automation（后台）。命令名称、分类和 binding 与本文档同源。每条命令的 IDE 描述都会以范围标签开头，避免把“后台消息”误认为真实鼠标操作。

## 三类能力对照

| 分类 | 目标 | 实现 | 是否移动真实光标 | 是否占用系统鼠标 | 失败边界 |
|---|---|---|---|---|---|
| 全局真实输入（前台） | 当前 Windows 输入流及前台窗口 | `GetCursorPos`、`SetCursorPos`、`SendInput` | 查询不移动；移动/相对移动会移动 | 会。按下、单击和滚轮会进入真实输入流，与用户输入交错 | 不主动切换前台；UIPI、桌面或安全软件可能拒绝注入 |
| 窗口消息输入（后台） | 调用者指定的 `HWND` | 受控 `PostMessageW` | 不会 | 不会 | 只保证消息进入目标队列；目标可忽略、过滤或不处理后台消息 |
| UI Automation（后台） | 指定窗口下的语义控件元素 | `IUIAutomation` | 不会 | 不会 | 目标需要公开对应 Pattern；元素关闭或权限隔离后句柄可能失效 |

本模块不会调用 `BlockInput`，不会锁定或独占实体鼠标。需要完全不干扰用户当前光标时，应使用窗口消息或 UI Automation 类命令。

## 全局真实输入（前台）

| 命令 | 说明 |
|---|---|
| `鼠标_取横坐标()`、`鼠标_取纵坐标()` | 读取真实系统光标屏幕坐标；不占用鼠标。 |
| `鼠标_移动(横坐标, 纵坐标)` | 用 `SetCursorPos` 移动真实光标；会改变用户看到的光标位置。 |
| `鼠标_相对移动(横向增量, 纵向增量)` | 用 `SendInput` 发送相对鼠标输入；会改变用户看到的光标位置，实际位移受 Windows 鼠标速度和加速度设置影响，不保证严格等于参数像素数。 |
| `鼠标_左键按下()` / `鼠标_左键放开()` | 注入真实左键按下或放开；必须成对管理。 |
| `鼠标_左键单击()` | 注入左键按下和放开；会占用当前系统鼠标输入流。 |
| `鼠标_右键按下()` / `鼠标_右键放开()` / `鼠标_右键单击()` | 右键的按下、放开和单击版本；会占用系统鼠标输入流。 |
| `鼠标_中键按下()` / `鼠标_中键放开()` / `鼠标_中键单击()` | 中键的按下、放开和单击版本；会占用系统鼠标输入流。 |
| `鼠标_滚轮(滚动量)` | 注入垂直滚轮；通常不移动光标，但会占用系统鼠标输入流。 |
| `鼠标_水平滚轮(滚动量)` | 注入水平滚轮；通常不移动光标，但会占用系统鼠标输入流。 |

```lcpp
// 前台真实输入：会改变当前系统鼠标状态
鼠标_移动(640, 360)
鼠标_左键单击()
```

这些命令不会自动把窗口置前。目标窗口必须已经是前台窗口；如需切换窗口，应显式调用窗口模块的“置前台”命令，并提醒用户这会改变桌面状态。

## 窗口消息输入（后台）

窗口命令的第一个参数是 `窗口句柄`（Win32 `HWND`），不是窗口标题文本。移动和按钮坐标使用目标窗口客户区坐标；滚轮消息使用屏幕坐标，这是 Windows 消息定义的差异。

| 命令 | 说明 |
|---|---|
| `鼠标_窗口消息移动(窗口句柄, 客户区横坐标, 客户区纵坐标)` | 投递 `WM_MOUSEMOVE`，不移动真实光标。 |
| `鼠标_窗口消息左键单击(...)` | 投递移动、`WM_LBUTTONDOWN` 和 `WM_LBUTTONUP`，不抢焦点。 |
| `鼠标_窗口消息右键单击(...)` | 投递移动、`WM_RBUTTONDOWN` 和 `WM_RBUTTONUP`，不抢焦点。 |
| `鼠标_窗口消息中键单击(...)` | 投递移动、`WM_MBUTTONDOWN` 和 `WM_MBUTTONUP`，不抢焦点。 |
| `鼠标_窗口消息滚轮(窗口句柄, 滚动量, 屏幕横坐标, 屏幕纵坐标)` | 投递 `WM_MOUSEWHEEL`，不移动真实光标。 |
| `鼠标_窗口消息水平滚轮(窗口句柄, 滚动量, 屏幕横坐标, 屏幕纵坐标)` | 投递 `WM_MOUSEHWHEEL`，不移动真实光标。 |

```lcpp
局部 句柄 记事本 = 窗口_按标题查找("记事本")
// 后台消息：真实鼠标保持原位，记事本可以选择忽略消息
鼠标_窗口消息左键单击(记事本, 30, 30)
```

`PostMessageW` 的真返回只表示消息成功入队，不表示目标已经执行。自绘界面、Raw Input、DirectInput、权限隔离窗口和带安全校验的程序可能不响应这类消息。

## UI Automation（后台）

UI Automation 命令按控件语义操作，不模拟鼠标。`鼠标_UIA_按名称查找` 和 `鼠标_UIA_按自动化ID查找` 返回一个受管的整数 `元素句柄`，该值只在当前进程和本模块中有效，不能当作 HWND，也不能转换为裸 COM 指针。使用完后调用 `鼠标_UIA_释放`。

| 命令 | 说明 |
|---|---|
| `鼠标_UIA_按名称查找(窗口句柄, 名称)` | 在指定 HWND 的 UIA 子树中按 Name 查找第一个元素。 |
| `鼠标_UIA_按自动化ID查找(窗口句柄, 自动化ID)` | 在指定 HWND 的 UIA 子树中按 AutomationId 查找第一个元素。 |
| `鼠标_UIA_调用(元素句柄)` | 调用 `InvokePattern`，适合按钮、链接等。 |
| `鼠标_UIA_设置文本(元素句柄, 文本)` | 调用 `ValuePattern` 设置文本。 |
| `鼠标_UIA_取文本(元素句柄)` | 读取 `ValuePattern`；没有时回退到元素 Name。 |
| `鼠标_UIA_设置勾选(元素句柄, 是否勾选)` | 调用 `TogglePattern` 设置开关状态。 |
| `鼠标_UIA_设置焦点(元素句柄)` | 调用 UIA `SetFocus`；不移动光标，但可能改变键盘焦点。 |
| `鼠标_UIA_释放(元素句柄)` | 释放受管元素引用。 |

```lcpp
局部 句柄 确定按钮 = 鼠标_UIA_按名称查找(记事本, "确定")
如果 确定按钮 != 0
    鼠标_UIA_调用(确定按钮)
    鼠标_UIA_释放(确定按钮)
结束
```

UIA 需要目标程序公开对应的控件模式。查找不到元素、元素没有 `InvokePattern`/`ValuePattern`/`TogglePattern` 或跨完整性级别访问受限时，命令返回失败或空值；这不代表应该退回全局真实输入。

## 选择建议

- 要让用户看到并接收真实鼠标动作：使用“全局真实输入（前台）”，并在界面提示会移动/占用系统鼠标。
- 要在不移动光标的情况下给传统 Win32 窗口发消息：使用“窗口消息输入（后台）”，传入真实 `HWND`。
- 要操作按钮、输入框、复选框等语义控件：优先使用“UI Automation（后台）”，传入模块返回的元素句柄。

## 平台与验证

当前实现使用 Windows User32 和 UI Automation，目标为 Windows MSVC Win32/x64。生成工程会链接 `uiautomationcore.lib`，由生成器统一初始化 COM；本模块不开放任意窗口消息和裸 COM 指针。

```bash
cd electron
npm run lint
npm run test:lingcpp
npm run module:demos -- --module lingbuilder.input.mouse
npm run build
```
