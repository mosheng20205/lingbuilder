# WebSocket 服务端模块 2.0

模块 ID：`lingbuilder.websocket.server`
当前版本：`2.0.0`
最低 LingBuilder：`0.2.8`

本模块提供基于 RFC 6455 的受管 WebSocket 服务端。它使用后台非阻塞 reactor 处理多个客户端，通过窗口消息把连接、消息、断开和错误事件投递到创建服务的 UI 线程。普通 Win32 与 New_Emoji 后端使用同一协议运行时和命令 binding。

## 适用场景

- 桌面程序内的本地实时接口、调试通道和设备控制面板。
- 局域网内经过明确授权的实时消息服务。
- 需要文本、二进制、广播、心跳、关闭握手和客户端状态查询的 Windows 服务端程序。

本模块不是 HTTP 路由框架，也不内置 TLS 证书、用户登录、房间管理、消息持久化或跨机器集群。公网部署应在受维护的反向代理或网关终止 TLS，并把经过访问控制的连接转发到本模块的回环地址。

## 平台与依赖

- Windows + MSVC，支持 Win32 和 x64。
- C++17。
- 系统库：`ws2_32.lib`、`advapi32.lib`。
- 支持普通 Win32 和 New_Emoji UI 后端。
- 当前协议入口是 `ws://`。浏览器公网场景应由 IIS、Caddy、Nginx 或同类网关提供 `wss://`，不要直接把未加密监听端口暴露到互联网。

## 运行模型

`WebSocket服务端` 和 `WebSocket客户端` 都是受管 ID，不是原生 `SOCKET`。服务端使用一个后台 `WSAPoll` reactor 管理其客户端，发送数据进入每个客户端独立的有界队列。事件处理器在所属窗口的 UI 线程顺序执行，可以安全调用工作台生成的界面命令，但不应执行长时间阻塞任务。

一个窗口可以创建多个服务端。服务停止或窗口销毁时，运行时会发送关闭帧、停止后台线程并释放连接。客户端 ID 在连接断开后只可用于读取已保存的连接元数据，发送操作会失败。

## 完整示例

```text
类 MainWindow
    程序集变量 WebSocket服务端 消息服务

    事件 _MainWindow_创建完毕()
        消息服务 = WSS_创建服务()
        WSS_配置服务(消息服务, "127.0.0.1", 18080, 512)
        WSS_设置资源限制(消息服务, 64, 16, 8, 30000)
        WSS_设置心跳(消息服务, 30000, 10000)
        WSS_设置访问路径(消息服务, "/ws")
        WSS_设置允许来源(消息服务, "https://app.example.com")
        WSS_设置子协议(消息服务, "chat.v2, chat.v1")
        WSS_绑定连接处理器(消息服务, &客户端已连接)
        WSS_绑定消息处理器(消息服务, &收到客户端消息)
        WSS_绑定断开处理器(消息服务, &客户端已断开)
        WSS_绑定错误处理器(消息服务, &服务端发生错误)
        WSS_启动(消息服务)
    结束

    事件 客户端已连接()
        调试输出("客户端连接：", WSS_取客户端地址(WSS_取当前客户端()))
    结束

    事件 收到客户端消息()
        如果 (WSS_取当前消息类型() == "文本")
            WSS_发送文本给客户端(WSS_取当前客户端(), WSS_取当前文本())
        否则
            WSS_发送二进制给客户端(WSS_取当前客户端(), WSS_取当前二进制())
        如果结束
    结束

    事件 客户端已断开()
        调试输出("客户端断开：", WSS_取当前关闭代码(), WSS_取当前关闭原因())
    结束

    事件 服务端发生错误()
        调试输出("WebSocket 错误：", WSS_取当前文本())
    结束
结束类
```

所有处理器引用必须使用 `&处理器名`，不能写成字符串。四类处理器都必须无参数；事件数据通过 `WSS_取当前...` 系列读取。当前事件快照只在处理器执行期间有效，需要延迟使用时应先复制文本、字节集或客户端 ID。

## 服务与安全配置

| 命令 | 说明 |
| --- | --- |
| `WSS_创建服务()` | 创建受管服务端，返回 `WebSocket服务端`。 |
| `WSS_配置服务(服务端, 监听地址, 端口, 最大客户端数)` | 配置地址、端口和并发上限。端口 `0` 由系统分配；客户端数范围为 1 到 4096。 |
| `WSS_设置资源限制(服务端, 握手头上限KB, 消息上限MB, 单客户端发送队列上限MB, 超时毫秒)` | 限制握手、完整消息、每客户端背压队列和连接超时。 |
| `WSS_设置心跳(服务端, 间隔毫秒, Pong超时毫秒)` | 自动发送 Ping 并回收未按时 Pong 的连接；间隔 `0` 关闭心跳。 |
| `WSS_允许外部监听(服务端, 允许)` | 默认只允许回环地址。监听局域网地址前必须显式设为真。 |
| `WSS_设置访问路径(服务端, 路径)` | 限制握手路径，例如 `/ws`；空文本表示不限制。 |
| `WSS_设置允许来源(服务端, 来源列表)` | 设置逗号分隔的完整 Origin 白名单；配置后，无 Origin 或不匹配的请求都会拒绝。 |
| `WSS_设置子协议(服务端, 子协议列表)` | 按服务端顺序选择双方共同支持的第一个子协议。 |
| `WSS_启动(服务端)` | 启动后台监听。 |
| `WSS_停止(服务端)` | 停止监听并以 1001 关闭在线客户端。 |
| `WSS_销毁服务(服务端)` | 停止并释放服务端 ID。 |

监听配置、资源限制、心跳、路径、Origin 和子协议只能在停止状态修改。配置失败时命令返回假，可用 `WSS_取服务错误` 读取中文原因。

## 事件

| 命令 | 说明 |
| --- | --- |
| `WSS_绑定连接处理器(服务端, &处理器)` | 客户端完成 RFC 6455 握手后触发。 |
| `WSS_绑定消息处理器(服务端, &处理器)` | 收到一条完整文本或二进制消息后触发，分片已由运行时重组。 |
| `WSS_绑定断开处理器(服务端, &处理器)` | 正常关闭、超时、协议错误或网络异常后触发。 |
| `WSS_绑定错误处理器(服务端, &处理器)` | 握手拒绝、协议错误、队列背压或网络错误时触发。 |
| `WSS_取当前事件类型()` | 返回 `连接`、`文本`、`二进制`、`断开` 或 `错误`。 |
| `WSS_取当前客户端()` | 返回当前事件的 `WebSocket客户端`。服务级错误可能返回 0。 |
| `WSS_取当前消息类型()` | 消息事件返回 `文本` 或 `二进制`。 |
| `WSS_取当前文本()` | 返回文本消息或当前中文错误说明。 |
| `WSS_取当前二进制()` | 返回二进制消息的字节集副本。 |
| `WSS_取当前关闭代码()` | 返回断开事件的关闭状态码。 |
| `WSS_取当前关闭原因()` | 返回经过 UTF-8 校验的关闭原因。 |

处理器在 UI 线程执行。大文件处理、压缩、数据库查询或耗时计算应交给受控任务/线程服务，完成后再回到 UI；不要在处理器中等待下一条 WebSocket 消息。

## 客户端与消息

| 命令 | 说明 |
| --- | --- |
| `WSS_客户端是否在线(客户端)` | 判断客户端仍在线且没有进入关闭状态。 |
| `WSS_取客户端地址(客户端)` | 返回数字 IP 地址。 |
| `WSS_取客户端端口(客户端)` | 返回 TCP 对端端口。 |
| `WSS_取客户端路径(客户端)` | 返回不含查询字符串的握手路径。 |
| `WSS_取客户端来源(客户端)` | 返回 Origin。 |
| `WSS_取客户端子协议(客户端)` | 返回协商结果；未协商时为空。 |
| `WSS_取客户端连接时长(客户端)` | 返回握手完成后的毫秒数。 |
| `WSS_取客户端列表JSON(服务端)` | 返回在线客户端快照，包含 ID、地址、端口、路径、来源和子协议。 |
| `WSS_发送文本给客户端(客户端, 内容)` | 把完整 UTF-8 文本帧加入该客户端发送队列。 |
| `WSS_发送二进制给客户端(客户端, 数据)` | 把完整二进制帧加入该客户端发送队列。 |
| `WSS_广播文本(服务端, 内容)` | 广播文本，返回成功入队的客户端数。 |
| `WSS_广播二进制(服务端, 数据)` | 广播二进制，返回成功入队的客户端数。 |
| `WSS_发送Ping(客户端, 数据)` | 发送最多 125 字节的 UTF-8 Ping 数据。 |
| `WSS_关闭客户端(客户端, 状态码, 原因)` | 校验状态码和原因后执行关闭握手。 |
| `WSS_强制断开客户端(客户端)` | 立即关闭 TCP，仅用于管理、超时或无法继续协议握手的情况。 |

发送命令只表示数据成功进入有界队列，不表示对端已经处理。单客户端队列满时发送返回假、记录中文错误并触发已绑定的错误处理器。广播返回成功入队数量，调用方应与 `WSS_取在线客户端数` 比较并处理部分失败。

## 状态与统计

| 命令 | 说明 |
| --- | --- |
| `WSS_是否运行(服务端)` | 服务端是否正在监听。 |
| `WSS_取监听地址(服务端)` | 当前监听地址。 |
| `WSS_取监听端口(服务端)` | 实际端口，适合端口 `0` 场景。 |
| `WSS_取在线客户端数(服务端)` | 已完成握手的在线客户端数。 |
| `WSS_取累计连接数(服务端)` | 该服务端成功握手的累计连接数。 |
| `WSS_取累计消息数(服务端)` | 收到的完整文本和二进制消息总数。 |
| `WSS_取服务错误(服务端)` | 最近一次服务级或发送级中文错误。 |

统计是进程内运行统计，服务销毁后不持久化。

## 协议行为

- 只接受 `GET HTTP/1.1` 和 WebSocket 版本 13。
- 校验 `Upgrade`、`Connection`、`Sec-WebSocket-Key` 和 16 字节随机 nonce。
- 客户端帧必须带掩码；未掩码、RSV 非零、未知 opcode、非最短长度编码等会以 1002 关闭。
- 支持文本、二进制、继续帧、跨帧 UTF-8、Ping、Pong 和 Close。
- 文本消息和关闭原因必须是有效 UTF-8；错误时使用 1007。
- 超过消息或资源上限时使用 1009 或拒绝握手。
- 不协商压缩扩展，因此客户端不得设置 RSV1。

`WSAPoll` 单 reactor 适合桌面程序和中等并发服务。最大客户端数 4096 是硬配置范围，不代表任意硬件都能在最大消息和最大队列配置下稳定承载 4096 个活跃大流量连接。上线前应按真实消息大小、广播比例和客户端速度进行压力测试，并用操作系统监控观察句柄、内存、CPU 和发送积压。

## 安全部署清单

1. 默认监听 `127.0.0.1`；只有明确需要局域网访问时才调用 `WSS_允许外部监听`。
2. 浏览器客户端应配置精确 Origin 白名单和固定访问路径。
3. 使用不可预测的应用层登录令牌，并在业务消息进入敏感操作前完成鉴权。本模块不会替代身份认证。
4. 根据业务下调消息、握手和队列上限，避免使用不必要的 1GB 上限。
5. 公网只暴露带证书、限流和访问日志的 `wss://` 网关，不直接暴露 `ws://` 端口。
6. 不把凭据、Cookie、Authorization 或完整敏感消息写入调试输出。

## 旧版迁移

1.0 的 6 条同步 API 仍保留为高级兼容入口：`WSS_启动服务`、`WSS_等待连接`、`WSS_接收文本`、`WSS_接收到调试输出`、`WSS_发送文本`、`WSS_关闭服务`。它们使用默认受管服务，阻塞等待最长 30 秒，只面向旧源码迁移，不出现在普通补全中。

新项目应创建显式 `WebSocket服务端`，绑定 `&处理器名`，在事件快照中取得客户端，再使用定向发送或广播。这样才能使用多客户端、二进制、访问控制、资源限制、心跳、状态和错误处理能力。
