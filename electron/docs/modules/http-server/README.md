# HTTP 服务端模块 2.0

模块 ID：`lingbuilder.http.server`

本模块提供商业可用的嵌入式 HTTP/1.1 服务端能力。它使用后台接受线程、有界连接队列和 1 至 64 个工作线程处理连接，再通过窗口消息把请求投递到创建服务的 UI 线程。普通 Win32 与 New_Emoji 后端使用同一份运行时和命令 binding。

## 适用场景

- 桌面软件的本地管理接口、健康检查、OAuth 回调和自动化入口。
- 明确授权后的局域网设备接口、控制面板和轻量业务 API。
- 需要路由、请求头/查询/正文读取、JSON/文件/二进制响应、Cookie、限制和运行统计的 Windows 应用。

本模块是进程内 HTTP/1.1 服务端，不是完整互联网 Web 平台。它不内置 TLS、HTTP/2、HTTP/3、用户认证、会话存储、模板引擎、压缩、代理信任链、限流集群或跨进程负载均衡。公网部署应由 IIS、Caddy、Nginx 或同类网关终止 HTTPS、执行认证和限流，再转发到模块的回环监听地址。

## 平台与依赖

- Windows + MSVC，支持 Win32 和 x64。
- C++17。
- 系统库：`ws2_32.lib`。
- 支持普通 Win32 和 New_Emoji UI 后端。
- 支持 HTTP/1.0 与 HTTP/1.1 请求、`Content-Length`、`Transfer-Encoding: chunked`、`Expect: 100-continue`、HEAD 和 keep-alive。

## 快速开始

```text
类 MainWindow
    HTTP服务端 接口服务

    事件 _MainWindow_创建完毕()
        接口服务 = HTTP_创建服务()
        HTTP_配置服务(接口服务, "127.0.0.1", 8080, 4, 256)
        HTTP_设置请求限制(接口服务, 64, 16, 30000)
        HTTP_添加路由(接口服务, "GET", "/api/health", &处理健康检查)
        HTTP_添加路由(接口服务, "POST", "/api/echo", &处理回显)
        HTTP_绑定请求处理器(接口服务, &处理未匹配请求)
        如果 (!HTTP_启动(接口服务))
            调试输出("HTTP 启动失败：", HTTP_取服务错误(接口服务))
        如果结束
    结束

    事件 处理健康检查()
        HTTP请求 请求 = HTTP_取当前请求()
        HTTP_设置响应头(请求, "Cache-Control", "no-store")
        HTTP_发送JSON(请求, "{\"ok\":true}", 200)
    结束

    事件 处理回显()
        HTTP请求 请求 = HTTP_取当前请求()
        HTTP_发送文本(请求, HTTP_取请求正文(请求), "text/plain; charset=utf-8", 200)
    结束

    事件 处理未匹配请求()
        HTTP请求 请求 = HTTP_取当前请求()
        HTTP_发送JSON(请求, "{\"error\":\"not_found\"}", 404)
    结束

    事件 _MainWindow_已关闭()
        HTTP_停止(接口服务)
        HTTP_销毁服务(接口服务)
    结束
结束类
```

处理器必须使用 `&处理器名`，不得写成字符串。处理器必须返回 `空` 且没有参数，请求数据通过 `HTTP_取当前请求()` 和 `HTTP_取请求...` 系列读取。`HTTP请求` 只在本次处理期间有效，不得保存后跨请求使用。

## 运行模型

`HTTP服务端` 和 `HTTP请求` 是受管 ID，不是原生 `SOCKET`。每个服务端拥有独立监听 socket、接受线程、有界等待队列和固定工作线程组；一个窗口可以创建多个服务端。

工作线程解析请求后，在窗口 UI 线程顺序调用路由处理器。处理器可以安全更新所属窗口控件，但不应执行长时间文件计算、数据库查询或同步网络访问。处理器在配置的请求超时内未完成响应时，运行时返回 504。没有匹配路由和默认处理器时返回 404；事件无法投递到窗口时返回 503。

每个连接最多处理 100 个请求，之后主动关闭。服务停止或窗口销毁时，监听 socket、排队连接、活动连接、请求和工作线程会统一回收。

## 服务生命周期

| 命令 | 说明 |
| --- | --- |
| `HTTP_创建服务()` | 创建停止状态的服务端，返回 `HTTP服务端`。 |
| `HTTP_配置服务(服务端, 监听地址, 端口, 工作线程数, 等待队列上限)` | 设置 IPv4/IPv6 地址、端口、1–64 个工作线程和 1–65535 的有界队列。端口 0 由系统分配。 |
| `HTTP_设置请求限制(服务端, 请求头上限KB, 请求体上限MB, 请求超时毫秒)` | 在停止状态设置 4–1024KB 请求头、0–1024MB 正文和 100–3600000ms 超时。 |
| `HTTP_允许外部监听(服务端, 允许)` | 显式授权非回环监听；只能在停止状态修改。 |
| `HTTP_启动(服务端)` | 启动后台监听，重复启动同一服务视为成功。 |
| `HTTP_停止(服务端)` | 停止监听，中止等待请求并回收线程；服务 ID 可重新配置和启动。 |
| `HTTP_销毁服务(服务端)` | 停止并永久释放服务 ID。 |

监听配置、请求限制和外部监听授权只能在停止状态修改。命令失败时使用 `HTTP_取服务错误` 读取中文原因。

## 路由

| 命令 | 说明 |
| --- | --- |
| `HTTP_绑定请求处理器(服务端, &处理器)` | 设置未命中显式路由时的默认处理器。 |
| `HTTP_添加路由(服务端, 方法, 路径模式, &处理器)` | 添加或替换路由。方法使用大写 token 或 `*`；路径支持精确匹配和末尾 `/*` 前缀匹配。 |
| `HTTP_清空路由(服务端)` | 删除全部显式路由，保留默认处理器。 |

路由按登记顺序匹配。`/api/*` 匹配 `/api/users`，不匹配 `/api`；如需同时匹配，应另外登记 `/api`。请求路径会按 UTF-8 百分号编码解码，路径中的 `+` 保持加号；查询参数中的 `+` 按表单规则解释为空格。

## 请求读取

| 命令 | 返回内容 |
| --- | --- |
| `HTTP_取当前请求()` | 当前处理器的 `HTTP请求`，不在处理器中时为 0。 |
| `HTTP_取请求服务(请求)` | 接收请求的 `HTTP服务端`。 |
| `HTTP_取请求方法(请求)` | 大写方法，例如 GET、POST。 |
| `HTTP_取请求目标(请求)` | 请求行中的原始 target，包含查询字符串。 |
| `HTTP_取请求路径(请求)` | 解码后的路径。 |
| `HTTP_取查询字符串(请求)` | 未解码且不含问号的查询字符串。 |
| `HTTP_取查询参数(请求, 名称)` | 首个同名查询参数的 UTF-8 解码值。 |
| `HTTP_取请求头(请求, 名称)` | 不区分大小写读取请求头；重复头以逗号合并。 |
| `HTTP_取全部请求头(请求)` | 请求头 JSON 对象。 |
| `HTTP_取请求正文(请求)` | 按 UTF-8 转换的正文文本。 |
| `HTTP_取请求正文十六进制(请求)` | 原始正文字节的小写十六进制。 |
| `HTTP_取请求正文大小(请求)` | 原始正文长度，单位字节。 |
| `HTTP_取客户端地址(请求)` | TCP 对端数字 IP。 |
| `HTTP_取客户端端口(请求)` | TCP 对端端口。 |
| `HTTP_取协议版本(请求)` | HTTP/1.0 或 HTTP/1.1。 |

`HTTP_取请求正文` 只适合 UTF-8 文本。上传文件、压缩内容或其它二进制协议应使用正文十六进制接口，或使用面向字节集/流的专用模块；不要把任意二进制误当文本。

## 响应

| 命令 | 说明 |
| --- | --- |
| `HTTP_设置状态码(请求, 状态码)` | 在完成响应前设置 100–599 状态码。 |
| `HTTP_设置响应头(请求, 名称, 值)` | 设置或替换响应头，拒绝非法名称和 CR/LF 注入。 |
| `HTTP_添加响应头(请求, 名称, 值)` | 追加同名响应头。Content-Length、Connection 和 Transfer-Encoding 由运行时管理。 |
| `HTTP_设置Cookie(请求, 名称, 值, 路径, 最大秒数, HttpOnly, Secure, SameSite)` | 追加 Set-Cookie；值按 UTF-8 百分号编码，SameSite 支持 Lax、Strict、None，None 必须启用 Secure。 |
| `HTTP_发送文本(请求, 内容, 内容类型, 状态码)` | 发送 UTF-8 文本并完成请求。 |
| `HTTP_发送JSON(请求, JSON, 状态码)` | 发送 `application/json; charset=utf-8` 并完成请求。调用方负责 JSON 语法正确。 |
| `HTTP_发送十六进制(请求, 十六进制, 内容类型, 状态码)` | 校验偶数长度十六进制并发送原始字节。 |
| `HTTP_发送文件(请求, 文件路径, 下载名称, 内容类型, 状态码)` | 以 64KB 缓冲分块读取文件，自动设置长度和可选下载文件名。 |
| `HTTP_重定向(请求, 地址, 状态码)` | 发送 301、302、303、307 或 308。 |
| `HTTP_发送空响应(请求, 状态码)` | 完成无正文响应，适用于 204、304 等状态。 |
| `HTTP_是否已响应(请求)` | 判断请求是否完成或中止。 |
| `HTTP_中止请求(请求)` | 不发送应用层响应，直接结束请求并关闭连接。 |

每个请求只能完成一次。响应函数返回假通常表示请求 ID 已过期、已完成或参数无效。运行时自动设置 `Content-Length`、`Connection` 和 `X-Content-Type-Options: nosniff`；HEAD 发送与 GET 相同的响应头但不发送正文。

`HTTP_发送文件` 接受应用提供的本机路径，不会自动建立静态目录沙箱。不得把未验证的 URL 参数直接拼到文件路径；应先映射到应用允许的文件 ID，或执行规范化后确认最终路径仍位于授权目录。

| 命令 | 说明 |
| --- | --- |
| `HTTP_是否运行(服务端)` | 服务端是否正在接受连接。 |
| `HTTP_取监听地址(服务端)` | 当前配置的监听地址。 |
| `HTTP_取监听端口(服务端)` | 实际端口，适合端口 0 场景。 |
| `HTTP_取活动连接数(服务端)` | 当前工作线程正在处理的连接数。 |
| `HTTP_取累计请求数(服务端)` | 成功解析并投递的累计请求数。 |
| `HTTP_取服务错误(服务端)` | 最近一次服务级中文错误。 |

统计只存在于当前进程和服务 ID 生命周期内，不是持久化审计日志。

## 协议校验

- HTTP/1.1 必须包含且只能包含一个非空 Host；缺失或重复返回 400。
- 只接受面向源站、以 `/` 开头的 request-target，以及 `OPTIONS *`；绝对形式、片段、控制字符、反斜杠和错误百分号编码返回 400。
- 请求行、头名称、CRLF、Content-Length、Transfer-Encoding、UTF-8 头值及百分号解码后的 UTF-8 字节会严格校验，降低请求走私和解析歧义风险。
- `Expect: 100-continue` 会先返回 100；其它 Expect 返回 417。
- 同时出现 Content-Length 与 Transfer-Encoding、未知 transfer coding、无效 chunk 或超限正文都会拒绝。
- HTTP/1.0 响应保持 HTTP/1.0 状态行；HTTP/1.1 默认 keep-alive，HTTP/1.0 仅在客户端明确请求时保持连接。

## 默认安全边界

1. 默认只允许 `127.0.0.1`、`localhost`、`::1` 或 `127.0.0.0/8` 回环监听。运行时以地址解析后的实际 IPv4/IPv6 `sockaddr` 判断是否回环，不依赖主机名外观；非回环地址必须显式调用 `HTTP_允许外部监听(服务, 真)`。
2. 上线前按实际业务下调请求头、正文、超时、工作线程和队列上限，避免不必要的资源占用。
3. 不信任 Host、Origin、Referer、X-Forwarded-For 或用户输入的路径。反向代理场景只读取网关明确重写并保护的头。
4. 身份认证、CSRF 防护、访问令牌、业务权限、速率限制和审计由应用或前置网关实现。
5. Cookie 中不要放明文密码或长期密钥；公网 Cookie 应启用 Secure、HttpOnly 和合适的 SameSite。
6. 不把 Authorization、Cookie、请求正文或个人信息完整写入调试输出。
7. 公网只暴露 HTTPS 网关。模块本身不提供 TLS，不能直接作为互联网边界服务器。

## 旧版迁移

1.x 的 5 条同步 API 保留为高级兼容入口：`HTTP_启动服务`、`HTTP_等待请求`、`HTTP_等待请求到调试输出`、`HTTP_回复文本`、`HTTP_关闭服务`。它们使用默认受管服务，只监听回环地址，主要用于旧源码迁移，不出现在普通补全或新示例中。

新项目应迁移为显式 `HTTP服务端`，在启动前配置资源限制，以 `&处理器名` 注册路由，并保证每个处理器明确发送或中止响应。迁移后才能使用多连接、动态端口、路由、完整请求读取、Cookie、文件/二进制响应、统计和可控生命周期。
