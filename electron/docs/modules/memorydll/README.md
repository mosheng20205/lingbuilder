# 内存加载 DLL 模块（lingbuilder.advanced.memorydll）

把 DLL 的字节数据在内存中手工完成 PE 映射并解析导出函数，**全过程不向磁盘释放 DLL 文件**。
需要「不落盘分发 DLL」「exe 单文件即可运行」时使用本模块。

- 模块 ID：`lingbuilder.advanced.memorydll`
- 命令数：7
- 平台：`windows-msvc-win32`、`windows-msvc-x64`
- 类别：系统（高级 · 风险）

## 适用场景

1. 把第三方 DLL 以字节集形式随程序分发，但不希望 exe 目录里出现该 DLL。
2. 配合「项目 DLL 命令声明」的 `加载方式 = 内存`，让声明出的中文命令直接调用内嵌 DLL（推荐，无需手写函数指针）。
3. 需要自己控制加载时机、检查导出是否存在、或把函数地址交给其它原生命令时，直接用本模块的命令。

## 调用方式

### 命令清单

| 命令 | 签名 | 说明 |
|---|---|---|
| `内存DLL_加载` | `内存DLL_加载(数据, 虚拟名, [虚拟目录], [过文件校验], [不执行入口])` → 长整数型 | 映射内存并执行入口函数，返回模块地址；0 表示失败 |
| `内存DLL_取函数地址` | `内存DLL_取函数地址(模块地址, 函数名)` → 长整数型 | 按导出名取地址；0 表示未找到 |
| `内存DLL_取函数序号地址` | `内存DLL_取函数序号地址(模块地址, 序号)` → 长整数型 | 按导出序号取地址（只按序号导出的 DLL） |
| `内存DLL_取模块大小` | `内存DLL_取模块大小(模块地址)` → 整数型 | 本次映射占用的映像字节数 |
| `内存DLL_已加载` | `内存DLL_已加载(模块地址)` → 逻辑型 | 地址是否仍是有效模块 |
| `内存DLL_卸载` | `内存DLL_卸载(模块地址)` → 逻辑型 | 注销模块（不释放映像，见限制） |
| `内存DLL_取错误信息` | `内存DLL_取错误信息()` → 文本型 | 最近一次失败的中文原因 |

`内存DLL_加载` 的第 3～5 个参数可省略，缺省为：虚拟目录为空文本、过文件校验 = 假、不执行入口 = 假。

### 参数与返回值

- **数据**：DLL 文件的完整字节集。可用 `缓冲区_从文件("路径")` + `缓冲区_到字节集(缓冲区)` 读入，
  或由项目 DLL 命令声明的内嵌资源提供。必须与程序位数一致、未加壳。
- **虚拟名**：模块自称的库文件名（如 `"sqlite3.dll"`）。重复加载判断与错误提示都用它；
  同一虚拟名再次加载会直接返回已加载的模块地址。
- **虚拟目录**：可选，仅作为模块来源信息记录，不参与寻址。
- **过文件校验**：传真时额外校验节区数据完整性与导出表结构，并识别 UPX、ASPack、Themida、VMProtect
  等常见加壳段名，遇到加壳 DLL 直接失败并说明原因。
- **不执行入口**：传真时不调用 DLL 的入口函数（DllMain 的 `DLL_PROCESS_ATTACH`）。

## 完整示例

### 一、声明即调用（推荐）

```text
// src/项目DLL命令.lcpp
DLL命令库 MemoryDemo
  x64 = "dll/x64/memory_demo.dll"
  Win32 = "dll/Win32/memory_demo.dll"
  加载方式 = 内存

  整数型 内存演示_加法(整数型 甲, 整数型 乙) = memo_add
结束DLL命令库
```

```text
// 业务代码：与普通 DLL 声明完全一致
整数型 结果 = 内存演示_加法(2, 3)
```

构建期会把 `<项目源码根>/dll/<架构>/memory_demo.dll` 以 RCDATA 资源内嵌进 EXE
（资源号 2201 起，按声明顺序分配），运行期首次调用该命令时完成映射与解析；
失败时不抛出异常，而是写入中文原因并返回类型零值（可用 `内存DLL_取错误信息()` 查看）。

前置条件：项目必须启用本模块，否则构建给出中文阻断诊断。

### 二、命令直用

```text
局部 长整数型 缓冲区 = 缓冲区_从文件("data/memory_demo.dll")
局部 字节集 数据 = 缓冲区_到字节集(缓冲区)
局部 长整数型 模块地址 = 内存DLL_加载(数据, "memory_demo.dll", "", 真)
如果真 (模块地址 == 0)
    调试输出(内存DLL_取错误信息())
    返回
结束如果

局部 长整数型 加法地址 = 内存DLL_取函数地址(模块地址, "memo_add")
调试输出(格式化文本("模块大小={}，函数地址={}", 内存DLL_取模块大小(模块地址), 加法地址))
```

## 依赖与平台限制

- 只支持 Windows PE（DLL），只支持与当前程序位数一致的映像。
- 依赖的系统 DLL（kernel32、user32、ucrtbase 等）仍由 Windows 加载器从系统目录加载——
  这与易语言内存加载 DLL 的行为一致，不属于“释放到本地”。
- 不支持 .NET 程序集（那是 CLR 加载，另一条链路）；不支持加壳/自解压 DLL。
- 一个进程内每个内存模块会占用一个 TLS 槽位；实测建议单进程内存加载的 DLL 数量控制在个位数。

## 已知限制（实测结论，务必遵守）

1. **模块不在系统模块链表中**：`GetModuleHandleW("库文件名")`、`EnumProcessModules` 都看不到它，
   依赖自身模块句柄加载资源或自定位的 DLL 会失败。
2. **不要依赖 C++ 异常**：手工映射模块内的 MSVC `throw/catch` 不会被派发，x64 下进程会以
   未处理异常终止；`__try/__except` 在 x64 目标可用，在 Win32（WOW64）目标不可用。
   需要异常机制的 DLL，请改用默认的「同目录加载」。
3. **卸载只注销、不释放**：静态 CRT 会向系统登记线程局部存储（FLS/TLS）回调，释放已映射代码会让
   进程退出时的回调落到被回收的内存上。因此 `内存DLL_卸载` 只注销模块（此后取函数地址/已加载都失败、
   同一虚拟名可重新加载），映像内存保留到进程退出；也不会调用 DllMain 的分离通知。
4. **由项目 DLL 命令声明内嵌加载的模块不能手工卸载**，返回假并给出中文原因。
5. **安全提示**：在内存中加载未签名 PE 是敏感行为，部分安全软件会告警。请只加载你自己信任的 DLL，
   不要把来路不明的 DLL 内嵌进程序分发。

## 版本与迁移

- 1.0.0：首个版本，提供上述 7 条命令与「项目 DLL 命令声明 → 加载方式 = 内存」链路。
- 从「同目录加载」迁移到内存加载：在声明库内加一行 `加载方式 = 内存`，并启用本模块即可；
  命令名、参数与返回值都不变，`src/dll/` 下的 DLL 文件仍需保留（构建期要用它的字节）。
