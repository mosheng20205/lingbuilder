# 进程内存模块使用说明（1.1）

进程内存模块（`lingbuilder.advanced.process-memory`，v1.1.0）提供受控的目标进程内存读写与字节集特征扫描能力：显式按进程 ID 打开句柄、读写 32 位整数、批量读取字节集、装入缓冲区、枚举已提交内存区域，以及对目标进程做整块分片 + 重叠补偿的特征扫描。打开失败时区分「拒绝访问（需要管理员）」「参数无效」「部分读取」等中文错误。

## 风险与默认启用

- 本模块属于**高风险模块**：读取或写入其它进程内存可能涉及用户隐私与系统安全，请仅在拥有授权、自有程序调试等合法场景使用；AI 不得在未说明风险时生成读写无关进程的代码。
- 自 2026-09-18 起模块**默认随新项目启用**：旧工作区/旧项目在读取层自动补齐（只补缺不覆盖，参照随包模块铺设语义），用户可在项目「配置项目所使用模块」里按项目禁用，禁用选择会持久化（`optOutDefaultModuleIds`）。
- 模块依赖 `lingbuilder.std.buffer`（缓冲区模块），启用时自动带上；禁用主模块不会连带移除缓冲区模块。

## 打开句柄与错误自检

所有读写命令的 `进程句柄` **只能来自 `进程内存_打开`**，传裸地址句柄一律拒绝；句柄 `0` 表示打开失败。`进程内存_取错误码()` / `进程内存_取错误()` 返回本线程最近一次操作的 Win32 错误码与中文说明：

```text
长整数型 句柄 = 进程内存_打开(进程ID, 假)
如果 (句柄 = 0)
    调试输出(进程内存_取错误码())
    调试输出(进程内存_取错误())
如果结束
```

- 错误码 `5`（拒绝访问）：目标为系统进程或其它用户的进程，**需要以管理员身份运行本程序**。可先用 `系统_是否管理员`（系统信息模块）自检，避免把「没权限」误判为「没有数据」。
- 错误码 `87`（参数无效）：进程 ID、长度、地址等参数不合法。
- 错误码 `299`（部分复制）：目标区域只有部分字节可读，`进程内存_读字节集` 会返回可读前缀并设置该错误码。

## 读写字节

```text
整数型 值 = 进程内存_读整数(句柄, 地址, 0)
逻辑型 成功 = 进程内存_写整数(句柄, 地址, 值)
字节集 数据 = 进程内存_读字节集(句柄, 地址, 4096)
长整数型 缓冲 = 进程内存_读到缓冲区(句柄, 地址, 4096)
```

- 单次批量读取上限 **64 MB**（67108864 字节），更长内容请分块读取。
- 地址必须落在用户态范围（0 到 0x00007FFFFFFFFFFF）；越界、长度非法、句柄无效一律返回空字节集或 0，并设置错误码，不会静默返回假数据。
- 打开时 `允许写入 = 真` 才申请写入权限；`进程内存_写整数` 需要该权限且目标页可写。

## 枚举内存区域

```text
文本型 区域JSON = 进程内存_枚举区域JSON(句柄, 真)
```

用 `VirtualQueryEx` 步进枚举目标进程地址空间，返回 JSON 数组，每个元素含 `baseAddress`、`regionSize`、`state`、`protect`、`type`（均为十进制数值，state 4096 = MEM_COMMIT）。第二个参数传**假**列出全部区域（含保留、空闲），传**真**只返回已提交且页保护可读（排除 PAGE_GUARD / PAGE_NOACCESS）的区域。

## 字节集特征扫描

```text
字节集 特征 = 字节集_十六进制解码("4C0042005300...")
长整数型 命中[]
整数型 命中数 = 进程内存_扫描字节集(句柄, 特征, 100, 命中)
文本型 命中JSON = 进程内存_扫描字节集JSON(句柄, 特征, 100)
```

- 运行时内部自动分块读取：单区域不超过 32 MB 时整块读，更大的区域按 8 MB 分块并自动携带 `max(1KB, 特征长度-1)` 的重叠区，**命中跨块不会被截断**，中文代码无需手搓分块。
- 命中地址按升序去重后写入 `结果数组`（**长整数型数组**）或返回为 JSON 数组文本；达到 `最大命中数`（1 到 1000000）即提前结束。
- 特征字节集为空、最大命中数非法、句柄无效时返回 0 / 空文本并给出中文诊断。
- 扫描受保护进程同样需要管理员权限；权限不足时命中数为 0 且 `进程内存_取错误()` 会说明原因，请勿把权限问题当成「没有命中」。

## 与 Visual Studio 导出的关系

生成的 C++ 源码与 Visual Studio 导出工程共用同一实现（Toolhelp 快照、VirtualQueryEx、ReadProcessMemory），IDE 内 F5、AI Bridge 构建与 VS 打开导出工程编译结果一致。生成 exe 需要管理员权限时，在项目 `buildProperties` 设置 `requireAdministrator: true`（详见 `docs/FUTURE_OPTIMIZATIONS.md` 与更新记录），程序启动即弹 UAC 提权。

## 命中点形态校验：宽松解码 + 正则（2026-09-23 实测范式）

扫描得到命中地址后，经常要判断「这段内存是不是某类字符串」（例如形如 `windows_1-<base64>_<数字>_<数字>` 的登录令牌）。**标准做法是「宽松解码（GB18030/ANSI）+ 正则」，禁止写逐字节状态机**：

```text
文本型 抠令牌(长整数型 句柄, 长整数型 地址)
  局部 字节集 数据
  局部 文本型 明文
  局部 文本型 结果
  数据 = 进程内存_读字节集(句柄, 地址, 200)
  如果 (字节集_长度(数据) == 0)
      返回 ("")
  如果结束
  明文 = 编码_字节集转文本(数据, "GB18030")
  如果 (明文 == "")
      明文 = 编码_字节集转文本(数据, "ANSI")
  如果结束
  如果 (明文 == "")
      返回 ("")
  如果结束
  结果 = 正则_取首个(明文, "windows_1-[A-Za-z0-9+/]{20,90}_[0-9]{6,12}_[0-9]{6,12}")
  返回 (结果)
结束
```

- `GB18030` / `ANSI` 都是宽松编码：ASCII 段（令牌本体）原样保留，内存里的任意二进制不会让整体解码失败；两种都失败就跳过该命中。
- **不要写逐字节状态机做同一件事**：独立最小复现实测，同一份数据正则法 200/200 命中、状态机 0/200 漏判（合法样本放在内存里也判不出来）。状态机的典型错误是 `状态` 在某个 `如果 (状态 == N)` 块内被改写后，同一轮循环里后面的 `如果 (状态 == N+1)` 块立刻又执行一遍，分隔符字节被当成「数据结束」，结束位置停在分隔符上、段长算成负数；这类错误不崩、不卡、只是静默漏判，极难排查。
- 需要按字节语义处理二进制协议时，仍用 `进程内存_读字节集` + `字节集_寻找` / `字节集_截取` 等命令，不要手写下标循环。
