# 键盘输入模块 2.0 使用说明

`lingbuilder.input.keyboard` 提供全局状态读取、前台系统输入注入、指定 HWND 的后台窗口消息以及键名、虚拟键码和扫描码转换。模块不依赖额外 DLL，Win32 和 x64 均使用 Windows `user32` 能力。

## 作用范围与键盘占用

| 分类 | 实际作用对象 | 是否抢焦点 | 是否占用实体键盘 | 关键语义 |
|---|---|---|---|---|
| 全局状态 | 当前 Windows 桌面与前台线程 | 否 | 否 | 只读取状态或 HWND，不发送输入 |
| 键码转换 | 当前 Windows 键盘布局 | 否 | 否 | 纯转换，不产生按键 |
| 前台输入 | 当前前台窗口中拥有焦点的控件 | 不主动抢焦点 | 不独占，但会注入系统输入流 | 使用 `SendInput`，会与用户真实按键交错 |
| 后台窗口 | 调用者指定的 HWND | 否 | 否 | 使用 `PostMessageW`，只投递消息，不改变物理键状态 |

本模块所有公开命令都不会调用 `BlockInput`，不会锁定、挂起或独占用户的实体键盘。“前台输入”仍然会影响当前正在接收键盘输入的程序，调用期间用户按键可与注入事件交错。

## 全局状态

| 命令 | 返回 | 说明 |
|---|---|---|
| `键盘_全局_键是否按下(虚拟键码)` | 逻辑型 | 使用 `GetAsyncKeyState` 读取当前桌面键状态 |
| `键盘_全局_切换状态(虚拟键码)` | 逻辑型 | 读取切换键的开关位 |
| `键盘_全局_大小写锁定状态()` | 逻辑型 | Caps Lock 状态 |
| `键盘_全局_数字锁定状态()` | 逻辑型 | Num Lock 状态 |
| `键盘_全局_滚动锁定状态()` | 逻辑型 | Scroll Lock 状态 |
| `键盘_全局_取前台窗口()` | 句柄 | 当前前台顶层窗口 HWND |
| `键盘_全局_取前台焦点控件()` | 句柄 | 前台线程中真正具有键盘焦点的子控件 HWND |

`GetAsyncKeyState` 受 Windows 桌面和安全边界限制。当调用进程不在活动输入桌面，或系统限制跨进程状态访问时，可能返回假。

## 键码转换

| 命令 | 说明 |
|---|---|
| `键盘_键名取键代码(键名)` | 识别 `Ctrl键`、`Shift键`、`Alt键`、`Win键`、方向键、翻页键、F1～F24、字母和数字等常用中英文名称 |
| `键盘_键代码取键名(虚拟键码)` | 按当前 Windows 键盘布局返回本地化键名 |
| `键盘_键代码取扫描码(虚拟键码)` | VK 转扫描码，保留 E0/E1 扩展前缀 |
| `键盘_扫描码取键代码(扫描码)` | 扫描码转 VK |
| `键盘_键代码是否扩展键(虚拟键码)` | 判断是否需要 `KEYEVENTF_EXTENDEDKEY` |

```lcpp
局部 整数型 控制键 = 键盘_键名取键代码("Ctrl键")
局部 整数型 保存键 = 键盘_键名取键代码("S键")
```

## 前台输入

| 命令 | 说明 |
|---|---|
| `键盘_前台_按下(虚拟键码)` | 注入虚拟键按下，必须与放开成对使用 |
| `键盘_前台_放开(虚拟键码)` | 注入虚拟键放开 |
| `键盘_前台_单击(虚拟键码)` | 用一个 `SendInput` 批次按下并放开 |
| `键盘_前台_组合按键(主键码, 修饰键码1, 修饰键码2, 修饰键码3)` | 支持最多三个修饰键，未使用的位置传 0 |
| `键盘_前台_输入文本(文本)` | 通过 `KEYEVENTF_UNICODE` 注入 UTF-16 文本 |
| `键盘_前台_扫描码按下(扫描码, 扩展键)` | 注入物理扫描码按下 |
| `键盘_前台_扫描码放开(扫描码, 扩展键)` | 注入物理扫描码放开 |
| `键盘_前台_扫描码单击(扫描码, 扩展键)` | 注入成对的扫描码按下和放开 |

```lcpp
// Ctrl+Shift+S：17 = Ctrl，16 = Shift，83 = S
键盘_前台_组合按键(83, 17, 16, 0)
键盘_前台_输入文本("你好 LingBuilder")
```

前台命令不会自动激活或切换窗口。需要指定前台目标时，先通过窗口模块显式激活，再调用前台命令。`SendInput` 受 UIPI 限制，普通权限进程通常无法向更高完整性级别的程序注入输入。

## 指定 HWND 的后台窗口消息

| 命令 | 说明 |
|---|---|
| `键盘_窗口_取焦点控件(窗口句柄)` | 返回指定顶层窗口线程的焦点子控件，不修改焦点 |
| `键盘_窗口_按下(窗口句柄, 虚拟键码, 系统键)` | 投递 `WM_KEYDOWN` 或 `WM_SYSKEYDOWN` |
| `键盘_窗口_放开(窗口句柄, 虚拟键码, 系统键)` | 投递 `WM_KEYUP` 或 `WM_SYSKEYUP` |
| `键盘_窗口_单击(窗口句柄, 虚拟键码, 系统键)` | 依次投递按下和放开 |
| `键盘_窗口_组合按键(窗口句柄, 主键码, 修饰键码1, 修饰键码2, 修饰键码3, 系统键)` | 向同一 HWND 顺序投递组合键消息 |
| `键盘_窗口_输入文本(窗口句柄, 文本)` | 逐个 UTF-16 代码单元投递 `WM_CHAR` |

```lcpp
局部 句柄 顶层窗口 = 窗口_按标题查找("记事本")
局部 句柄 输入控件 = 键盘_窗口_取焦点控件(顶层窗口)
键盘_窗口_输入文本(输入控件, "后台文本")
```

`PostMessageW` 成功只表示消息已进入目标队列，不代表目标已执行按键。很多程序会检查真实键盘状态、Raw Input、DirectInput 或自身安全规则，因而可以忽略后台消息。普通顶层窗口也可能不处理 `WM_CHAR`，应优先把真正的编辑子控件 HWND 作为目标。

## 系统键参数

后台按键命令的“系统键”参数用于选择消息类型：

- 传假：`WM_KEYDOWN` / `WM_KEYUP`。
- 传真：`WM_SYSKEYDOWN` / `WM_SYSKEYUP`，用于 Alt、F10 或目标明确要求系统键消息的场景。

它不会真正按下物理 Alt 键，也不会改变 `GetAsyncKeyState` 的结果。

## 1.x 兼容命令

`键盘_键是否按下`、`键盘_大小写锁定状态`、`键盘_数字锁定状态`、`键盘_单击` 和 `键盘_组合按键` 继续可用。它们会转发到 2.0 的全局状态或前台输入实现。新源码应使用带 `全局`、`前台` 或 `窗口` 的明确命令名。

## 安全与非目标

- 本模块不提供全局低级键盘钩子、隐藏记录按键或任意进程代码注入。
- 本模块不提供 `BlockInput`，不应用于阻止用户控制系统。
- 不应将后台消息当成绕过目标程序权限、安全检查或用户授权的方式。
- 前台和后台文本均限制为 32768 个 UTF-16 代码单元，避免单次生成过大输入队列。

## 验证

```bash
cd electron
npm run lint
npm run test:lingcpp
npm run smoke:keyboard-native
npm run build
```

`smoke:keyboard-native` 会使用 MSVC 分别生成和运行 Win32/x64 工程，只验证键名、虚拟键码、扫描码与扩展键转换，不会向用户桌面注入按键。
