# 网页访问模块使用说明

网页访问模块（`lingbuilder.web.http`，当前版本 1.1.1）是 LingBuilder 内置的网络模块，基于 Windows WinHTTP 封装易语言风格的网页访问命令。提供两条使用路径：

- **同步访问**：`网页_访问_对象` 一条命令完成 GET/POST 等请求，配合 `网页_取返回文本` 等命令读取最近一次结果。适合非界面流程或能接受短暂阻塞的场景。
- **异步访问**：`网页_异步访问` 在受控后台线程执行请求，完成后回到 UI 主线程分发完成处理器。**窗口事件中发起 HTTP/HTTPS 访问必须优先使用本命令**，避免阻塞 Win32 消息循环导致界面假死。

本模块为内置模块：无需下载安装，在「配置项目所使用模块」中启用即可使用；对应的底层实现已内置在生成模板中，F5 构建、原生预览和 Visual Studio 工程导出行为一致。

## 命令总览（12 条）

| 命令 | 返回值 | 说明 |
| --- | --- | --- |
| 网页_异步访问(网址, 访问方式, 完成处理器) | 整数型 | 后台线程访问网页，立即返回请求编号 |
| 网页_异步取返回文本(请求编号) | 文本型 | 按请求编号读取 UTF-8 文本结果 |
| 网页_异步取状态代码(请求编号) | 整数型 | 按请求编号读取 HTTP 状态码 |
| 网页_异步取错误信息(请求编号) | 文本型 | 按请求编号读取中文错误信息 |
| 网页_异步取当前请求编号() | 整数型 | 在完成处理器中读取当前分发的请求编号 |
| 网页_异步取消(请求编号) | 逻辑型 | 标记取消指定异步请求 |
| 网页_访问_对象(网址, 访问方式, ...) | 字节集 | WinHTTP 对象方式同步访问网页 |
| 网页_取返回文本() | 文本型 | 读取最近一次同步访问的文本结果 |
| 网页_取返回Cookies() | 文本型 | 读取最近一次同步访问返回的 Cookie |
| 网页_取返回协议头() | 文本型 | 读取最近一次同步访问的响应协议头 |
| 网页_取返回状态代码() | 整数型 | 读取最近一次同步访问的 HTTP 状态码 |
| 网页_取错误信息() | 文本型 | 读取最近一次访问失败的中文错误信息 |

## 访问方式取值

`网页_异步访问` 与 `网页_访问_对象` 的「访问方式」参数取值一致：

`0=GET，1=POST，2=HEAD，3=PUT，4=OPTIONS，5=DELETE，6=TRACE，7=CONNECT，8=PATCH`

## 异步访问（窗口事件中推荐）

完成处理器使用 `&处理器名` 引用当前窗口中的无参数事件或方法，不得用引号包裹成字符串：

```lcpp
类 MainWindow
    整数型 请求编号
    事件 _按钮1_被单击()
        请求编号 = 网页_异步访问("https://ipinfo.io/json", 0, &获取IP完成)
    结束
    事件 获取IP完成()
        请求编号 = 网页_异步取当前请求编号()
        调试输出(网页_异步取返回文本(请求编号))
        调试输出(网页_异步取状态代码(请求编号))
    结束
结束类
```

要点：

- `网页_异步访问` 立即返回，返回值是**请求编号**而不是 HTTP 状态码；`0` 表示异步任务未成功启动（网址或完成处理器无效、后台线程未能创建）。
- 完成处理器在所属窗口的 UI 主线程执行，可以安全更新控件；处理器内部先用 `网页_异步取当前请求编号()` 取得本次编号，再用 `网页_异步取返回文本(编号)`、`网页_异步取状态代码(编号)`、`网页_异步取错误信息(编号)` 读取**按请求编号隔离**的结果，不要用同步族"最近一次结果"命令猜测并发请求归属。
- `网页_异步取消(编号)` 是协作式取消：标记后当前 WinHTTP 请求返回时会以已取消状态分发完成处理器。
- 多个请求并发时各自的结果互不覆盖，可同时携带多个在途请求。

## 同步访问（网页_访问_对象）

`网页_访问_对象` 参数较多，日常 GET/POST 只需前两个参数，其余按需填写：

```lcpp
// GET：取网页文本
网页_访问_对象("https://example.com", 0)
调试输出(网页_取返回文本())
调试输出(网页_取返回状态代码())

// POST：提交 UTF-8 表单
网页_访问_对象("https://example.com/api", 1, "name=lingbuilder&ver=1")
如果 (网页_取返回状态代码() = 200)
    调试输出(网页_取返回文本())
否则
    调试输出(网页_取错误信息())
如果结束
```

完整参数表（按顺序）：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| 网址 | 文本型 | 完整网页地址，必须包含 http:// 或 https:// |
| 访问方式 | 整数型 | 0=GET，1=POST …… 8=PATCH，见上表 |
| 提交信息 | 文本型 | POST 专用，自动 UTF-8 编码 |
| 提交Cookies | 文本型 | 设置提交时的 Cookie |
| 返回Cookies | 文本型 | 兼容占位，当前以 网页_取返回Cookies 读取 |
| 附加协议头 | 文本型 | 一行一个协议头 |
| 返回协议头 | 文本型 | 兼容占位，当前以 网页_取返回协议头 读取 |
| 返回状态代码 | 整数型 | 兼容占位，当前以 网页_取返回状态代码 读取 |
| 禁止重定向 | 逻辑型 | 为真时禁止自动重定向 |
| 字节集提交 | 字节集 | 以字节集作为请求正文提交 |
| 代理地址 | 文本型 | 格式如 `8.8.8.8:88` |
| 超时 | 整数型 | 秒，默认 15，-1 为无限等待 |
| 代理用户名 / 代理密码 | 文本型 | 代理身份验证凭据 |
| 代理标识 | 整数型 | 默认 1，0 使用系统默认代理 |
| 对象继承 | 原生类型 | 预留 WinHTTP 对象继承入口 |
| 是否自动合并更新Cookie | 逻辑型 | 为真时自动合并响应 Cookie |
| 是否补全必要协议头 | 逻辑型 | 为真时自动补全 Referer、User-Agent 等 |
| 是否处理协议头大小写 | 逻辑型 | 为真时统一协议头名称大小写 |

返回值是响应体原始**字节集**；文本内容用 `网页_取返回文本()` 读取（自动按 UTF-8 解码），失败时返回空字节集并通过 `网页_取错误信息()` 给出中文错误。

## 适用场景与取舍

- 快速抓取接口、提交表单、下载文本内容：用本模块，命令贴合易语言习惯，一行即可完成。
- 需要精细控制（独立客户端会话、多超时细分、TLS 证书固定、资源上限、请求级事件）：改用内置的 **HTTP 客户端模块**（`lingbuilder.net.http-client`），两个模块可同时启用。

## 依赖与平台限制

- 依赖 Windows WinHTTP（`winhttp.lib`），生成工程已默认链接；支持 Windows 7 及以上系统。
- 当前仅提供 `windows-msvc-win32` 与 `windows-msvc-x64` 两个 target；macOS 适配后需提供等价实现。
- 同步命令会阻塞调用线程，窗口事件中禁止直接调用 `网页_访问_对象`，请改用 `网页_异步访问`。
- HTTPS 证书校验遵循系统信任链；本模块不提供"忽略证书错误"类开关，需要证书策略控制时使用 HTTP 客户端模块。

## 迁移说明

- 旧工作区中以 `.lbmod` 形式安装的 `lingbuilder.web.http` 1.0.0（仅 6 条同步命令）已被本内置模块取代：安装版模块会与内置模块同名冲突，请卸载旧安装版本，启用内置模块即可获得全部 12 条命令。
- 1.0.0 时代的调用源码无需修改；`网页_访问_对象` 与结果读取命令的签名、语义保持不变。
