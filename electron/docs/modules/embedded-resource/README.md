# 内嵌资源模块（lingbuilder.resource.embed）

把**任意格式**的项目文件在构建期以 RCDATA 打进 EXE，运行期用「资源_*」命令按逻辑名读取，全程不落盘。
适合：内嵌图片、文本/JSON 配置、zip 压缩包、字体、数据文件、以及要交给「内存加载 DLL」的 DLL 字节。

- 模块 ID：`lingbuilder.resource.embed`
- 命令数：8
- 平台：`windows-msvc-win32`、`windows-msvc-x64`
- 类别：系统

## 适用场景

1. 单文件分发：程序要用的图片/文本/压缩包不想散落在 exe 旁边。
2. 交给只吃字节集的接口：`内存DLL_加载(资源_取字节集("dll/mylib.dll"), "mylib.dll")`。
3. 只接受磁盘路径的老库：`资源_释放到临时目录("assets/包.zip")` 拿到真实路径。

## 资源清单从哪里来

**设计器面板（推荐）**：窗口设计器 → 选中窗口（画布空白处点一下）→ 属性面板「项目 / 内嵌资源（跨窗口共享）」。
- 「选择文件…」：本机多选，自动复制进 `<项目源码根>/resources/`（重名自动加后缀）并回填逻辑名。
- 「选择文件夹…」：递归展开成多条，逻辑名保留文件夹内的相对路径。
- 「扫描目录」：引用工作区内已有文件（不复制），逻辑名取工作区相对路径原样。
- 表格内可直接改逻辑名/源文件、勾选「启动释放」、删除条目；未启用本模块时面板顶部有一键启用入口。

也可以在项目模型（`window-designer.json` 的顶层 `embeddedResources`）里手写，跨窗口共享：

```json
"embeddedResources": [
  { "name": "assets/说明.txt", "file": "assets/说明.txt" },
  { "name": "assets/包.zip",   "file": "assets/包.zip", "extract": true },
  { "name": "dll/mylib.dll",   "file": "dll/x64/mylib.dll" }
]
```

- `name`：逻辑名（运行期用它读取，大小写与斜杠方向不敏感）。
- `file`：工作区内相对源文件路径（必须带扩展名）。
- `extract`：真时**进程启动**就释放到 `%TEMP%\lingbuilder-embedded\<工程ID>\<逻辑名>`（保持子目录结构），供只接受磁盘路径的 API；
  为假（缺省）时资源只存在于 EXE 映像内，运行期零释放。

也可以直接添加整个文件夹：把文件夹里每个文件各加一条，`name` 保留相对路径（与「内嵌站点」同一机制，
PE 资源本身是扁平的 key → 二进制块，没有目录概念）。

## 命令清单

| 命令 | 签名 | 说明 |
|---|---|---|
| `资源_取字节集` | `资源_取字节集(逻辑名)` → 字节集 | 读成字节集（失败返回空字节集） |
| `资源_取文本` | `资源_取文本(逻辑名)` → 文本型 | 按 UTF-8 解码（文件须是 UTF-8） |
| `资源_是否存在` | `资源_是否存在(逻辑名)` → 逻辑型 | 清单里有且 EXE 里能取到 |
| `资源_取大小` | `资源_取大小(逻辑名)` → 整数型 | 原始字节数 |
| `资源_列表` | `资源_列表()` → 文本型 | 每行一个逻辑名，便于自检 |
| `资源_保存到文件` | `资源_保存到文件(逻辑名, 路径)` → 文本型 | 覆盖写成真实文件，返回路径 |
| `资源_释放到临时目录` | `资源_释放到临时目录(逻辑名)` → 文本型 | 释放到 %TEMP% 并返回路径 |
| `资源_取错误信息` | `资源_取错误信息()` → 文本型 | 最近一次失败的中文原因 |

## 完整示例

```text
// 内嵌的文本与压缩包
局部 文本型 说明 = ""
局部 整数型 压缩包大小 = 0
局部 字节集 压缩包数据 = 字节集_从文本("")

说明 = 资源_取文本("assets/说明.txt")
压缩包大小 = 资源_取大小("assets/包.zip")
压缩包数据 = 资源_取字节集("assets/包.zip")
调试输出(格式化文本("说明={}，压缩包={} 字节", 说明, 压缩包大小))

// 需要真实文件路径时
局部 文本型 路径 = 资源_释放到临时目录("assets/包.zip")
如果 (路径 = "")
  调试输出(资源_取错误信息())
如果结束

// 内嵌 DLL 直接内存加载（无需项目 DLL 命令声明）
局部 长整数型 模块地址 = 内存DLL_加载(资源_取字节集("dll/mylib.dll"), "mylib.dll")
```

## 放置与构建规则

- 资源号 2301 起按清单顺序分配（图标 101 / 内嵌站点 2101+ / 项目 DLL 2201+ 均已占用）。
- 源文件在构建期会被复制成 ASCII 归档名（`resources/res-0007.bin`）再交给 rc.exe，
  因此**中文路径与中文文件名都能安全内嵌**；逻辑名里的中文只出现在生成的映射表里。
- 上限：条目 ≤ 4096、单文件 ≤ 256MB；总量超过 256MB 会给出体积告警（不阻断）。
- 路径必须位于工作区内且不能含 `..`、引号或控制字符。
- 清单位于设计器模型（项目级），因此**多个窗口共享同一份内嵌资源**。

## 平台限制与边界

- 只支持 Windows 目标（PE 资源机制）；资源数据随 EXE 体积线性增长。
- 内嵌 ≠ 解压：`资源_取字节集` 读 zip 拿到的是原始字节；要解压请先 `资源_保存到文件` 再用 ZIP 模块（或你自己的 zip 库）。
- 内嵌资源只在**构建期**打包：改了源文件必须重新构建，运行期读到的始终是打包时的内容。
- 不要内嵌 `.exe`/`.com` 等可执行文件（无实际意义）；要内嵌可执行代码请用「内存加载 DLL」链路。
- 旧「窗口内嵌文件」（`embeddedFiles`，释放到 %TEMP%）已弃用：打开或构建时会自动迁移成等价的 `extract: true` 条目
  （释放路径不变），构建日志给出中文弃用提示，保存项目即写回新格式。新项目一律使用本模块。
