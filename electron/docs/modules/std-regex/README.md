# 正则表达式模块使用说明（std.regex 1.0）

正则表达式模块（`lingbuilder.std.regex`）基于 C++ `std::wregex`（ECMAScript 语法）提供 10 条中文命令：`正则_完全匹配`、`正则_是否包含`、`正则_取首个`、`正则_替换`、`正则_匹配数量`、`正则_取所有匹配`、`正则_取第N个匹配`、`正则_取分组`、`正则_取所有分组`、`正则_取匹配位置`。表达式非法时一律安全返回失败值（空文本 / 假 / 0 / -1），不抛异常。生成端在 `standardLibraryRuntime` 的 REGEX_RUNTIME 片段（`std::wregex` + `wsregex_iterator`）。

## 典型用法

```text
文本型 结果 = 正则_取首个("订单 A-1001、B-2002", "[A-Z]-[0-9]+")
逻辑型 合法 = 正则_完全匹配(输入, "[0-9]{6,12}")
文本型 个数 = 正则_取分组("2026-09-23", "([0-9]+)-([0-9]+)-([0-9]+)", 2)
```

## 推荐范式：宽松解码 + 正则做「形态校验」（2026-09-23 实测锚定）

对「进程内存 / 文件 / 网络载荷」里命中点的**内容形态校验**（判断一段二进制是否长得像某类字符串，例如形如 `windows_1-<base64>_<数字>_<数字>` 的登录令牌），标准写法是**先用宽松编码把字节集解码成文本，再用正则提取**：

```text
明文 = 编码_字节集转文本(数据, "GB18030")
如果 (明文 == "")
    明文 = 编码_字节集转文本(数据, "ANSI")
如果结束
结果 = 正则_取首个(明文, "windows_1-[A-Za-z0-9+/]{20,90}_[0-9]{6,12}_[0-9]{6,12}")
```

- `GB18030` / `ANSI` 都是宽松编码，ASCII 段原样保留，任意二进制不会让整体解码失败；两种都失败就跳过该命中。
- 独立最小复现实测：同一份数据，**正则法 200/200 命中；逐字节状态机 0/200 漏判**（内存里放的就是合法样本仍判不出来）。状态机的典型错误是 `状态` 在某个 `如果 (状态 == N)` 块内被改写后，同一轮循环里后面的 `如果 (状态 == N+1)` 块立刻又执行一遍——分隔符被当成「数据结束」，结束位置停在分隔符上、段长算成负数，且不崩不卡、只有静默漏判，极难排查。
- 结论：**做形态校验不要写逐字节状态机，把形态判断交给正则**；细则另见《LingBuilder AI 规则手册》「内存命中点形态校验范式」节与 `docs/modules/advanced/process-memory.md`。
