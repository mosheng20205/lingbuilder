# 多线程模块使用说明

多线程模块提供项目级受管任务、类型化参数、进度与完成回调、有界线程池以及常用同步原语。生成的 C++ 使用标准线程能力，不依赖额外运行时 DLL。

## 提交任务

工作处理器使用 `&处理器名` 引用。提交时，记录、数组、文本和标量参数会按值复制到后台任务中：

```text
线程任务 任务 = 线程_提交完成(&计算汇总, &计算完成, 记录参数, 数值数组, "批次A")
```

`线程_提交` 只执行后台工作；`线程_提交完成` 会在工作结束后把完成处理器派发到发起窗口的 UI 线程；`线程_提交进度` 还会合并进度通知，避免频繁刷新界面。

## 状态、取消与进度

- `线程_取状态(任务)` 返回固定状态码：`-1` 无效、`0` 排队、`1` 运行、`2` 成功、`3` 失败、`4` 请求取消、`5` 已取消。
- `线程_请求取消(任务)` 发起协作取消；工作处理器应通过 `线程_是否请求取消(0)` 或 `线程_协作等待(毫秒)` 及时响应。
- `线程_报告进度(百分比, 说明)` 只能从当前工作处理器报告进度。
- 已完成任务可用 `线程_释放任务` 单独释放，也可用 `线程_清理已完成` 批量清理。

## 自定义线程池

默认池按需启动。需要隔离并发数或限制排队数量时，可以创建自定义有界线程池：

```text
线程池 后台池 = 线程池_创建(4, 1000)
线程池_提交(后台池, &后台工作, 参数)
线程池_等待空闲(后台池, 5000)
线程池_关闭(后台池, 5000)
线程池_销毁(后台池)
```

并发数范围为 `1` 到 `64`，队列容量范围为 `1` 到 `100000`。关闭操作采用协作停止，超时不会强制终止正在运行的线程。

## 同步原语

模块提供受管互斥锁、64 位原子整数、自动/手动重置事件和计数信号量。它们都使用 64 位受管 ID，不向中文代码暴露裸 C++ 指针。

```text
线程互斥锁 锁 = 互斥锁_创建()
线程原子整数 计数 = 原子整数_创建(0)
线程同步事件 就绪 = 线程事件_创建(真, 假)
线程信号量 限流 = 信号量_创建(2, 2)
```

互斥执行命令使用 RAII 自动解锁；同一线程重入非递归互斥锁会失败。销毁同步对象前，应确保没有任务仍在持有或等待该对象。

## 界面线程边界

- 后台工作处理器不能直接操作 Win32 控件；界面更新应放在完成或进度处理器中执行。
- `线程_等待`、`线程池_等待空闲` 和同步等待命令会阻塞调用线程。在窗口 UI 事件中应使用有限超时，并避免长时间等待。
- 禁止任务等待自身。任务和线程池停止均为协作式，不会用不安全的方式强杀线程。

## 线程安全队列（2.1.0 新增）

队列族共 8 条命令，内部使用互斥锁与条件变量，工作线程与界面线程可直接共享同一个队列，无需再手写互斥锁保护数组：

- `队列_创建(容量上限)`：容量上限为 `0` 表示无界，`1`～`100000` 为有界队列；返回项目级队列句柄。
- `队列_入队(队列, 文本, 超时毫秒)`：把文本放入队尾；有界队列已满时在超时内阻塞等待（`-1` 无限等待、`0` 立即返回），形成天然背压；队列已销毁时返回假。
- `队列_出队(队列, 超时毫秒)`：从队首取出文本；队列为空时在超时内阻塞等待。返回空文本不代表失败，必须用 `队列_上次出队是否成功()` 判断。
- `队列_上次出队是否成功()`：按线程记录最近一次出队结果，用于区分「取到空文本元素」与「超时空返回」。
- `队列_取长度(队列)`、`队列_是否为空(队列)`、`队列_清空(队列)`、`队列_销毁(队列)`：状态查询与销毁；销毁会唤醒全部等待者（其后续操作返回失败），未取出的数据被丢弃，句柄不复用。

典型生产者-消费者：

```text
线程队列 结果 = 队列_创建(1000)
线程_提交(&后台生产, 结果)

空 后台生产(长整数型 结果队列)
  // 计算得到一条结果后：
  队列_入队(结果队列, 一条结果, -1)
结束

// 界面事件或完成处理器中：
文本型 一条 = 队列_出队(结果, 100)
如果 (队列_上次出队是否成功())
  控件_添加项目(日志列表, 一条)
如果结束
```

队列元素支持文本、整数（`队列_入队整数/出队整数`）和字节集（`队列_入队字节集/出队字节集`）。出队时按规则自动转换：出队→整数转十进制文本、字节集按 UTF-8 解码；出队整数→文本完整十进制解析失败返回 0、字节集取前 8 字节小端；出队字节集→文本按 UTF-8 编码、整数转 8 字节小端。三个出队共用 `队列_上次出队是否成功()` 判断有效性。
