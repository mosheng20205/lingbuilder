# RichList 富列表 RichList · 惯用要点与红线

- 与 `Table` 的区别：`RichList` 是**模板驱动的自定义行布局**（文本/徽标/图片节点自由摆位），`Table` 是固定列网格；行内要放图标+主副标题+状态徽标时用本控件。
- 模板与条目都是 JSON：`NE富列表_设置模板(列表, “{"template":{"rowHeight":64,"nodes":[…]}}”)`、`NE富列表_设置条目(列表, “{"items":[{"key":"task-1","data":{…}}]}”)`。**整串用中文引号 `“ ”` 包裹**，内部保留英文双引号——这是 new_emoji 数据桥已验证的写法，直接写英文引号会被源码字符串边界切断。
- 设计器模型对应属性是 `templateJson` / `itemsJson` / `selectedKeys`；跨事件重设请用 `通过标记文本获取NE富列表("…")` 重新取控件引用，局部变量不跨事件存活。
- 返回值是整数状态码：`设置模板`/`设置条目` 的结果要 `调试输出` 出来，JSON 写错时界面只是「什么都不显示」，没有报错。
- 单条目更新用 `NE富列表_更新条目(列表, "task-1", “{…}”)`，选中用 `NE富列表_设置选中键(列表, “["task-1"]”)`；不要用重设全量条目冒充局部刷新。
- 万行以上必须 `NE_EU_SetRichListVirtualItemCount` + `NE富列表_绑定虚拟数据源(列表, &虚拟数据源)`，处理器 `(整数型 行号)` 内调 `NE富列表_设置虚拟行数据(“{…}”)` 回填；逐条添加行会卡死界面线程。
- 事件都是「事件数据 wideString」（点击/双击/按钮/徽标/右键/倒计时结束都是同一形态），需要结构化字段就自己 `JSON_取文本` 解析该串，别假设存在按行号拆分的参数。

```lcpp
局部 NE富列表 任务列表 = 控件_创建NE富列表(当前窗口, 24, 60, 560, 420, "任务列表", "任务列表", 1)
局部 整数型 模板结果 = NE富列表_设置模板(任务列表, “{"template":{"rowHeight":64,"nodes":[{"id":"name","type":"text","x":18,"y":10,"w":400,"h":24,"field":"name","size":15,"role":"primary"}]}}”)
调试输出("模板结果", 模板结果)
```
