# CSV 数据模块 1.1

模块 ID：`lingbuilder.data.csv`
模块版本：`1.1.0`
目标：Windows / MSVC / Win32 与 x64
运行依赖：无外部 DLL，运行时随生成的 C++ 源码一起编译进 exe

## 适用场景

本模块提供 RFC 4180 风格的 CSV 读写能力，覆盖三类需求：

1. **写**：`CSV_转义字段` / `CSV_生成两列` / `CSV_生成三列` 生成可安全落盘的字段与行。
2. **读整表**：`CSV_打开文件` 按文件读取，`CSV_解析文本` 解析已在内存里的多行文本，结果统一用 `表格数据` 快照承载。
3. **读单行**：`CSV_字段数量` / `CSV_取字段` 只处理一行文本（不跨行）。

要「把 CSV 直接查进数据库」，优先用 SQLite 模块内置的 `csv` 虚拟表（见 `docs/modules/sqlite/README.md`），它不占额外内存副本、可用 SQL 过滤和 JOIN。本模块适合需要在 `.lcpp` 里逐格读取、做界面填充或类型判定的场景。

## 调用方式

`表格数据` 是进程内不复用的 64 位受管句柄，不暴露内部字符串数组：

```
局部 表格数据 表 = CSV_打开文件("员工.csv", "AUTO")
如果 (表 != 0)
    局部 整数型 行数 = 数据表_行数(表)
    局部 整数型 列数 = 数据表_列数(表)
    调试输出(数据表_列名(表, 1))
    调试输出(数据表_取文本(表, 1, 2))
    数据表_关闭(表)
否则
    调试输出(数据表_取错误())
如果结束
```

行号与列号都**从 1 起**，行号不含表头行。所有 `数据表_` 命令在句柄失效或越界时返回空值（0、空文本、假），具体原因读 `数据表_取错误()`；每次进入任一 `数据表_`/`CSV_` 命令都会清空该错误。

## 参数与返回值

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `CSV_打开文件` | 文件路径，可选 编码名称（缺省 `AUTO`）、分隔符（缺省 `,`）、含表头（缺省 真） | `表格数据` | 整文件读取；失败返回 `0` |
| `CSV_解析文本` | CSV文本，可选 分隔符、含表头 | `表格数据` | 解析内存里的多行文本 |
| `数据表_行数` / `数据表_列数` | 表格 | 整数 | 列数取所有记录的最大宽度 |
| `数据表_列名` | 表格, 列号 | 文本 | 无表头或表头缺名时为 `列N` |
| `数据表_取文本` | 表格, 行号, 列号 | 文本 | 单元格原文 |
| `数据表_单元格类型` | 表格, 行号, 列号 | 整数 | `0` 空、`1` 整数、`2` 小数、`3` 布尔、`4` 文本 |
| `数据表_取整数` / `数据表_取小数` | 表格, 行号, 列号 | 长整数 / 小数 | 内容不合形态时返回 `0` 并记录错误 |
| `数据表_取布尔` | 表格, 行号, 列号 | 逻辑 | `TRUE/真/1/YES/是` 为真，`FALSE/假/0/NO/否` 为假，其它按假 |
| `数据表_单元格为空` | 表格, 行号, 列号 | 逻辑 | 空文本或越界都为真 |
| `数据表_关闭` | 表格 | 逻辑 | 重复关闭返回假 |
| `数据表_取错误` | 无 | 文本 | 最近一次失败的中文说明 |

## 解析语义（必须与实现一致）

- **引号内的换行属于字段内容**，不会被当成记录结束；`"表示"引用"` 形式的内部引号翻倍写。
- 记录结束符支持 `\r\n`、`\n`、`\r` 三种，可混用。
- 空行（没有引号的单个空字段）被跳过，不产生记录；因此文件末尾的换行不会多出一行空记录。
- 分隔符取参数的**首字符**生效，支持半角逗号、分号、竖线、制表符和全角逗号。
- 列数取所有记录的最大宽度：窄行右侧补空，宽行超出列数的字段被忽略。
- `含表头` 为真时第一条记录转为列名并从数据行中扣除。

## 编码

`编码名称` 忽略大小写与空格、连字符、下划线，支持 `UTF-8`、`UTF-16LE`、`UTF-16BE`、`UTF-32LE`、`UTF-32BE`、`ANSI`、`GBK`、`GB2312`、`GB18030`，以及 `AUTO`。

`AUTO` 的顺序是固定的三级：**BOM → 严格 UTF-8 → GB18030 兜底**（GBK/GB2312 都是 GB18030 子集）。不做启发式猜测，避免把语义错误但字节合法的流误判成某种中文编码。显式指定编码时，若字节不是该编码的合法序列，`CSV_打开文件` 返回 `0` 并在 `数据表_取错误()` 给出中文原因，不会静默换一种编码重试。

同一份编码内核也服务 `文件_读取文本(路径, 编码名称)` 与 `编码_字节集转文本(数据, 编码名称)`；不要在自己代码里再写一套代码页映射。

## 依赖与平台限制

- 无第三方依赖；Win32 与 x64 均由 MSVC 编译验证。
- 整文件按一次读取解码进内存（宽字符约两倍文件体积），适合常规配置表与业务导出文件。超大文件（数十万行以上）建议改用 SQLite 的 `csv` 虚拟表，或按业务分批导出。
- 快照句柄进程内全局登记，跨线程共享同一 `表格数据` 时由调用方自行串行化。

## 迁移说明

- 1.0.x → 1.1.0：原 5 条行级命令名称、签名与语义**完全不变**；`CSV_字段数量` / `CSV_取字段` 的行说明补上了「不跨行」提示，含换行的字段请改用 `CSV_打开文件` 或 `CSV_解析文本`。
- 历史代码里用 `文件_读取文本(路径)` + 自行按 `\n` 拆行的写法，遇到引号内换行会读错列；迁移到 `CSV_打开文件` 即由内核统一处理。
