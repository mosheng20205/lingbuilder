# LingBuilder Windows 安装包重新打包提示词（唯一权威流程）

> **AGENTS.md 强制引用**：任何「重新打包 / 出安装包 / repack / 出 setup / 打新版本包」任务，开工前必须完整阅读本文档并严格按流程执行，禁止凭记忆或简化步骤。
>
> 本文档 2026-10-27 由 0.8.36 安装事故复盘落地。旧文档 `docs/精简版打包提示词.md`（0.6.1 时代）降级为「版本号同步、依赖恢复、历史失败对照」的细节附录；其中「win-unpacked 被占就换输出目录」的建议**已证伪作废**——正是它导致 0.8.36 安装包在所有机器上必然安装中止（见第 5 节事故一）。

## 0. 一键提示词（复制整段给执行 AI）

```text
请为 LingBuilder 重新打包 Windows x64 正式联网安装包。全程遵守仓库根目录 AGENTS.md 与 docs/重新打包提示词.md，按以下步骤执行，不得跳过任何门禁与核验。

【目标】
- 产物：electron/release/LingBuilder-<目标版本>-x64.exe（NSIS）+ .blockmap。
- 云端配置：resources/cloud-release.json = {"schemaVersion":1,"cloudMode":"online","cloudApiOrigin":"https://api.lingbuilder.com"}。
- 精简定义不变：安装包严禁包含 lingbuilder.cef3.sdk / lingbuilder.fbro.sdk 模块目录与 SDK 二进制，CEF3/FBro 由内置 aria2 按需下载；verify 门禁强制拦截，禁止改过滤器绕过。

【步骤 1：打包前检查】
1. electron/package.json 的 version 已是目标版本；版本同步细节（根/contracts/cloud 五处 package.json、两处 lock、mcpServer 等硬编码版本、发布说明）按 docs/精简版打包提示词.md「步骤 1」清单执行并按当前代码核对。
2. 若本次改过 electron/installer/installer.nsh：先跑 cd electron && npm run test:installer，3 个断言组必须全绿。
3. 关闭所有从 electron/release/win-unpacked 运行的 LingBuilder 实例与测试进程（被占会导致 EPERM unlink 打包失败，也会污染量尺）。AI 客户端（Codex/Claude/ZCode）会自动重启其 MCP 宿主——该宿主进程名就是 LingBuilder.exe（位于安装目录，node 模式跑 cli.cjs），必要时按「杀 cmd.exe 包装 → 改名安装目录 lingbuilder.cmd → 杀 LingBuilder.exe」顺序清场。

【步骤 2：执行打包（标准链，禁止换道）】
cd electron
LINGBUILDER_CLOUD_RELEASE_MODE=online LINGBUILDER_CLOUD_API_URL=https://api.lingbuilder.com npm run package:win
- 链路：prepare-cloud-release-config → module:crypto-sdk → verify:cef3/fbro/skill-kit-release → npm run build（vite + monaco NLS 门禁 + build-meta + server/cli/extension-host/electron 编译）→ prepare:nsis → prepare:webview2 → electron-builder --win nsis --x64（beforePack 自动打「单阶段直解」NSIS 补丁；afterPack 自动写量尺锚点 lb-app-out-dir.txt + 严格精简校验）→ verify:cef3/fbro/skill-kit-installer。
- 耗时约 10-20 分钟，建议后台执行并轮询日志；判断成败以日志内容为准（出现 npm error / failed 即失败）——管道（如 | tail）会吞真实退出码，不能只看 exit 0。
- 红线：禁止用 -c.directories.output= 换输出目录，产物固定在 electron/release 根。win-unpacked 被占的正确处置是清占用进程后重跑，不是换目录绕开（0.8.36 事故根因，见第 5 节）。

【步骤 3：打包后核验（全部通过才算完成）】
1. 量尺锚点：cat electron/build/lb-app-out-dir.txt 必须为 LB_APP_OUT_DIR=<本次打包的 win-unpacked 绝对路径>。
2. 负载与基准同源（核心核验，缺此步等于没验）：
   - 记下 electron/release/win-unpacked/resources/app.asar 字节数 A 与 win-unpacked/LingBuilder.exe 字节数 B；
   - 7z x electron/release/LingBuilder-<版本>-x64.exe -o<临时目录>，再 7z l <临时目录>/'$PLUGINSDIR'/app-64.7z，包内 resources\app.asar 必须等于 A、LingBuilder.exe 必须等于 B。
   - 不一致＝安装包在任何机器上都会安装中止（弹「核心程序文件被占用」假象），必须重新打包，禁止交付。
3. 内容抽查：grep -ac "<新版本号>" win-unpacked/resources/app.asar 命中；asar 内 dist/build-meta.json 版本/构建时间正确（安装目录根下另有历史遗留的旧 build-meta.json，不代表构建身份，以 asar 内为准）。
4. 三个 verify:*-installer 门禁在链内已跑，日志不得有 FAIL。
5. （推荐）本机 /S 安装冒烟：先确认 HKCU\Software\<APP_GUID>\InstallLocation（APP_GUID 见注册表卸载键同名 GUID）指向的目录真实存在且非历史错误目录（0.8.36 曾被指向 C:\Program Files (x86)\LingBuilder 残留），再运行安装包 /S，退出码必须 0；装后核对 ProductVersion 与 asar 字节数。注意 /S 是真实升级本机。
6. 报告：产物路径与字节数、核验 1-5 结果、变更文件清单；代码改动保持未提交，由用户决定是否提交；更新记录按 AGENTS.md 规则追加当天 更新记录/YYYY-MM-DD.md。
```

## 1. 红线（逐条来自真实事故）

1. **只用标准链**：`cd electron && LINGBUILDER_CLOUD_RELEASE_MODE=online LINGBUILDER_CLOUD_API_URL=https://api.lingbuilder.com npm run package:win`。缺环境变量会在第一步 prepare-cloud-release-config 直接失败。
2. **禁止 `-c.directories.output=` 换输出目录**。安装器的期望尺寸核对基准来自 afterPack 写出的 `build\lb-app-out-dir.txt`（指向真实打包目录）——现行机制虽能跟随自定义目录，但换目录会产生「子目录产物 + 根目录陈货」并存的混乱（旧文档 0.6.1 时代的换目录建议已造成 0.8.36 全量报废）。win-unpacked 被占的唯一正确处置：清占用进程后重跑。
3. **打包后必须做第 3.2 条负载与基准同源核验**，只看 `electron-builder` 日志成功不算完成。
4. **不要杀用户正在使用的进程**来解锁 win-unpacked；先确认进程身份（命令行、启动时间），测试实例可清，用户实例应报告用户。
5. **禁止带病放行**：任何门禁失败先读完整日志与相关脚本定位根因，不得跳过/注释门禁强行出包。

## 2. 打包链与产物结构速查

- 命令入口：`electron/package.json` 的 `package:win`，必须在 `electron/` 目录运行。
- NSIS 外壳只含十几个文件（`$PLUGINSDIR/app-64.7z`、WebView2 引导器、卸载器等），应用全部内容在内嵌 `app-64.7z` 里；7z 负载由 electron-builder 从 win-unpacked 打出。
- beforePack 自动维护「单阶段直解」NSIS 模板补丁（`scripts/patch-nsis-single-phase-extract.cjs`，模板漂移会 loud 失败），禁止手工改 node_modules 里的 NSIS 模板。
- afterPack（`scripts/verify-cef3-after-pack.cjs`）做两件事：严格精简校验（SDK 不随包）+ 把 `context.appOutDir` 写进 `build/lb-app-out-dir.txt` 供安装器量尺。
- 7za 查找顺序：`LINGBUILDER_7ZA_PATH` 环境变量 → PATH → electron-builder 缓存；本机装了 7-Zip 时通常无需设置。
- 依赖恢复（CEF3/FBro SDK 模块、aria2 三件套、7za MSI 提取）与版本号同步五处清单：见 `docs/精简版打包提示词.md` 步骤 1、2 与附录对照表（仍有效部分）。

## 3. 安装器机制（为什么有这些核验）

- **期望尺寸核对**：`installer.nsh` 在 makensis 编译期从 `lb-app-out-dir.txt` 指向的目录实测 exe/asar 字节数（`LB_EXPECTED_*`），安装落盘后比对，防「半更新」。**基准必须与负载同源**——写死目录或换输出目录都会让它失效，失败形态是误导性的「安装已中止：核心程序文件被占用」弹窗。判别口诀：修复循环跑满 3 轮而目标文件零字节变动＝常量错（打包问题），不是文件锁。
- **$INSTDIR 播种**：安装向导从 `HKCU\Software\<APP_GUID>\InstallLocation`（注意不是卸载注册键）预填目录；`preInit` 只清除「指向目录已无主程序」的死指针。装错目录先查这个值；本机为按机器安装器（INSTALL_MODE_PER_ALL_USERS_REQUIRED），播种值即一切。
- **MCP 宿主复活**：Codex/Claude/ZCode 等客户端会自动重启其 LingBuilder MCP 宿主（进程名 LingBuilder.exe，从安装目录经 lingbuilder.cmd 拉起）；测试安装器前按「杀 cmd 包装 → 改名 lingbuilder.cmd → 杀宿主」断复活链，装完安装器会自动恢复 cmd。
