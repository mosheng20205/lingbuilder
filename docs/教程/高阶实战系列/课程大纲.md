## 制作规则（每集必须遵守）

1. 面向新手：从「新建项目」截起，每步操作一张配图，命令逐参数解释。
2. 每张标注截图用 Read 目检：红框位置是否对准目标控件/代码行；代码截图必须含完整事件块（事件行＋逻辑行＋结束行），滚动位加密覆盖防漏段。
3. 运行/编译前先看 IDE 底部错误列表，截图「零报错」状态；有报错先修复再继续。
4. 每集导出 `.lcpppkg` 一键分享源码包＋同名预览图（进阶系列分流口径）。
5. 每集独立会话制作，防止上下文撑满；交接以本文件＋项目记忆为准。

## 技术红线备忘（正文必须警示）

- **企微**：webhook 参数名是 `key` 不是 access_token；news 图文 **url 必填**（40039）；Markdown **不能 @**（与钉钉相反）；文本 2048 字节（UTF-8≈680 汉字）、Markdown 4096 字节；图片 ≤2MB 仅 jpg/png（运行时自动 base64＋小写 MD5）；文件 ≤20MB、media_id 3 天有效；语音与 template_card 不做结构化命令（走 `推送_发JSON`）。
- **钉钉**：Markdown **title 必填**（400402，运行时自动取正文首个非空行截 20 字）；Markdown **能 @** 但内容须同时出现 `@手机号` 文本；加签＝毫秒时间戳+"\n"+SEC → HMAC-SHA256(key=SEC) → base64 → urlencode → 拼 URL；webhook 不能直接发图片（接口权限差异）；关键词过滤与加签可叠加（两条都要满足）。
- **飞书**：加签＝**秒**时间戳写进 body 的 `timestamp`/`sign` 字段（与钉钉 URL 拼接不同）；@ 靠 open_id 内联标签 `<at user_id="...">`（不是手机号）；旧版响应格式 `{"StatusCode":0,...,"code":0}`，成功判定 errcode/StatusCode/code 三键兜底。
- **通用**：三家均约 20 条/分钟限流；内容参数收原文文本、JSON 信封由运行时构建（防引号/换行/反斜杠炸裂）；Git Bash 里 curl 内联中文会转 GBK（模块运行时无此问题）。
