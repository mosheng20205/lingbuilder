# LingBuilder 0.6.4 更新记录

发布日期：2026-09-05　　对比版本：0.6.3

---

## 新增

### 数组操作模块（`lingbuilder.std.array`）

补齐 LingCpp 数组一直缺失的运行时能力。此前数组只能声明、传参、下标访问和用 `枚举循环首` 遍历，没有任何命令可以读取长度或追加成员。

共 13 条中文命令：

| 命令 | 返回 | 说明 |
| --- | --- | --- |
| `数组_取成员数(数组)` | 整数型 | 当前成员数量 |
| `数组_是否为空(数组)` | 逻辑型 | 是否没有任何成员 |
| `数组_取成员(数组, 索引)` | 元素类型 | 越界返回元素类型默认值 |
| `数组_置成员(数组, 索引, 值)` | 逻辑型 | 越界返回假且不修改 |
| `数组_加入成员(数组, 值)` | 整数型 | 末尾追加，返回追加后的成员数 |
| `数组_插入成员(数组, 索引, 值)` | 逻辑型 | 索引等于成员数时等价于追加 |
| `数组_删除成员(数组, 索引)` | 逻辑型 | 后续成员依次前移 |
| `数组_清空(数组)` | 逻辑型 | 删除全部成员 |
| `数组_查找(数组, 值)` | 整数型 | 首个相等成员索引，未找到返回 -1 |
| `数组_是否包含(数组, 值)` | 逻辑型 | 是否存在相等成员 |
| `数组_排序(数组, 升序)` | 逻辑型 | 按元素自身顺序稳定排序 |
| `数组_倒序(数组)` | 逻辑型 | 整体反转当前顺序 |
| `数组_重定义(数组, 新成员数)` | 逻辑型 | 截断或用默认值补齐 |

- 不引入新的数组类型，直接作用于语言原有的数组声明（`局部 文本型 名单[]`、`全局 整数型 编号[]`、参数 `整数型[] 编号集合`、记录字段的数组维度），生成的 C++ 中对应 `std::vector<T>`，值语义随作用域自动释放。
- 命令对元素类型透明：基础类型、文本型、字节集、项目自定义记录和模块公开记录都可以作为成员。
- 索引统一从 0 开始；所有越界索引一律安全返回失败值，不抛异常、不崩溃。
- `数组_查找`、`数组_是否包含` 需要元素类型支持相等比较，`数组_排序` 需要支持大小比较；记录型默认不带比较运算，调用这三条命令会稳定返回 -1 或假，不会编译失败。需要按字段查找或排序时请用 `计次循环首` 配合字段比较自行实现。
- 与 `lingbuilder.data.json` 的 `JSON_数组_*` 不同：后者操作受管 `JSON值` 句柄、需要 `JSON_释放`，本模块操作语言原生数组值，两者不能混用。

内置模块总数由 84 增至 85，中文命令总数由 2998 增至 3011。

### 数组纳入类型推断

- 数组下标取值 `名单[0]` 现在参与类型推断，可定型到元素类型（此前无法定型）。
- 数组成员型命令（如 `数组_取成员`）没有固定返回类型，改为按本次调用的数组实参求解元素类型。
- 局部变量、程序集变量、项目全局变量和记录字段的数组维度，统一以 `元素类型[]` 参与初始化检查、返回值检查与补全提示。

### 数组命令编辑期校验

新增专用诊断，在编辑期直接报错而不是等到编译：

- 数组参数必须是数组变量名或记录字段路径，不能传命令结果、下标或其它表达式（数组命令会就地读写传入的数组）；
- 数组变量必须已在局部变量表、程序集变量表或项目全局变量表中声明；
- 传入的必须是数组类型，标量会被拒绝并提示打开「数组」开关；
- 成员参数类型必须与数组元素类型一致；
- 参数个数必须与命令签名一致。

### 应用内更新

「帮助 → 检查更新」发现新版本后，可直接在 IDE 内完成下载、校验和安装，不必再跳转官网手动下载；云端未提供安装包直链或校验值时，对话框自动降级为「前往官网下载」。启动后的静默检查也走同一对话框。

### 数组操作示例项目

新增 `examples/array-operations-demo`，可直接打开并 F5 运行，覆盖追加、遍历、查找、删除、排序等典型用法。

## 改进

### 动态图像控件 GIF 播放

Win32 原生生成器改为一次性预渲染全部帧，并使用持久化双缓冲 DIB 在控件自身的 `WM_PAINT` 中绘制当前帧；动画定时器只推进帧索引并触发无擦除重绘，不再逐帧调用 `STM_SETIMAGE` 替换位图。消除了逐帧解码开销、GDI 句柄抖动和画面闪烁。控件销毁与 DPI 重建时会释放双缓冲 DC、DIB 与 GDI+ Image。

### 第三方模块清单校验新增数组门禁

- `array` 不能作为命令的 `returnType`——泛型数组只能作为参数原样传递；
- `arrayElement` 无论用作参数还是返回值，都必须同时声明一个 `array` 参数来确定元素类型；
- 带原生 DLL 目标的命令不能传递 `array` / `arrayElement` 参数——泛型数组只服务于同工程值语义运行时。

### AI 生成规则同步

启用数组模块时，AI 必须使用原生数组命令操作数组，不得再用分隔符文本、控件列表或 `JSON值` 模拟动态数组；并明确记录型数组不能按字段查找或排序，避免 AI 给出不成立的用法。

## 修复

### 云端检查更新会漏推新版本

客户端更新接口原先只按 `sortOrder` / `publishedAt` 取第一条发布记录。后台若给旧版本设置了更大的排序值，就会把新版本压住，导致所有用户都收不到更新。现改为在候选发布记录中按语义化版本号取最高版本，排序值只作为同版本号之间的次级顺序。

### DataGrid 命令目录类型收窄

DataGrid 的原生 ABI 只承载标量与文本，不承载 LingCpp 数组值。其命令目录的绑定返回类型已在类型层面排除 `array` / `arrayElement`，防止误声明。
