# 自研内核模块方案：lingbuilder.hydriver（64 位驱动能力全覆盖）

> 状态：方案已获方向性批准（2026-10-03），本文档为实施蓝图。
> 目标：以自研 x64 内核驱动 + lbmod 模块封装，**全覆盖** `Hy_Driver`（C:\Users\Administrator\Downloads\Hy_Driver）的 55 个导出能力，并摆脱其 32 位 DLL 限制。

## 一、总架构

```
┌─ 用户 .lcpp 程序（x64，requireAdministrator）
│    调用 lingbuilder.hydriver 命令（~70 条中文命令）
│
├─ lbmod 模块 C++ 源码（src/，编入用户工程）
│    ├─ 驱动通信层：CreateFile(\\.\\LingDrv) + DeviceIoControl 封装
│    ├─ 用户态能力层：特征码扫描（含 ?? 通配/加花定位）、后台键鼠 PostMessage
│    └─ 模块部署层：释放 .sys → 按[加载策略]装载 → 健康检查
│
└─ 自研内核驱动 lingdrv.sys（x64，单一 .sys）
     ├─ 内存：跨进程 RW（附加/Mdl 双模式）、申请/释放/属性、模块枚举、PEB
     ├─ 进程：保护/提权/降权/强杀/隐藏/伪装/禁止新进程/暂停恢复
     ├─ 文件：强删（含占用句柄强制关闭）、文件保护
     ├─ 注入：内核 APC 注入 DLL、远程线程
     └─ 键鼠：attach KeyboardClass/PointerClass 注入前台输入
```

设计原则（对齐 Hy_Driver 已验证的分工）：
- **驱动只提供原语**：IOCTL 粒度尽量小、参数简单（PID + 地址 + 缓冲）。
- **复杂逻辑在用户态**：特征码扫描、类型化读写、通配解析、加花定位全在模块 C++ 里做——这正是 Hy_Driver「驱动 + 易语言扩展层」的分工，可完全复刻且不用把扫描逻辑塞进内核。
- **稳定 API 优先**：`KeStackAttachProcess`/`Mdl`/`ObRegisterCallbacks`/`PsSetCreateProcessNotifyRoutineEx` 均为文档化接口，不依赖内核偏移；仅「隐藏/伪装」两项必须用 EPROCESS 偏移（见 4.2 动态定位策略）。

## 二、驱动 IOCTL 面

设备名 `\Device\LingDrv` / 符号链接 `\??\LingDrv`，IOCTL 前缀 `0x8C00`，缓冲方式 METHOD_BUFFERED 为主（大块读写用 METHOD_OUT_DIRECT/IN_DIRECT）。

### A. 内存读写与管理
| IOCTL | 功能 | 内核实现 |
|---|---|---|
| MEM_READ | 读任意进程内存 | 模式 0：`KeStackAttachProcess` + 直接 memcpy；模式 1：`MmProbeAndLockPages`(Mdl) + `MmMapLockedPagesSpecifyAccess`——对齐 Hy_Driver `初始化_读取方式(0附加/1Mdl)` 双模式 |
| MEM_WRITE | 写任意进程内存 | 同上双模式 |
| MEM_ALLOC / MEM_ALLOC_EX | 远程申请内存 | `ZwAllocateVirtualMemory`（Ex 支持 0 基址随机/指定地址/高位 `MmAllocateAlignedMemory` 偏好，属性透传 PAGE_*/MEM_*） |
| MEM_FREE | 远程释放 | `ZwFreeVirtualMemory` |
| MEM_QUERY | 查询内存属性 | `ZwQueryVirtualMemory`(MemoryBasicInformation) |
| MEM_PROTECT | 修改内存属性 | `ZwProtectVirtualMemory` |
| PROC_MODULE_BASE | 取指定模块基址 | attach 后遍历 `PEB->Ldr->InLoadOrderModuleLinks`（用户态 PEB 路径太繁，内核一次取齐） |
| PROC_MAIN_MODULE | 取主模块基址 | PEB->ImageBaseAddress |
| PROC_PEB | 取 PEB 地址 | `EPROCESS->Peb`（x64 直接读，无需 Wow64 转换——只支持 x64 目标进程，Wow64 进程返回 32 位 PEB 并带标记） |
| PROC_IS64 | 是否 64 位进程 | `PsGetProcessWow64Process` 是否为 NULL |

### B. 进程操控
| IOCTL | 功能 | 内核实现 |
|---|---|---|
| PROC_PROTECT | 进程保护/取消 | `ObRegisterCallbacks`(PsProcessType+PsThreadType) 剥离他人句柄的 PROCESS_TERMINATE/VM_WRITE/VM_READ 权限；支持多 PID 白名单 |
| PROC_ELEVATE / PROC_DEGRADE | 提权/降权 | 目标 `EPROCESS->Token` 换成 System(4) 进程 Token 引用（提权）/ 受限 Token（降权恢复原 Token） |
| PROC_KILL | 强杀（绕保护） | `ObOpenObjectByPointer` 拿内核句柄（不受自身保护回调影响）→ `ZwTerminateProcess` |
| PROC_HIDE | 隐藏/取消隐藏 | DKOM：从 `ActiveProcessLinks` 摘链/回链（保存前后节点便于恢复） |
| PROC_DISGUISE | 伪装父进程 | 改写 `EPROCESS->InheritedFromUniqueProcessId` |
| PROC_BLOCK_NEW | 禁止/解锁新进程 | `PsSetCreateProcessNotifyRoutineEx` 回调置全局开关，命中时 `PsCreateProcessNotifyInfo->CreationStatus = STATUS_ACCESS_DENIED`；稳定 API 无偏移 |
| PROC_SUSPEND / PROC_RESUME | 暂停/恢复 | 内核档：attach 后遍历目标全部线程，对每线程内核强句柄调 `NtSuspendThread` 等价路径；实现顺序见 4.3 |

### C. 文件与注入
| IOCTL | 功能 | 内核实现 |
|---|---|---|
| FILE_FORCE_DELETE | 强删文件 | 三步：① 遍历 `SystemHandleInformation` 找到占用该文件的句柄，跨进程 `ZwDuplicateObject`+`ZwClose` 强制关闭；② `ZwCreateFile`(DELETE) + `FILE_DISPOSITION_INFORMATION` 标删除；③ 仍占用则改名为随机临时名+标删除（重启后消失）——对齐「强删」语义 |
| FILE_PROTECT / FILE_UNPROTECT | 文件保护/解锁 | `ObRegisterCallbacks`(IoFileObjectType) 剥离他人句柄的 DELETE/WRITE 权限；返回保护 ID 供解锁 |
| PROC_INJECT | DLL 注入（路径） | 内核 APC 注入：attach 目标 → `ZwAllocateVirtualMemory` 写 DLL 路径(UTF-16) → `KeInitializeApc`+`KeInsertQueueApc` 让目标线程执行 `LdrLoadDll`（技术参考 Blackbone，MIT，不引入其代码） |
| PROC_REMOTE_THREAD | 远程线程 | 同 APC 通道：以用户态传入的「开始地址+参数地址」构造 APC，等价 `CreateRemoteThread` |

### D. 前台键鼠注入
| IOCTL | 功能 | 内核实现 |
|---|---|---|
| INJ_KEY | 键盘按键（按下/弹起） | 初始化时 `IoAttachDevice` 到 `\Device\KeyboardClass0`（成功后保存服务回调指针）；注入时构造 `KEYBOARD_INPUT_DATA` 直调服务回调——免重启、免过滤驱动注册表，Win10/11 x64 可用 |
| INJ_MOUSE | 鼠标（移动/按键/滚轮） | 同法 attach `\Device\PointerClass0`；构造 `MOUSE_INPUT_DATA`：`MouseData` 相对/绝对移动（绝对=X/Y 归一化 0~65535 + `MOUSE_MOVE_ABSOLUTE`）、ButtonFlags 五键（含 XBUTTON1/2 侧键）、Wheel 上下滚 |
| INJ_MOUSE_ABS_POS | 绝对移动取屏幕尺寸 | 用户态 `GetSystemMetrics` 完成，不进内核 |

> 说明：后台键鼠族（按 HWND）**不需要驱动**——`PostMessage`/`SendMessage` 即可，且 LingBuilder 现有 `lingbuilder.input.keyboard/mouse` 模块已有「窗口消息」族；本模块在 C++ 侧实现同形命令，参数形态对齐 Hy_Driver（HWND + X + Y + 按键类型）。

## 三、lbmod 模块命令面（lingbuilder.hydriver）

包结构（对齐 MMKV 模板）：
```
.lingbuilder/module-build/lingbuilder.hydriver/
  lingbuilder.module.json     # manifest v2, targets: 仅 windows-x64
  driver/lingdrv.sys          # 自研驱动二进制（批1起随包）
```

### 模块门禁
- **仅 x64**：manifest `targets` 限 windows-x64；Win32(x86) 构建给中文阻断诊断（与 Hy_Driver 相反，我们全 64 位）。
- **管理员要求**：所有驱动族命令在未提权进程内调用返回明确中文错误（提示项目需以管理员运行——给项目模板/例程配 requireAdministrator 说明，链接点传参方式项目已有先例）。

## 四、关键技术决策

### 4.1 加载策略（驱动_安装 的 `策略` 参数）
| 策略 | 适用 | 说明 |
|---|---|---|
| 0 服务模式（默认） | 开发机 | `sc create` + `sc start`；要求驱动已测试签名或机器开了 `bcdedit /set testsigning on` |
| 1 免签名映射 | 无签名环境 | 内置 KDMapper（MIT）+ iqvw64e.sys 加载；**杀软/HVCI 风险如实声明**，默认不启用，须用户显式传 1 |
| 2 指定签名驱动路径 | 正式发布 | 用户自购 EV 证书签名后的 lingdrv.sys，`驱动_安装(2, "D:\签名版\lingdrv.sys")` |

### 4.2 EPROCESS 动态定位（隐藏/伪装/提权的前置）
三个候选按序尝试，全部失败才报错：
1. **符号表**：随包带 `ntoskrnl.exe` 关键偏移表（UniqueProcessId/ActiveProcessLinks/Token/InheritedFromUniqueProcessId），按内核版本号（`RtlGetVersion`）索引——覆盖 Win10 19041~Win11 当前主流构建；
2. **PDB 解析**：参考 KDMapper `SymbolsFromPDB` 思路在线拉符号（需网络，作为兜底）；
3. **特征扫描**：在 `System`(4) 进程 EPROCESS 附近按模式扫描（最后兜底）。
每条命令的实现不得写死偏移；「驱动_取最后错误」要能报告用的是哪一档定位。

### 4.3 进程暂停/恢复实现顺序
先内核档（`ObOpenObjectByPointer` + 遍历 `EPROCESS->ThreadListHead`，对每线程内核句柄走挂起路径）；若某构建内核档不可用，自动降级用户态（`NtQuerySystemInformation` 取线程 → 逐 `NtSuspendThread`）并在返回值/诊断中注明用了哪档——对齐 Hy_Driver 行为同时不静默降级。

## 五、实施批次（每批真机验收后才进下一批）

- **批 0 环境核实**：① 本机 WDK 是否可用（构建 .sys 必需，缺则先装）；② 核实 lbmod 包内二进制文件的部署路径契约（模块 C++ 运行时如何拿到 .sys 的磁盘路径——对照 cef3-sdk 的 runtime-manifest 机制）；③ 确定 manifest targets 仅 x64 的写法。
- **批 1 骨架 + 内存族**：驱动骨架（设备/IOCTL/装卸）+ MEM_READ/WRITE/ALLOC/FREE/QUERY/PROTECT + 模块命令 + 真机读写记事本内存验证。**这是最大风险点（驱动能否加载），最先验证。**
- **批 2 进程族**：保护/强杀/提权/降权/Peb/是否64位/禁止新进程/暂停恢复 + EPROCESS 动态定位 + 隐藏/伪装 + 真机验证（目标：自写测试程序，不拿真实游戏反作弊做验收）。
- **批 3 文件族 + 注入**：强删/保护 + APC 注入 + 远程线程 + 真机验证（注入目标：自写宿主程序）。
- **批 4 键鼠族**：attach kbdclass/mouclass 前台注入 + 后台 PostMessage 族 + 真机验证（记事本打字/画图点击）。
- **批 5 特征码 + 收尾**：特征码四命令（含 Ex/动态Ex 照抄 .e 逻辑）+ 模块打包 .lbmod + 例程 + 文档四层同步（模块 README、`docs/MODULE_ENCAPSULATION_CHECKLIST.md`、`MCP_INSTRUCTIONS` 推送、`LingBuilder AI 规则手册.md`）+ 每日更新记录。

## 六、风险与边界（如实声明）

1. **HVCI/内存完整性**：Win11 默认开启的「内核隔离」会阻止未签名驱动加载（服务模式与 KDMapper 都失效）。模块文档必须写明：开启 HVCI 的机器只能走策略 2（签名驱动）。
2. **杀软**：自研无签名 .sys + KDMapper 加载大概率被杀软拦截/告警，属预期行为，文档如实说明，不做「免杀」承诺。
3. **PatchGuard**：DKOM 摘链（ActiveProcessLinks）不在 PG 直接保护范围，但属灰色技术，未来 Windows 加固可能失效——命令失败要给明确诊断而非蓝屏。
4. **合规**：模块定位为「自研软件调试与安全研究」，随包文档注明适用边界；不内置对特定商业反作弊的对抗逻辑。
5. **稳定性红线**：驱动任何 IOCTL 失败路径必须 `__try/__except` 包裹 + 引用计数严谨，绝不允许因非法参数蓝屏；批 1 起每条 IOCTL 配坏参数回归用例。
