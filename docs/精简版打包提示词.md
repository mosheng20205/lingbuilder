# 精简版打包提示词（Windows 联网安装包）

本文档是「LingBuilder Windows x64 精简联网安装包」的可复用打包提示词，来自 0.6.1 版本（2026-08-29）一次完整端到端打包的实操经验。把下方「一键提示词」整段复制给 AI 执行即可；文档末尾附常见失败处置对照与固定事实速查，供人工排障使用。

与 `AGENTS.md`「生产环境 API 信息」章节保持一致：云端地址 `https://api.lingbuilder.com`，正式联网打包只通过环境变量切换，不修改源码或 electron-builder 配置。

---

## 一键提示词（复制整段使用）

```text
请为 LingBuilder 打包一个 Windows x64 精简联网正式安装包。全程遵守仓库根目录 AGENTS.md 的相关规则，按以下步骤执行，不要跳过任何门禁。

【目标】
- 产物：electron/release/LingBuilder-<目标版本>-x64.exe（NSIS，约 140MB 级别）+ .blockmap。
- 必须对接生产 API：安装包内 resources/cloud-release.json 为 cloudMode=online、cloudApiOrigin=https://api.lingbuilder.com。
- 精简定义（不可违反）：安装包严禁包含 lingbuilder.cef3.sdk 与 lingbuilder.fbro.sdk 模块目录及任何 SDK 二进制（libcef.dll、FBrowserVIP.dll、LingBuilderFbroBridge.dll、LingBuilderCefBridge.dll 等）；CEF3/FBro 能力靠安装包内置的 aria2 下载器按需下载。electron/package.json 的 extraResources 过滤器已排除这两个 SDK，发布校验门禁会强制拦截，禁止为"缩小/增大体积"改过滤器或绕过门禁。

【步骤 0：打包前门禁】
- 执行 curl https://api.lingbuilder.com/health，必须 HTTP 200 且响应 JSON 的 ok=true；失败则停止打包并报告网络/服务故障，不得继续。

【步骤 1：版本统一（若目标版本与当前不同）】
1. 五处 package.json 版本号同步升级：根 package.json、electron/package.json、packages/contracts/package.json、cloud/api/package.json、cloud/admin/package.json。
2. cloud/api/package.json 与 cloud/admin/package.json 中对 "@lingbuilder/contracts" 的精确版本依赖同步改为新版本，否则根目录 npm install 会因私有包 E404 失败。
3. 在仓库根执行 npm install 同步根 package-lock.json（electron 是根工作区成员，npm 会自动上溯到根操作）；electron/package-lock.json 是遗留独立 lock，npm 不会更新它，需手动把其中两处版本字段（约第 3、9 行）改成新版本。
4. 硬编码版本同步三处：
   - electron/src/services/aiBridge/mcpServer.ts 的 MCP server version 字段；
   - electron/electron/lcppSourcePackageService.ts 的 CURRENT_GENERATOR_VERSION；
   - electron/src/services/product/productInfo.ts 的 LINGBUILDER_RELEASE_NOTES 数组头部新增新版本发布说明（注意：electron/tests/helpCenterUi.test.tsx 断言发布说明首项 version 必须等于当前产品版本，不加会挂测试）。
5. 模块里的 minLingBuilderVersion: '0.6.0' 是兼容下限，不要改。
6. 版本改动后至少跑：node --import tsx --test tests/helpCenterUi.test.tsx tests/versionCheck.test.ts（在 electron/ 目录）。

【步骤 2：本地依赖自检与恢复（本机开发状态可能被清理，逐项确认）】
1. CEF3/FBro 环境 SDK 模块（发布源校验门禁必需，只留在本地、不进安装包）：
   - 检查 .lingbuilder/modules/lingbuilder.cef3.sdk/lingbuilder.module.json 与 .lingbuilder/modules/lingbuilder.fbro.sdk/lingbuilder.module.json 是否存在；
   - 缺失时从 electron/src/services/sdkDependencies/sdkDependencyCatalog.ts 读取官方归档的 downloadUrl、archiveBytes、sha256（该文件是唯一权威来源，不要凭记忆写地址），下载后先核对字节数与 SHA-256，再用 PowerShell Expand-Archive 解压到 .lingbuilder/modules/（zip 顶层目录本身就是模块目录结构）；
   - 恢复后先单独跑 cd electron && npm run verify:cef3-release && npm run verify:fbro-release 确认 ok:true。
2. electron/third_party/aria2/（精简发布内置的按需下载器，三件套缺一不可）：
   - aria2c.exe（官方 aria2 1.37.0 win-64bit build1：https://github.com/aria2/aria2/releases/download/release-1.37.0/aria2-1.37.0-win-64bit-build1.zip）、COPYING（随 zip）、NOTICE.md（≥200 字节，写明版本、来源地址、GPLv2 许可、修改情况）；
   - 门禁要求：aria2c.exe ≥1MB、COPYING ≥1KB、NOTICE.md ≥200B。
3. 7za（安装包校验依赖，本机通常未安装）：
   - 先 where.exe 7za.exe 检查；没有则下载 7-Zip 官方 x64 MSI（https://www.7-zip.org/a/ 下当前版本，如 7z2602-x64.msi），用 msiexec //a "<msi路径>" //qn TARGETDIR="<本地目录>" 管理员提取（只解压不安装系统），得到 7z.exe；
   - 打包时通过环境变量 LINGBUILDER_7ZA_PATH 指向该 7z.exe（校验脚本兼容 l -slt 语法）。

【步骤 3：执行打包】
在 electron/ 目录用一次完整命令跑通整链（Git Bash 环境变量前缀写法）：
  cd electron
  LINGBUILDER_CLOUD_RELEASE_MODE=online \
  LINGBUILDER_CLOUD_API_URL=https://api.lingbuilder.com \
  LINGBUILDER_7ZA_PATH="<7z.exe 绝对路径>" \
  npm run package:win
该链路依次执行：写入云端发布配置 → CEF3/FBro 源校验 → vite/esbuild/tsc 构建 → WebView2 引导器冻结 → electron-builder NSIS → afterPack 严格精简发布校验 → 两项安装包校验。任何一步失败按文末对照表处置后从头重跑，禁止带病放行。
耗时约 8-10 分钟，建议放后台执行并轮询日志。

【步骤 4：产物验证（全部通过才算完成）】
1. 文件存在：electron/release/LingBuilder-<目标版本>-x64.exe 与 .blockmap；体积应在 140MB 量级，若明显异常增大（如 300MB+）优先怀疑 SDK 泄漏。
2. 云端配置（两处都要验）：
   - electron/release/win-unpacked/resources/cloud-release.json；
   - 安装包内嵌载荷：用 7z 先 "e <安装包> '$PLUGINSDIR\app-64.7z'" 解出内嵌归档，再从中提取 resources/cloud-release.json。
   两处内容必须均为 {"schemaVersion":1,"cloudMode":"online","cloudApiOrigin":"https://api.lingbuilder.com"}。
3. 版本元数据：PowerShell (Get-Item electron/release/win-unpacked/LingBuilder.exe).VersionInfo 的 FileVersion/ProductVersion 等于目标版本。
4. 精简校验：electron/scripts/verify-on-demand-sdk-release.cjs 的 installer 模式会自动解出内嵌 app-*.7z 检查真实载荷（SDK 排除 + SDK 二进制夹带 + aria2 三件套存在），package:win 已含此步；如需复检可单独执行 verify:cef3-installer。
5. 更新记录：按 AGENTS.md 规则把本次打包（版本号、恢复的本地依赖、脚本修复等）追加写入根目录 更新记录/<当天日期>.md。

【行为约束】
- 正式联网打包只通过 LINGBUILDER_CLOUD_RELEASE_MODE=online 与 LINGBUILDER_CLOUD_API_URL 环境变量切换，不得修改源码或 electron-builder 配置来切换。
- 默认输出会覆盖 electron/release/win-unpacked 与同名安装包；不要改写历史已验证安装包（如旧版本发布目录）。若 win-unpacked 被其他进程锁定，仅通过 electron-builder 命令行指定新的输出目录，不要杀用户进程。
- 恢复到 .lingbuilder/ 的 SDK 模块、下载工具、临时解压物全部留在该目录（已 gitignore），不得提交、不得写入任何入库文件。
- 发现校验失败时先读完整错误与相关脚本源码定位根因，不得用跳过/注释门禁的方式强行出包。
- 完成后报告：产物路径与体积、云端配置验证结果、每项门禁结果、变更文件清单；代码改动保持未提交，由用户决定是否提交。
```

## 附：常见失败与处置对照（本次实操踩坑记录）

| 报错（关键句） | 根因 | 处置 |
| --- | --- | --- |
| `verify:cef3-release` 失败：`缺少 CEF3 SDK 模块清单` | 本机 `.lingbuilder/modules/` 被清理 | 按步骤 2.1 从 sdkDependencyCatalog.ts 的官方地址下载、校验、解压恢复；源校验通过标准：CEF3 536 个文件 / 470,908,837 字节，FBro 478 个文件 / 830,471,391 字节 |
| 根目录 `npm install` 报 404：`@lingbuilder/contracts@旧版本` | 升了包版本但 cloud/api、cloud/admin 的依赖声明没同步 | 同步两处 `@lingbuilder/contracts` 精确依赖后再 install |
| electron/package-lock.json 版本字段更新不动 | electron 是根工作区成员，npm install 自动上溯根目录 | 手动改该 lock 第 3、9 行版本字段 |
| afterPack：`发布目录缺少有效的 aria2c.exe` | `electron/third_party/aria2/` 三件套缺失 | 按步骤 2.2 恢复（含 ≥200 字节的 NOTICE.md，不能只放 exe） |
| 安装包校验：`未找到 7za.exe` | 本机无 7-Zip、electron-builder 缓存无 7za | 按步骤 2.3 MSI 管理员提取 + `LINGBUILDER_7ZA_PATH` |
| 安装包校验：`安装包缺少 aria2 运行时资源`，但 win-unpacked 里明明有 | 旧版校验脚本只扫 NSIS 外层清单；electron-builder 26 通过 nsis7z 把整个应用嵌成单个 `$PLUGINSDIR/app-64.7z`，且 NSIS 条目可能无 CRC 被共享解析器过滤 | `verify-on-demand-sdk-release.cjs` 已修复为解出内嵌归档检查真实载荷（0.6.1 打包时落地）；若回退到旧脚本或报此错，先确认该修复在位，不要绕过 |
| py7zr 解压 7-Zip extra 包报 BCJ2 不支持 | extra.7z 用 BCJ2 滤镜，py7zr 不支持 | 不用 extra.7z，改走 MSI 管理员提取 |

## 附：固定事实速查

- 打包命令入口：`electron/package.json` 的 `package:win`；必须在 `electron/` 目录运行。
- 联网模式环境变量：`LINGBUILDER_CLOUD_RELEASE_MODE=online`、`LINGBUILDER_CLOUD_API_URL=https://api.lingbuilder.com`；`installer/cloud-release.json` 由 `scripts/prepare-cloud-release-config.cjs` 在打包链路内生成（该文件已 gitignore，不入库）。
- 7za 相关：`LINGBUILDER_7ZA_PATH` 指向 7z.exe（可不叫 7za.exe，脚本只要求文件存在）；查找顺序为环境变量 → PATH → electron-builder 缓存。
- 安装包结构：NSIS 外壳只含 13 个左右文件（`$PLUGINSDIR/app-64.7z`、WebView2 引导器、卸载器等），应用全部内容（含 `resources/cloud-release.json`、`resources/third_party/aria2/`、`resources/docs/`）在内嵌 `app-64.7z` 里。
- 0.6.1 基线体积：安装包 147,948,217 字节（约 141MB）；`app-64.7z` 145,427,738 字节、解压后约 659MB / 299 个文件。
- SDK 归档权威来源：`electron/src/services/sdkDependencies/sdkDependencyCatalog.ts`（下载地址、字节数、SHA-256、关键文件清单）；不要在本文档硬编码，以该文件为准。
- 权威规则来源：打包与生产 API 相关约束见根目录 `AGENTS.md`「系统 AI 云端与计费规则」「生产环境 API 信息」章节；本文档与其冲突时以 `AGENTS.md` 为准。
