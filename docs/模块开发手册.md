## JSON 数据模块参考

`lingbuilder.data.json@2.0.0` 是内置、零外部 DLL 的结构化数据模块参考实现。模块必须由单一 JSON 命令目录同时生成 `contributes.commands`、`bindings.commands`、代码片段、文档、补全、诊断和确定性 C++ 运行时；不得只增加 Monaco 补全或只在 renderer 中实现 JSON 行为。公开类型 `JSON值` 是 C++ `long long` 的受管句柄，不是裸指针，调用方长期持有时必须使用 `JSON_释放`。对象/数组写入会深度复制传入值，因此不会把临时句柄、STL 容器或原生地址跨模块泄漏。

运行时覆盖 RFC 8259、RFC 6901 JSON Pointer、RFC 6902 JSON Patch、RFC 7396 JSON Merge Patch 和文档列出的 JSON Schema 核心关键字。解析、Patch 与 Merge Patch 必须具备原子失败语义，输入大小、嵌套深度、Schema 深度和错误文本都应有明确的有界策略。JSON5/JSONC、BSON、MessagePack、CBOR、远程 `$ref` 和网络 schema 获取不是 JSON 模块能力，若后续封装必须以独立模块、独立 MIME/二进制类型和独立版本契约实现，禁止把非标准文本静默送入 `JSON_解析`。完整用户文档必须登记在 `electron/docs/modules/json/README.md`，并随安装资源和导出工程保持可读取。

## FBro 指纹浏览器模块参考

豆包视频下载器浏览器插件不是 LingBuilder 模块，不能写入 `.lingbuilder/modules`、项目模块引用或模块包。它是浏览器管理器项目自有的 Manifest V3 资源，必须放在 `assets/<项目ID>/doubao-downloader/`，由项目资源复制链路随源码包、预览和构建输出。运行时从真实 exe 目录查找 `assets` 下的项目资源，并在 RequestContext 加载扩展后才创建浏览器；Cookie、缓存和插件私有存储仍不得进入 `.lcpppkg`。

扩展加载事件复用 VIP lifecycle 事件码时，payload 必须含 `phase: "extension"` 才能更新“插件已加载/失败”状态；`contextInitialized`、普通 browser created 等生命周期必须作为 `VipLifecycle` 转发，不能误改插件状态。扩展加载失败不得销毁已成功创建的浏览器，列表和状态区只显示脱敏中文诊断。

独立 FBro Host 不得通过命令行 `load-extension` 伪造扩展状态：命令行仅可启用 Chrome Runtime，扩展必须在每个独立 RequestContext 创建完成后、创建浏览器前调用官方 VIP `LoadExtension`，保持与 FBro C# 独立浏览器示例相同的顺序。扩展 ID、部署路径和 `GetExtensionPath` 只能表示已注册；若界面要报告“已生效”，必须在当前页面执行受控 DOM 探针并将“页面不适用”“正在验证”“未在当前页面生效”与“已生效”分开显示。FBro Alloy 的内嵌浏览器不具备 Chromium 原生 `chrome://extensions/` UI，项目应在当前实例提供只读诊断页，保留逻辑地址并显示清单、注册和页面验证状态。
扩展注册事件到达而当前 URL 已匹配时，运行时最多刷新一次首个页面，随后才开始探针重试；不得使用定时无限 reload 代替真实的 content script 注入。

FBro 2.4 采用核心模块加能力子模块：`lingbuilder.fbro.events`、`session`、`transfer`、`automation`、`objects`、`network`、`vip` 均依赖 `lingbuilder.fbro.browser >= 2.1.0`。安装/启用子模块时必须先展示递归依赖计划并原子写入项目引用；核心仍被其它已启用模块依赖时禁止直接禁用，经用户确认后才允许级联禁用。manifest 命令可用 `aliases` 声明官方英文名；中文主名、官方英文名和旧事件别名必须落到同一个确定性 binding 与稳定事件 ID，不能复制多套运行时。

C ABI v3 的事件回调传递 `LB_FBRO_EVENT_PACKET_V3`、`LB_FBRO_EVENT_RESPONSE_V3`、整数实例/受管对象句柄和受管延续句柄，同时保留 v1/v2 兼容导出。复杂事件数据与结构化响应使用 UTF-16 JSON；异步结果使用任务 ID；二进制使用受管缓冲句柄，并提供大小、十六进制、保存和释放闭环。事件原生对象必须先登记到类型化对象注册表，再把整数句柄写入事件包，禁止跨 DLL 暴露对象地址。动态处理器参数必须声明为 `handler`，示例为 `FBro_绑定事件(浏览器1, "BeforePopup", &处理器名)`；浏览器参数必须声明为 `controlRef` 并使用裸控件名，处理器也不得写成普通字符串。普通即时决策默认 2 秒；官方 callback 延迟决策通过完成/取消延续 API 返回，按安全、查询、文件类使用 5/30/120 秒超时和目录默认动作。

官方 API 覆盖基线由 `electron/scripts/generate-fbro-api-coverage.cjs` 从 C++ 公共头生成，`.v` 二进制工程只用于火山 IDE 人工抽样。运行 `cd electron && npm run module:fbro-coverage:check` 会校验 77 个头文件、1079 个签名和 158 个事件/回调签名的稳定 ID、哈希、中文名、默认动作、限流和实现状态；分配器、重复适配器等内部项也必须写明理由，不能从清单消失。`planned` 只表示安全封装目标已分类，不表示已有可调用 wrapper。

面向用户的完整 FBro 事件与接口参考位于模块详情可直接打开的 `electron/docs/modules/fbro/README.md`。该文档由 `electron/scripts/generate-cef3-fbro-event-docs.ts` 从 C ABI v3 事件目录和实际模块 manifest 生成，当前覆盖 174 个类方法事件槽位、89 项公开可绑定事件、85 项 Bridge 托管/内部/不适用分类项和 461 条用户接口；9 条 `visibility: internal` 命令不会进入用户目录。修改 FBro 事件或命令清单后必须运行 `cd electron && npm run module:fbro-docs`，并用 `npm run module:fbro-docs:check` 阻止文档漂移。

`lingbuilder.fbro.vip` 的官方 VIP 目录为 188/188 implemented、planned=0。188 项官方能力逐项生成 contribution 和 binding：179 条单项安全命令、6 条 Bridge 自动管理能力、3 条凭据中心/安全入口替代能力；另保留 10 条“批量与通用高级入口”，模块清单共 198 条。单项命令固定官方动作，统一采用 `命令名(控件名, 参数JSON)`，不再要求调用者填写“命令名称”字符串。6 条自动管理和 3 条安全替代命令使用 `visibility: internal`，模块详情可展示其边界，但 Monaco 普通补全不得暴露。资源数据只能引用 `FBro缓冲_*` 产生的受管缓冲句柄；Bridge 会复制并保活二进制，不允许 `.lcpp` 传 `void*`。扩展目录、CRX 与资源文件必须位于生成程序目录内并经过规范化路径校验。DevTools 观察器与 VIP 生命周期事件必须先复制为 UTF-16 JSON，再进入统一事件协议。启动代理只能在首次 `LB_FBro_Initialize` 前配置，密码只保存在 Bridge 内存或受控子进程环境中，不得写入 manifest、模块包或日志。

覆盖项还必须包含稳定 wrapperSymbol、逐重载 overloadId、参数/返回 codec、线程、执行方式和所有权。术语无法确定时应标记 `needsReview` 并进入人工适配表，禁止使用 `功能XXXX` 占位名或根据复杂指针/回调猜测 ABI。当前核心模块已真实接入 86 条浏览器、独立进程和普通 Win32 浏览器管理器能力；objects 已扩展到 132 条中文命令，automation 现有 25 条命令，session 现有 10 条命令，transfer 现有 5 条命令；vip 官方目录为 188/188、planned=0。事件目录必须按“所属类 + 方法名 + 完整签名”登记，当前固定为 174 个类方法槽位和 158 个唯一签名、零 `planned/needsReview`；每项必须具有真实 override 或明确的 `managed/internal/notApplicable` 理由、字段/响应 schema 和测试。普通 Win32 与 New_Emoji 使用同一 C ABI v3 和事件目录。全 FBro 普通 API 目录仍为 397 项已实现、678 个非事件高级签名待实现、3 项内部不适用和 1 项高级替代不适用，不得把事件完成误写成 1079 项全部完成。

`lingbuilder.fbro.browser` 是外部原生浏览器采用“设计器贡献 + 预编译 C ABI 桥接 + 按需 SDK 环境”的参考实现。项目启用后，`FBro指纹浏览器 (FBroBrowser)` 自动出现在工具箱“媒体”分类，可拖入窗口、调整大小、编辑属性和绑定创建完成、加载完成、地址改变、即将打开新窗口、标题改变、关闭完成及错误事件。`processMode` 可取 `in-process`、`independent-embedded` 或 `independent-window`；两种独立模式必须为每个控件启动独立 Host 进程、profile、CDP 端口和随机回环 WebSocket 会话，并以一次性 256 位 Token 鉴权。每个内嵌控件实例仍必须拥有独立宿主 `HWND`，不能共享其它设计器控件的主句柄。“即将打开新窗口”由桥接层同步取消 popup，再把目标 URL 投递给 LCPP；单窗口项目可用 `FBro_导航(控件名, FBro_取最近事件(控件名))` 在当前实例打开，需要完整谷歌原生 UI 时可用 `FBro_打开谷歌原生UI浏览器(控件名, 地址)`。

`FBro_打开谷歌原生UI浏览器` 的 C ABI 为 `LB_FBro_CreateChromeUi(所属浏览器句柄, URL, 回调, 用户数据)`，故意不接收宿主 `HWND`。桥接层设置空 `parent_window/window`、`WS_EX_APPWINDOW`、`WS_OVERLAPPEDWINDOW` 与 `CEF_RUNTIME_STYLE_CHROME`，由 FBro/CEF 自行创建带 Chrome 地址栏的桌面顶层窗口；“没有窗口句柄”准确含义是调用者不提供 LingBuilder 窗口句柄，创建完成后 Windows 仍会为 Chrome 顶层窗口分配系统 HWND。原生 UI 浏览器继承所属内嵌实例的请求上下文、User-Agent 和指纹标志，句柄单独登记，关闭所属窗口时必须一并关闭。

FBro 尺寸回调运行在 Win32 宿主消息线程，必须使用非阻塞方式访问桥接状态，不得等待正在创建浏览器的 CEF UI 线程。缩放时只能调整宿主的直接子窗口，不得用 `EnumChildWindows` 递归改动 Chromium 内部窗口层级。

该模块只声明 `windows-msvc-x64`。`in-process` 与 `lingbuilder.cef3.browser` 互斥，因为二者会在同一应用进程加载 CEF 135 与 CEF 150；项目全部 FBro 控件使用独立模式时允许共存，原生依赖必须用 `HostOnly` 把 FBro Bridge、CEF 135 和资源放入 `fbro-host/`，主 exe 目录只保留 CEF3 的 CEF 150。用户代码只包含 `LingBuilderFbroBridge.h` 并链接导入库；C ABI 只允许整数句柄、POD 和调用者提供的 UTF-16 缓冲区，禁止跨 DLL 传递或释放 STL、`CefRefPtr`、FBro 对象或桥接层裸指针。回调必须先复制数据，再用窗口消息投递到所属 UI 线程。关闭时先关闭所有浏览器，再以 `FBroShutdown(FALSE)` 发起全局关闭，并等待 `OnBeforeClose` 后释放桥接状态；独立 Host 同时由 Job Object 兜底回收，不要直接销毁宿主或强制终止进程。

独立进程协议只作为核心浏览器控制面：当前覆盖创建、导航、前进后退、刷新、执行 JS、缩放、静音、代理、指纹、显隐、尺寸、截图、真实 Cookie 遍历/结构化写入、缓存清理、关闭、PID/CDP/状态查询和受限重启。Frame、其它受管对象、通用任务与 VIP 单项能力尚未全部远程化，模块作者不得仅增加 contribution 就宣称独立模式可用；扩展时必须同步版本化消息 schema、主控/Host 双端处理、超时与旧代次拒绝、普通 Win32/new_emoji 生成、F5/VS 导出以及真实双进程测试。

开发源 SDK 可由 `npm run module:fbro-sdk -- --install` 从官方目录生成到 `.lingbuilder/modules/lingbuilder.fbro.sdk/sdk/135.0.21/x64/`。正式安装版首次使用时从固定版本资源下载到 `%APPDATA%/LingBuilder/sdk-cache/modules/lingbuilder.fbro.sdk/sdk`；F5、运行和 VS post-build再按 `runtime-manifest.json` 的大小与 SHA-256 增量物化 78 项文件并保留目录结构。每位 IDE 用户在“设置 → 浏览器凭据”中自行保存 VIP Key，主进程用 `safeStorage` 加密并只向受控运行进程临时注入；`LINGBUILDER_FBRO_VIP_KEY` 保留给无人值守或脱离 IDE 的导出工程。禁止写入 manifest、设计器模型、源码、日志、AI 上下文、同步包或模块包。

FBro 的 SDK/桥接/运行时诊断是生成前硬门禁：缺失或哈希失败时必须停止编译和运行，不能继续生成仅显示白色占位区的程序。F5 中间工程的 VS post-build 从已校验的项目 `bin` 读取运行时，避免重复保存 390 MB；对外 `generated/cpp` 工程则必须自带 `modules/lingbuilder.fbro.browser/runtime/x64`、清单和 `materialize-fbro-runtime.ps1`，确保脱离 IDE 后仍可增量构建。

## 设计器运行时映射

`designerControls[].runtime` 可声明 `createParameters`、`propertySetters`、`propertyCommands` 和 `eventBindings`。Setter 参数使用 `propertyKey` / `lengthOf` 读取属性，也可用 `literal` 提供原生 API 必需的固定参数；共享原生回调使用 `eventCode` 区分鼠标或焦点事件。事件项及对应 `eventBindings` 可用 `aliases: string[]` 声明旧设计器模型或预览控件的同义事件键，生成器先匹配规范 `eventName` 再按别名兼容，新的事件绑定仍应保存规范名。模块只应给真正能生成或调用的属性、事件设置 `runtimeCommand`，不得仅为解除属性面板过滤而填写不存在的命令。

可选 Setter 如果会清空创建期数据、重置选择或切换数据源模式，生成器必须识别它的未启用值，不能因为 manifest 中存在映射就无条件调用。new_emoji ListBox 是参考：空 `listBoxItemsEx` 不覆盖简单项目，空 `selectedKeys` 不覆盖 `selectedIndex`，`virtualItemCount <= 0` 不调用会清空普通项目的虚拟数量 Setter。

new_emoji 是参考实现：生成脚本从上游 93 控件目录、`exports.h` 与 `.def` 自动构建 1618 个底层导出、718 个属性和 918 个事件映射；表格复合配置由生成器逐条解析，按钮状态色及通用鼠标/焦点/值变化事件由 DLL 回调实现。上游提交目录暂时落后于源码时，只能在系统临时目录调用上游 Catalog Exporter 重建，不得修改上游仓库或手工补写导出清单。

## 设计器控件高级贡献

`contributes.designerControls[]` 除 `type`、`label`、`defaultProps` 和 `events` 外，可选声明：

- `category`、`icon`：工具箱分类与图标键。
- `isContainer`、`isVisual`：容器或非可视资源语义。
- `nativeAdapter`、`requiredLibraries`：受控原生生成适配器和系统库依赖。

内置视频播放器是这一闭环的参考实现：`VideoPlayer` 声明 `nativeAdapter: media-foundation-video` 和 `mfplat.lib`、`mfplay.lib`、`mfuuid.lib`，并把设置文件、播放、暂停、停止、音量和状态命令同时注册到 `contributes.commands` / `bindings.commands`。第三方模块不得只贡献同名工具箱卡片；必须提供受控原生适配器或模块自身可审计的 C++ binding 实现。
- `properties[]`：专属属性 schema，支持 `text`、`number`、`boolean`、`enum`、`color`、`file`、`stringList`、`columns`、`treeNodes`、`tabs`、`date`、`controlRef`。

事件 `handlerPattern` 必须包含 `{controlName}`。属性 key 和事件 name 在单个控件中必须唯一；文件属性默认值必须是模块内安全相对路径。外部模块只能引用 LingBuilder 已注册的受控 `nativeAdapter`，不能通过 manifest 注入任意 C++ 字符串。

内置基础/高级 Win32 控件以注册表中的事件 schema 为准：普通可视 HWND 控件统一公开 `MouseDown`、`MouseEnter`、`MouseLeave`、`GotFocus`、`LostFocus`，标签、图片框和动态图像还公开 `Click`；颜色选择器与视频播放器由专用交互链管理，只保留经验证的专用事件。模块作者不得只在 manifest 中添加运行时不会分发的事件。

非可视资源的 `properties[]` 必须直接描述实际持久化字段，不能用近义键另建一套模型。内置 ToolTip 使用 `text/targetControlId/initialDelay`，FileDialog 使用 `ownerWindowId/triggerControlId/dropTargetId/title/filter/multiple/allowDrop`，ContextMenu 使用 `ownerWindowId/targetControlId/items`，PopupMenu 使用 `ownerWindowId/items`，PropertySheet 使用 `title/pages`。菜单选择处理器按菜单项保存；PropertySheet 的 `Applied` 与普通控件事件一样通过事件卡片创建和导航。

本文档面向希望把 C++ 能力封装到 LingBuilder 的模块作者。当前标准为 `schemaVersion: 2`，旧版 v1 `.lbmod` 不再作为兼容目标；旧模块应使用模块迁移工具重新打包。

### 公开记录和数组

`contributes.types[]` 支持三类公开类型：

- `opaque`：旧模块兼容类型；省略 `kind` 时默认使用，可用 `cppType` 映射句柄或原生不透明类型。
- `record`：LingCpp 公开记录，必须声明 `fields[]`。字段填写 `name`、`type`，可选 `description`、`initialValue` 和 `isArray`。
- `array`：命名数组，必须声明 `elementType`；例如 `请求结果列表` 在生成工程中等价于 `请求结果[]`。

结构化字段只允许 LingCpp 安全基础类型或本模块公开的其它 `record`/`array` 类型。数组、字节集和嵌套结构字段只能默认空初始化；结构化类型禁止循环嵌套，也禁止填写 `cppType` 绕过字段契约。启用模块后，这些类型会进入专业 Monaco、新手类型补全、字段悬停和赋值诊断，并可被项目 `项目数据类型.lcpp` 安全嵌套。普通 Win32 与 new_emoji 生成器使用同一类型结果，记录生成 C++ `struct`，数组映射为 `std::vector<T>`。

这里公开的是 LingCpp 值语义，不等于允许把 C++ 对象直接穿过 DLL。预编译 DLL 不得直接接收或返回 `std::vector<T>`、`std::wstring` 或未固定布局的 C++ `struct`。复杂数据跨原生边界时应提供稳定 C ABI：POD 字段、数据指针加数量、调用方分配缓冲区、任务 ID 或受管句柄；`bindings.commands` 仍负责 ABI，不能用 `cppType` 代替适配层。

由 LingBuilder 直接注入到生成工程的内置/源码运行时，可以在 `bindings.commands[].parameters[].type` 或 `returnType` 中引用本模块公开的 `record/array` 名称，生成器会使用对应 `struct/std::vector<T>`。清单同时携带原生 DLL runtime 时，校验器会拒绝这种结构化参数或返回值，模块作者必须改用稳定 C ABI。内置 `lingbuilder.system.disk@1.1.0` 的 `磁盘_枚举逻辑驱动器() -> 磁盘卷信息列表` 是同工程值语义参考实现。

### 公开常量

`contributes.constants[]` 让模块像易语言的模块常量表一样对外提供命名常量。每项声明：

```json
{
  "name": "键盘1",
  "type": "整数型",
  "value": 49,
  "description": "数字键 1 的虚拟键码，配合 键盘_按下 等命令使用。",
  "level": "basic"
}
```

- `name`：中文、字母、数字、下划线组成，不能以数字开头，不得带 `#` 前缀；模块内不得重名。
- `type`：只允许 `整数型`、`长整数型`、`字节型`、`小数型`、`双精度小数型`、`文本型`、`逻辑型`；字节集等复合类型暂不开放。
- `value`：纯字面量。数值类型填 JSON number（整数类型必须为整数），`文本型` 填 string，`逻辑型` 填 `true`/`false`。不支持表达式。
- `description`：非空中文说明，进入补全与悬停。
- `level`：可选，`basic`（默认）或 `advanced`；`advanced` 常量只在用户显式开启高级 API 后进入补全。

用户源码中引用常量的规范形态是 `#常量名`（裸标识符，不带引号），例如 `调试输出("版本：" + #版本号)`、`键盘_按下(#键盘1)`。`#` 前缀强制按常量解析：常量不存在、或给常量赋值，都会得到阻断级中文诊断；已安装但未启用模块提供该常量时，诊断会指明启用路径。旧源码中的裸名引用继续兼容（仅项目常量），但新示例、文档和 AI 生成必须用 `#` 形态。

生成期把启用模块常量与项目常量一起物化为 C++ 编译期常量（数值型 `inline constexpr`，文本型 `inline const std::wstring`），导出的 Visual Studio 工程可直接阅读和迁移。同名规则：项目常量遮蔽模块常量（只物化项目一份，模块份不生成）；两个启用模块公开同名常量属于硬冲突，构建前中文阻断，模块作者应为常量名加模块前缀规避。`@` 内嵌 C++ 行、字符串、注释和多行文本块内的 `#` 不视为常量引用。

常量与命令一样必须写入模块中文文档（`contributes.docs[]`）：说明每个常量的取值含义、配合哪些命令使用；`lingbuilder.module.info` 会随清单返回 `constants[]` 供外部 AI 查询。

### 界面示例与配方（`contributes.examples[]`）

命令与控件较多的模块，除了逐条命令说明，还应登记**可直接整文件复制的界面示例**：

```json
"examples": [
  { "title": "表格增删改与双击编辑", "path": "docs/examples/表格增删改.lcpp", "description": "列定义、行增删改与单元格编辑回读的完整单窗口示例。" }
]
```

- `path` 指向包内真实存在的非空文本文件（`.lcpp` 或 `.md`），随 `.lbmod` 分发，模块详情页可直接打开；清单校验会拒绝缺失或空文件。
- `title` 是外部 AI 的检索入口：`lingbuilder.module.info` 把它们汇总为 `uiExamples` 索引，传 `example`（标题、路径或序号）即返回正文，AI 不必再去翻完整命令表。
- 示例必须是**惯用写法**而不是命令清单的机械排列：单窗口、控制在百行以内、参数用真实可运行值、并在注释里写清适用场景与红线。逐条覆盖全量 binding 命令的穷举演示项目由 `npm run module:demos -w lingbuilder-electron` 生成到 `examples/module-demos/`，属于另一套语料，不要塞进 `contributes.examples`。
- 尚未随包分发示例的模块，可先放工作区语料 `examples/ui-recipes/<模块 ID>/recipes.json`（约定见 `examples/ui-recipes/README.md`），`module.info` 会把两个来源合并成同一份 `uiExamples`；正式对外发布的模块应改走 `contributes.examples[]`，否则打包版工作区取不到。

### 泛型数组参数

`bindings.commands[].parameters[].type` 另有两个只服务于同工程值语义运行时的类型，用于编写对元素类型透明的数组命令：

- `array`：任意元素类型的 LingCpp 数组左值。生成器按 `std::vector<T>&` 原样传递，不做任何 ABI 转换，因此运行时函数必须写成 `template <typename T>` 模板。
- `arrayElement`：与同一条命令中 `array` 参数元素类型一致的值。作为 `returnType` 时表示命令返回该元素类型，语言服务会回到本次调用的数组实参上求解，而不是使用固定标签。

语言服务对声明了 `array` 参数的命令统一执行：实参个数必须与 binding 一致；数组实参必须是数组变量名或记录字段路径（命令会就地读写调用方的数组，命令结果和下标都不是可写数组）；`arrayElement` 实参必须与数组元素类型兼容。

`array` 不能作为 `returnType`，这两个类型也不能出现在携带原生 DLL runtime 的清单上。内置 `lingbuilder.std.array@1.0.0` 是参考实现：`数组_排序`、`数组_查找` 用 `std::void_t` 探测元素类型是否支持比较，对不支持的元素类型返回失败值而不是编译失败。

`contributes.commands` 负责中文补全、提示和文档；`bindings.commands` 负责中文命令到 C++ 运行时函数的确定性生成。模块命令没有 binding 时，生成器会输出中文诊断注释，不再盲目按命令名生成 C++。

有返回值的命令应同时填写 `returnType` 和 `returnDescription`。前者声明中文类型，后者解释数值语义、成功/失败约定以及它是否为句柄、编号、状态码或数量。每个 `bindings.commands[].parameters[]` 也应填写独立 `description`；命令提示面板会按位置合并 binding 的参数类型与说明，不能用整条命令简介代替参数说明。

如果命令参数用于传入当前类中的事件或方法，binding 参数应声明 `type: "handler"`，`.lcpp` 使用 `&处理器名` 引用。新模块还应声明 `handlerSignature: { "parameterTypes": [...], "returnType": "..." }`；空参数处理器示例为 `{ "parameterTypes": [], "returnType": "空" }`。语言服务会校验 `&` 引用语法、目标是否存在、参数和返回类型，字符串处理器名只用于未迁移模块兼容；新模块不应再用 `wideString` 伪装回调类型，也不应省略可确定的签名契约。

系统对话框一类有后续状态的命令也必须显式贡献读取接口。例如内置 Win32 高级模块同时贡献 `打开文件` 与 `系统对话框_状态`，贡献 `查找文本`/`替换文本` 与对应动作、查找内容、替换内容读取命令；不能只弹出窗口而丢失用户取消、错误或回调结果。

同一设计器控件可以同时承担可视入口和不可视逻辑组件，但 manifest、设计器模型与原生生成器必须明确保持实例状态。内置 `ColorPicker` 在可视时显示色块并自行打开 LingBuilder 暗色原生颜色弹窗，设为不可视后仍可通过 `颜色选择器_打开(控件名)` 调用；生成器不能按普通隐藏控件规则把该实例裁掉。颜色弹窗由导出的 C++ 自绘 HSV 色谱、色相条、HEX/RGB 和预设色，不依赖旧式 `ChooseColorW`。颜色读写命令与打开、改变、确认、取消、关闭事件必须同时进入 `contributes.commands`、`bindings.commands` 和确定性 C++ runtime。

控件运行时 API 同样必须同时声明补全和 binding。内置基础模块的 `控件_设置文本`、`控件_设置位置大小` 等通用命令以设计器中文控件名定位真实 HWND；高级模块的 ListView、TreeView、Tab 集合命令以及 `上传_打开文件选择/开始/清空文件/取文件数量/取文件` 复用同一定位规则。模块不得依赖设计器数组序号或私有原生 ID。

设计器属性不自动等同于运行时命令。只有具备确定性 C++ 实现、且 `contributes.commands` 与 `bindings.commands` 成对声明的属性操作才能进入 `.lcpp` 控件命令补全。例如 TabControl 的 `选项卡_设置隐藏表头/取隐藏表头` 会在运行时同步重排标签页承载区；列集合、节点集合、创建样式等仅设计期结构属性不得只添加补全文案而缺少运行时实现。

## 3. C++ 库迁移流程

推荐流程：

1. 准备 C++ 库的头文件、源码、`.lib`、`.dll`、授权文件和说明文档。
2. 为普通用户编写中文桥接函数，避免直接暴露复杂指针、编码和回调参数。
3. 编写迁移配置 JSON，列出 headers、sources、libs、runtimeFiles 和 commands。
4. 运行：

```bash
lingbuilder module migrate-cpp --config migrate.json --out .lingbuilder/module-build/com.example.native
lingbuilder module validate .lingbuilder/module-build/com.example.native
lingbuilder module pack .lingbuilder/module-build/com.example.native --out .lingbuilder/module-packages/native.lbmod
lingbuilder module validate .lingbuilder/module-packages/native.lbmod
lingbuilder module inspect .lingbuilder/module-packages/native.lbmod
```

`module validate` 和 `module inspect` 同时接受模块目录、manifest 文件或 `.lbmod` 包；检查 `.lbmod` 时会在系统临时目录安全解包并清理，不会安装或启用模块。

当前真实构建闭环支持 Windows/MSVC 的 Win32 和 x64；`targets` 仍预留 CMake、Linux、macOS 字段，未支持的平台应给出中文诊断，不应静默失败。

当前 IDE/F5 依据工作区构建架构精确选择 `windows-msvc-win32` 或 `windows-msvc-x64`，不得回退到 `targets[0]` 或另一架构。模块未提供当前 target 时会跳过原生依赖并返回明确中文诊断，避免将不兼容库写入 Visual Studio 工程。

如果模块同时提供 Win32 与 x64 target，LingBuilder 生成到 `main.cpp` 的 MSVC 自动链接指令会用 `_WIN64` 条件分支选择各自 `libs`；因此两个 target 必须分别列出真实架构对应的库路径，不能让 x64 target 复用 Win32 导入库。生成的 `.vcxproj` 与依赖复制服务也会按当前平台选择同一 target。

## 4. 桥接代码规范

- 中文命令应优先绑定到稳定的桥接函数，而不是直接绑定到底层第三方 API。
- 字符串默认使用 `wideString`，桥接层内部再转换为 UTF-8 或其它编码。
- 如果 DLL 会在函数返回后继续读取字符串，桥接层必须持久保存缓冲区。
- `.lib` 模块通常要求 MSVC；如果只检测到 g++/clang++，应提示安装 Visual Studio Build Tools。
- 所有模块路径必须是包内安全相对路径，不允许绝对路径、空段或 `..`。
- `contributes.commands[].insertText` 应根据命令签名参数生成并和 `bindings.commands[].parameters` 数量一致：零参数写成 `命令()`，多参数按顺序使用 `$1`、`$2` … `$N`。

### 4.1 窗口事件上下文

内置窗口事件签名以 `windowEventRegistry.ts` 为唯一契约。`KeyDown` / `KeyUp` 依次传入 `整数型 键码` 和 Ctrl、Shift、Alt 三个 `逻辑型` 状态；`TextInput` 传入 `文本型 字符`；`DpiChanged` 传入 `整数型 新DPI`；`FileDropped` 传入 `文本型[] 文件集合`。其它窗口事件当前保持无参数。模块或 AI 不得自行增加、删除、改序或改写这些事件参数。

旧项目中的无参数处理器继续兼容，并可通过 `窗口_取消关闭`、`窗口_取事件宽度/高度`、`窗口_取事件键码/字符`、`窗口_取事件DPI`、`窗口_取拖入文件数量/窗口_取拖入文件` 等基础命令读取当前窗口保存的事件上下文。这些命令的 `contributes.commands` 与 `bindings.commands` 必须成对存在。返回文本来自窗口运行时持有的稳定快照，调用方只能在当前窗口生命周期内读取，不能把底层指针交给异步 DLL 长期保存。

同一基础模块还全局提供零参数初级命令 `取鼠标水平位置()` 和 `取鼠标垂直位置()`，两者的 binding 均返回 `int`，运行时使用 `GetCursorPos` 读取相对屏幕左边、顶边的像素坐标。这类内建全局命令也必须保持补全、binding 与 C++ 运行时三者同步；不得只添加文案或把屏幕坐标误作窗口客户区坐标。

基础模块的 `格式化文本(格式模板, 参数...)` 是当前内置的可变参数命令：第一个 binding 参数为 `wideString`，后续值按 `raw` 传给受控 C++ 模板重载，并沿用 `到文本` 对文本、整数、长整数、小数和逻辑值的转换规则。格式串只把 `{}` 作为顺序占位符，`{{` / `}}` 输出字面量花括号；参数不足保留 `{}`，多余参数忽略。第三方模块若设计类似可变参数命令，必须在 contribution 的签名和说明中明确可变参数语义，并提供真实可编译的桥接模板；不得把格式串交给不受控的 `printf`，也不得让补全声明与运行时接受的参数范围互相矛盾。

基础模块的 `调试输出(参数1, 参数2, ...)` 使用末尾 `lingValue` 且 `variadic: true` 的 binding，生成时保留文本、整数、小数和逻辑表达式的真实类型，由受控 C++ 模板逐项输出。不得把它声明为 `wideString` 后再强制包装第一个变量，否则整数键码、DPI 等强类型事件参数会生成不可编译的 C++。

## 5. 发布与市场索引

离线发布优先使用 `.lbmod` 和本地索引：

```bash
lingbuilder module market index --packages .lingbuilder/module-packages --out .lingbuilder/module-market.json
```

市场索引保存模块列表、版本、包路径、下载地址和哈希。第三方公开市场仍按离线索引发布；LingBuilder 官方收费模块另走受保护云端制品服务，不把价格写入 manifest，也不允许匿名下载。

官方收费模块由管理员在后台先建立 `moduleId` 商品，再上传 `.lbmod`。云端会校验安全 ZIP 路径、`schemaVersion: 2`、manifest 模块 ID 和版本，计算 SHA-256，并使用稳定 Ed25519 Permit 密钥签名制品元数据。IDE 只允许已登录且有权益的账号下载，依次校验签名密钥标识、元数据签名、文件大小和 SHA-256，然后复用安装预览确认和升级快照。官方收费模块不得随公开 IDE 安装包或默认工作区分发。

### 版本升级与覆盖安装

模块是**工作区级**安装（`.lingbuilder/modules/<moduleId>/`），项目 `project-modules.json` 只记录模块 ID 和启用时点的版本号（`pinnedVersions` 为元数据记录，构建时不做版本强校验），不复制模块文件。因此模块作者发布新版本时：

- 提高 manifest `version`、重新打包 `.lbmod` 后，使用者只需**重新安装一次**，全工作区所有引用该模块的项目在下次 F5 构建或导出时自动物化新版本头文件、库和 DLL，无需逐项目重新配置。
- 覆盖安装前 IDE 会把旧版本归档为模块历史快照，随后整目录替换，不会新旧文件混用。
- 调整中文命令签名、参数类型或语义属于**破坏性变更**：已生成 C++ 会随重新构建刷新，但用户已写的 `.lcpp` 源码不会自动改写，必须在发布说明中给出迁移指引；不兼容时优先升 major 版本号。
- 依赖其他模块时用 `dependencies[].minimumVersion` 声明下限，IDE 在安装前按已安装版本校验；`pinnedVersions` 只作展示与排查用途，不要依赖它做行为分支。

### 开发源链接（免重装调试，推荐日常使用）

反复「打包 → 预览 → 安装」只适合发布，不适合开发调试。LingBuilder 提供 **开发源链接**：把模块源码工程目录（推荐 `.lingbuilder/module-build/<id>`）链接进工作区，链接后该模块的补全、诊断和 F5 构建物化都**直接消费源目录**，改完清单、重编 DLL 后即时生效，不再需要重新打包安装。

- 入口：模块检查器 → 本地模块区底部「链接开发源」，填入工作区相对路径（如 `.lingbuilder/module-build/my.module`）。链接的模块在列表中标注「开发源 · 实时生效」，其 `installPath` 指向源目录而非 `.lingbuilder/modules`。
- 边界：开发源路径必须在当前工作区内，且不能指向 `.lingbuilder/modules`；内置模块与项目资源不能链接；同 ID 模块已链接开发源时，普通 `.lbmod` 安装会被拒绝（需先取消链接），避免安装目录与源目录双份混淆。
- 取消链接或「卸载」链接模块**只移除登记，绝不删除源目录文件**。
- 链接状态持久化在工作区级 `.lingbuilder/module-links.json`，随工作区迁移，不进项目 `project-modules.json`。
- 分发仍走 `.lbmod`：开发源链接只在作者本机生效，交付给用户时用「版本升级与覆盖安装」流程打包安装。

## 6. new_emoji v2 参考

`new_emoji` 模块 ID 为 `lingbuilder.new_emoji.ui`，通过以下命令重新生成：

```bash
cd electron
npm run module:new-emoji -- --install
```

v2 `new_emoji` 必须包含 Win32/x64 target、`NE_` 中文桥接命令、底层高级 API 文档、桥接源码和示例。普通 Win32 工具箱已移除固定外观的上传与拖拽上传控件，改由内置 `lingbuilder.win32.common-controls` 提供非可视 `FileDialog` 资源；同一内置模块还提供非可视 `ContextMenu` / `PopupMenu` 菜单资源及其确定性中文 bindings。new_emoji 上传桥接只保留旧项目兼容。AI 和普通示例不得为了文件选择或原生菜单功能自动加入 `lingbuilder.new_emoji.ui`，确实使用 new_emoji 时仍应优先使用稳定的 `NE_创建*` 命令，不要默认生成底层 `NE_EU_*` UTF-8 指针调用。

项目启用 new_emoji 后会把同名基础设计器模型直接映射到 new_emoji 后端，因此模块作者不得让 `designerControls`、桥接头文件和生成器支持列表彼此不一致。暂未适配的控件必须保持可诊断禁用，不能静默生成 Win32 替代品。

ListBox 的 `items` 是创建期简单项目；`listBoxItemsEx` 仅用于带 key、父级、分组、文本、值、图标、描述、标签及状态字段的高级 TSV 项目。生成器只有在高级项目非空时才应用 `EU_SetListBoxItemsEx`，并跳过空选中 Key 与零虚拟项目数量，防止上游 Setter 抹掉已经创建的静态项目和默认选择。

RichList 使用 `lingbuilder.new_emoji.ui/RichList` 命名空间类型。`templateJson`、`itemsJson` 和 `selectedKeys` 直接对应上游 UTF-8 JSON ABI；普通属性映射到 `EU_SetRichListOptions`、`EU_SetRichListStyle`、`EU_SetRichListScroll` 和 `EU_SetRichListVirtualItemCount`。`SelectionChanged` 返回选中 key JSON，六类语义事件共用 `EU_SetRichListEventCallback` 时必须在 `eventBindings[]` 中声明 `payloadEvent`，由生成器按 JSON 的 `event` 字段分流。

F5/导出生成器会在控件与“创建完毕”处理器完成后、进入消息循环前调用 `NE_显示并激活窗口`。桥接实现必须恢复和刷新窗口，短暂使用最上层层级确保窗口可见后立即以 `HWND_NOTOPMOST` 还原，并请求前台、激活与焦点；受 Windows 前台锁限制时可以临时用 `AttachThreadInput` 连接当前线程与原前台线程，但完成后必须立即分离。不能让窗口永久“总在最前”，也不能要求模块使用者修改 `.lcpp` 才能正常显示。

可运行验收：exe 同目录必须存在 `new_emoji.dll`，启动后至少 3 秒仍在运行；从 IDE/F5 后台启动时无需点击任务栏即可看到窗口，且窗口不保持永久置顶。

## 9. 内置多线程模块参考

`多线程模块` 的模块 ID 为 `lingbuilder.threading`，当前版本为 `2.0.0`。模块从 `threadingModule.ts` 的单一目录生成 54 条 contribution、binding、补全和示例，并公开 `线程任务`、`线程任务状态`、`线程池`、`线程互斥锁`、`线程原子整数`、`线程同步事件`、`线程信号量` 7 个不透明受管类型。

- 任务：`线程_提交`、`线程_提交完成`、`线程_提交进度`，以及状态、取消、等待、进度、错误、释放和清理命令。
- 线程池：项目默认池和最多 16 个自定义池；支持提交、并发数/队列/运行状态、等待空闲、协作停止、关闭、重启和销毁。自定义池并发数为 1～64，队列容量为 1～100000。
- 同步：非递归定时互斥锁、64 位原子整数/CAS、自动或手动重置事件和有上限的计数信号量。全部对象使用项目级 64 位受管 ID，不暴露 Win32 `HANDLE` 或 C++ 指针。

工作处理器必须以 `&处理器名` 引用，`参数...` 数量不设人为上限，并与处理器形参逐项匹配。提交时按值深拷贝基础值、文本、字节集、数组、项目记录、模块公开 `record` 和嵌套组合，也允许本模块自己的受管同步句柄；`controlRef`、其它模块 `opaque`、原生句柄、裸指针、引用及不可复制对象会在语言服务阶段被阻断。

工作返回 `T` 时，完成处理器签名为 `(线程任务, T)`；工作返回空时只接收任务。进度处理器固定接收 `(线程任务, 整数型百分比, 文本型说明)`，进度按 80ms 合并。进度和完成处理器通过发起窗口的 UI dispatcher 执行；工作处理器不能调用 UI/controlRef 命令。窗口关闭只取消本窗口排队任务并请求运行任务协作退出，其他窗口任务继续运行。

2.0 不兼容删除原 9 条演示命令。旧源码会得到阻断诊断和人工迁移建议，不会自动创建处理器或改写源码结构。完整命令表、示例和安全边界见模块随包文档 `electron/docs/modules/threading/README.md`。模块作者不得通过 manifest 注入任意 C++、裸线程入口、强制终止、挂起/恢复、DLL 注入或跨线程控件引用。

- `EdgeView_创建实例` / `EdgeView_创建区域`：按实例编号创建多个浏览器。每个实例可指定不同 User Data Folder，使 Cookie、LocalStorage、缓存和登录会话相互隔离。
- `EdgeView_绑定事件`：按中文事件名动态绑定完整事件目录；`EdgeView_等待事件` 使用分事件计数等待，不会因 Web 资源、下载进度等高频事件覆盖“最近事件”而漏掉目标。

- `EdgeView_执行JS(脚本)`：执行 JavaScript，等待 WebView2 异步回调后返回 JSON 编码结果（字符串结果包含 JSON 引号）。
- `EdgeView_执行JS实例(实例编号, 脚本)`：在指定浏览器实例执行 JavaScript 并取得独立返回值。

- `EdgeView_导航`、`EdgeView_后退`、`EdgeView_前进`、`EdgeView_刷新`、`EdgeView_关闭`：提供基础浏览器生命周期操作。

生成工程使用 Microsoft Edge WebView2。LingBuilder 会从 `NUGET_PACKAGES` 或用户 NuGet 缓存发现最新 `Microsoft.Web.WebView2`，复制 `WebView2.h`、环境选项头文件和匹配 Win32/x64 的 Loader；机器仍必须安装 WebView2 Runtime。缺少 SDK 时会给出中文构建诊断，不会静默换成旧版 IE WebBrowser 控件。设计器控件使用稳定生成 ID 作为内部实例编号，旧项目手写数字实例时应避免与生成控件编号混用，常规新项目优先使用按控件名命令。执行 JS 的同步返回封装会泵送当前线程消息并设置 15 秒超时；耗时业务应避免在高频界面事件中反复调用。

## 11. 内置 CEF3 浏览器模块参考

`CEF3浏览器模块` 的模块 ID 为 `lingbuilder.cef3.browser`，属于内置界面模块，基于 Chromium Embedded Framework 3。它是 `contributes.designerControls` 设计器控件高级贡献的参考实现之一：项目启用该模块后，窗口设计器控件工具箱会自动新增一个 `CEF3浏览器 (CefBrowser)` 控件，可以在任意窗口中添加多个实例，并在属性面板中配置常用参数。

### 11.1 设计器控件

`CefBrowser` 控件声明 `nativeAdapter: cef3-browser` 和 `libcef.lib`、`libcef_dll_wrapper.lib`，并把导航、JS、事件命令同时注册到 `contributes.commands` / `bindings.commands`。控件支持的专属属性（`properties[]`）包括：

- `url`（打开地址）：浏览器初始加载的 HTTP/HTTPS 或本地文件地址。
- `cacheDir`（缓存目录）：Chromium 缓存、Cookie、LocalStorage 存放目录，默认 `.cef3/cache`。
- `userAgent`（User-Agent 标识）：自定义浏览器 UA 字符串。
- `enableJs`（启用 JavaScript）、`enableDevTools`（允许开发者工具）、`loadImages`（加载图片）、`enableWebGL`（启用 WebGL）、`muteAudio`（静音）。
- `proxyMode`（代理模式：system / none / custom）与 `proxyServer`（自定义代理地址）。

控件事件来自 `cef3BrowserEvents.ts` 的 CEF 150 兼容目录，共 92 项用户事件名称，对应覆盖目录 113 条官方事件签名，当前已全部由 Bridge 真实接通。目录、模块清单、设计器事件面板和 C++ 生成器必须消费同一来源；原有 `开始加载`、`加载完成`、`加载失败`、`标题被改变`、`地址被改变` 的设计器事件 ID 保持兼容。同步决策、通知、高频音频/进度事件的线程、默认动作和字段约定以 `electron/docs/modules/cef3/events.md` 为准。

面向用户的完整 CEF3 事件与接口参考位于模块详情可直接打开的 `electron/docs/modules/cef3/README.md`。该文档由 `electron/scripts/generate-cef3-fbro-event-docs.ts` 从 `cef3BrowserEvents.ts`、安全覆盖目录和实际模块 manifest 生成，当前统一列出 92 项事件名称、113 条官方事件签名和 10 个模块中的 373 条用户接口，并明确区分目录契约与原生实现状态。修改 CEF3 事件或命令清单后必须运行 `cd electron && npm run module:cef3-docs`，并用 `npm run module:cef3-docs:check` 阻止文档漂移。

多实例与所属窗口：`CefBrowser` 是可视控件，添加到哪个窗口就属于哪个窗口；在同一窗口或多个窗口中都可以添加任意多个 CEF3 控件，每个控件按中文控件名定位，互不干扰。

### 11.2 中文命令

- `CEF3_创建(控件名)`：使用属性面板配置的地址、缓存目录和代理初始化浏览器；传空控件名时初始化当前窗口全部 CEF3 控件。窗口创建完毕时会自动调用一次。
- `CEF3_导航(控件名, 地址)`、`CEF3_后退(控件名)`、`CEF3_前进(控件名)`、`CEF3_刷新(控件名)`、`CEF3_停止(控件名)`、`CEF3_关闭(控件名)`。
- `CEF3_打开原生UI浏览器(控件名, 地址)`：使用 CEF Chrome Runtime、空父句柄和独立根 HWND 创建带原生地址栏和完整浏览器界面的桌面顶层窗口，并归入指定内嵌控件的 popup 生命周期；不得复用所属 LingBuilder 窗口的 HWND。
- `CEF3_执行JS(控件名, 脚本)`：执行 JavaScript。
- `CEF3_取标题(控件名)`、`CEF3_取地址(控件名)`、`CEF3_取最近事件(控件名)`、`CEF3_取事件数据(控件名)`；复杂事件使用 `CEF3_取事件字段(控件名, 字段名)` 读取 `url`、`frameId`、`statusCode`、`progress`、`commandId` 等命名字段。
- `CEF3_取资源地址(相对路径)`：把相对路径解析为随程序一起部署在 exe 同级 `assets/` 目录下的文件，返回已按 UTF-8 百分号转义的 `file:///` 地址，用于加载本地测试页；传入盘符绝对路径、UNC 路径或已带协议的完整地址时原样返回，可重复套用，且不依赖浏览器控件实例。**接收它的地址形参在 C++ 侧是 `const wchar_t*`，所以必须先把结果赋给文本型局部变量再传给 `CEF3_导航`**（`局部 文本型 地址 = CEF3_取资源地址("index.html")` → `CEF3_导航(浏览器1, 地址)`）；直接内联嵌套会生成 `std::wstring` 传 `const wchar_t*` 而编译失败。模块若随包分发本地 HTML/CSS/JS/图片，必须部署到该 `assets/` 目录并让示例用本命令寻址，**不得要求用户在 `.lcpp` 源码里写死机器特定的绝对路径**，否则示例无法复制迁移。
- `CEF3_设置缓存目录(控件名, 目录)`、`CEF3_设置代理(控件名, 代理地址)`：需在创建前调用。
- `CEF3_绑定事件(控件名, 事件名, 处理器名)`：把任意目录事件回调到当前窗口无参数中文事件；也可直接使用设计器事件绑定。
- `CEF3_设置事件结果(控件名, 结果)`：只在同步决策事件处理期间使用，`0=默认、1=允许/继续、2=拒绝/取消、3=已处理`；`CEF3_设置事件返回文本` 用于返回下载路径、修改后的 URL、对话框输入或认证信息。

“新窗口打开前”返回 `1` 或保持默认会让 CEF 创建独立原生 popup；返回 `2` 取消，返回 `3` 表示当前 LCPP 已接管。生成运行时把 popup 与主内嵌浏览器分开登记，popup 不得覆盖主浏览器句柄、地址/标题/加载状态或导航目标；关闭控件和所属主窗口时必须关闭全部受管 popup。主动创建完整谷歌原生 UI 窗口应调用 `CEF3_打开原生UI浏览器`，由运行时设置 `CEF_RUNTIME_STYLE_CHROME` 并直接创建受管顶层窗口，不能依赖可能被弹窗策略拦截的脚本 `window.open`。

#### 11.2.1 内嵌浏览器与谷歌原生 UI 的宿主边界

这两种浏览器形态必须使用不同的 Win32/CEF 创建参数，不能只靠窗口标题或控件尺寸区分：

- 内嵌浏览器：使用 `CefWindowInfo::SetAsChild(浏览器控件宿主HWND, CefRect)`，其 Chromium 内容属于设计器 `CefBrowser` 控件，必须跟随主窗口和控件尺寸变化。
- 谷歌原生 UI 浏览器：使用 `SetAsPopup(nullptr, 窗口标题)`，随后保持 `parent_window = nullptr`，添加 `WS_EX_APPWINDOW`，移除 `WS_CHILD`，并设置 `runtime_style = CEF_RUNTIME_STYLE_CHROME`。这样 CEF 才会创建拥有独立根 `HWND`、Windows 标题栏、Chrome 标签页、地址栏和菜单的桌面顶层窗口。
- 已确认的错误写法：`SetAsPopup(主窗口HWND, ...)` 或把 LingBuilder 主窗口句柄写入 `parent_window`。Chrome Runtime 会复用该句柄层级，结果是 Chrome 原生 UI 覆盖进主窗口客户区，看起来像又在内嵌窗口里创建了一个浏览器。
- 主浏览器和原生 UI 窗口仍应复用同一个受管 `LingCefClient`，但必须分别保存为主浏览器句柄和 `popupBrowsers` 集合。popup 回调不能回写主窗口地址栏、标题、加载状态或前进后退状态；关闭所属控件或主窗口时必须关闭全部受管 popup。
- 不要用脚本 `window.open` 代替主动创建命令：没有真实网页用户手势时可能被 Chromium 标记为 `Pop-up blocked`。主动创建统一调用 `CEF3_打开原生UI浏览器`；网页真实链接产生的新窗口继续由 `OnBeforePopup` 的允许/取消/接管结果控制。

2026-07-28 已用 `src/cef3-2` 实机验证：左侧 LingBuilder 主窗口保持工具栏和内嵌百度页面，右侧同时出现带独立 Windows 边框、Chrome 标签页和地址栏的谷歌原生 UI 浏览器；两个窗口可独立移动和调整大小。

CEF 回调不都运行在 Win32 窗口线程。生成运行时通过专用消息把普通通知异步投递到所属窗口，把需要立即返回结果的回调同步投递；音频数据包、下载和加载进度按受控频率采样。模块不得从 CEF IO/音频线程直接执行窗口业务代码。
- `CEF3_是否可后退(控件名)`、`CEF3_是否可前进(控件名)`、`CEF3_是否加载中(控件名)`。

### 11.3 运行与构建边界

- CEF3 同一 exe 共享 Chromium 多进程运行时，但每个控件由 Bridge 创建独立 `CefRequestContext`；实例缓存目录安全映射为全局 `root_cache_path` 的直接子目录，Cookie、缓存和代理按实例隔离。
- 生成工程使用受控 CEF3 SDK：LingBuilder 会发现已安装 SDK，只把 `LingBuilderCefBridge.h`、导入库、Bridge DLL、CEF 运行时 DLL 和资源物化到项目；应用不复制 CEF 头，也不直接链接 libcef/wrapper。缺少或损坏 Bridge/SDK 时必须给出中文阻断诊断。
- 链接 `.lib` 需要 MSVC / Visual Studio Build Tools；只检测到 g++/clang++ 时给出中文诊断。
- CEF 150 头文件要求 C++20，且预编译 `libcef_dll_wrapper.lib` 使用动态 CRT `/MD`。LingBuilder 会把这两个要求统一写入 F5、AI Bridge 和导出的 `.vcxproj`；Debug 配置保留调试信息但使用 `NDEBUG`，避免 `_DEBUG` 与 `/MD` 组合产生 Debug CRT 链接符号。看到 `<concepts>` STL4038 或 `convertible_to` C2061 时应重新生成工程，不要修改 SDK 头文件。
- 当前按需下载的 CEF 150 SDK 仅支持 x64。新项目启用 CEF3 时 IDE 会自动从 Win32 切换到 x64，F5/解决方案构建前还会再次校正，因此模块作者不应宣称可运行的 32 位 CEF 产物。
- IDE 构建目录内生成的 `.vcxproj` 把 exe 输出到 `$(Platform)/$(Configuration)/bin/`，与 F5 的运行时资源目录对齐。CEF3 验收必须同时检查 exe、`libcef.dll`、`v8_context_snapshot.bin` 和 Resources，不能只检查 MSBuild 退出码；`generated/cpp` 还要单独检查对外可移植文件集。
- LingBuilder 严格精简发布仍须先校验源 CEF3 SDK 制作来源；`win-unpacked` 与最终 NSIS 不得含 `lingbuilder.cef3.sdk` 或 `lingbuilder.fbro.sdk` 的任何模块目录、清单、README、SDK 或二进制，发现任一路径即终止发布。需要浏览器能力的用户必须另行安装受控完整模块目录或独立模块包。`package:dir` / `package:win` 的前后钩子和安装包归档校验不得绕过。
- CEF3 以子进程方式复用宿主 exe；入口 `wWinMain` 先调用 `LB_CEF3_ExecuteSubProcess`，Bridge 内部执行 `CefExecuteProcess`。应用层不得直接调用 CEF 生命周期 API。
- 可运行验收：exe 同目录必须存在 `libcef.dll`、`chrome_elf.dll` 和 CEF 资源文件，启动后浏览器区域应能加载网页。

## 12. 常见错误

- `schemaVersion 必须为 2`：旧 v1 模块需要重新迁移或重新打包。
- `binding 引用了未贡献的命令`：先在 `contributes.commands` 中声明中文命令。
- `模块命令缺少 v2 binding`：命令能补全，但无法确定性生成 C++，需要补 `bindings.commands`。
- `命令 X 缺少 bindings.commands 映射：编辑器能补全，但无法生成 C++ 调用；请让 AI 补上同名 binding。`：`contributes.commands` 里的这条中文命令没有同名 binding。整体缺少 `bindings` 或 `bindings.commands` 时，全部命令都会逐条报出这条诊断。
- `模块包中包含不安全路径`：检查路径中是否有绝对路径、空段或 `..`。
- `new_emoji 模块需要 MSVC`：安装 Visual Studio 2022 或 Visual Studio Build Tools。

## 13. IDE 与 CLI 路径边界

模块开发者中心的 HTTP 接口只接受当前工作区内的相对路径：模板和迁移输出必须在 `.lingbuilder/module-build`，模块包必须在 `.lingbuilder/module-packages`，市场索引必须直接写入 `.lingbuilder`。界面中的手册入口由桌面宿主打开打包资源，不依赖开发机绝对路径。

命令与 binding 的成对检查只在 IDE 的两处强制执行：「导入 AI 生成的文件」（写盘前先严格校验，未通过时一个文件都不写）和「③ 校验模块」。CLI 的 `module validate` / `module pack` 仍使用默认清单口径，不会因缺少 binding 直接报错，但缺少 binding 的模块在编辑器里只有补全、F5 无法生成调用，作者仍需自行补齐。

需要迁移或打包工作区外的本机 C++ 库时，请使用 `lingbuilder module ...` CLI 并显式传入本机路径。CLI 能力不会放宽 IDE HTTP 接口的工作区边界。

LingBuilder 已按精易模块的能力分类整理出内置分类模块库。完整、可核对的模块 ID、命令数量、能力边界和验证状态见根目录 `MODULE_ENCAPSULATION_CHECKLIST.md`。

内置分类模块的清单位于：

- `electron/src/services/modules/standardLibraryModules.ts`
- `electron/src/services/modules/systemLibraryModules.ts`
- `electron/src/services/modules/networkLibraryModules.ts`
- `electron/src/services/modules/dataMediaModules.ts`
- `electron/src/services/modules/platformAdvancedModules.ts`

对应 C++ 运行时位于 `electron/src/services/windowDesigner/*LibraryRuntime.ts`，由 `lingCppWin32Project.ts` 根据当前项目启用模块确定性注入。新增内置模块不得把运行时重新堆回 React 组件或 Monaco 封装。

内置模块通过同一份命令规格生成 `contributes.commands` 和 `bindings.commands`，避免两份清单漂移。每个新增分类模块必须同时提供 Win32/x64 target，并通过真实 Visual Studio 双架构编译验证。

外部 `.lbmod` 不会自动获得 x64 target。只有不携带架构相关二进制的 LingBuilder 内置模块会从 Win32 系统 target 补齐等价 x64 target；第三方模块仍须为每个架构提供正确的 `.lib`、`.dll` 和源码声明。

以下运行边界必须明确保留：

- `lingbuilder.database.sqlite@2.0.0` 是动态桥接模块，保留 7 条默认连接兼容命令并公开 67 条生产接口。新代码使用受管 `SQLite连接` / `SQLite语句`，通过预编译语句完成 NULL、整数、长整数、小数、UTF-8 文本和 BLOB 参数绑定/逐列读取，并显式管理事务、保存点、WAL、Online Backup、中断和错误码。模块不得暴露 `sqlite3*` / `sqlite3_stmt*`，不得把外部输入拼入 SQL，不得用文件复制替代活动库备份；连接关闭必须兜底释放所属语句，活动资源存在时必须拒绝切换或卸载 DLL。
- SQLite 项目仍需提供与目标架构一致的官方 `sqlite3.dll`。生产发行必须固定来源、版本、文件大小和 SHA-256，分别验证 Win32/x64，禁止自动下载“最新版”或把单架构 DLL 复制到两个输出。SQLite 默认不提供数据库加密，模块文案和 AI 不得虚构加密能力。正式说明位于 `electron/docs/modules/sqlite/README.md`，原生验收命令为 `npm run smoke:sqlite-native`。
- `lingbuilder.net.mail` 当前只支持普通 SMTP，不支持 STARTTLS，不能用于传输真实生产凭据。
- `lingbuilder.archive` 只调用 Windows 自带 `tar.exe` 的固定 ZIP 参数，不接受任意命令行。
- `lingbuilder.advanced.*` 模块属于高风险能力，不能成为普通项目默认引用，也不能由 AI 静默启用。

## 外部设计器目录与商业授权

带设计器控件的 v2 模块可在 manifest 的 `designer` 字段声明版本化目录文件、后端 ID、schema 版本和 SHA-256。`contributes.designerControls` 中的控件必须使用稳定命名空间 ID，并声明属性分组、基础/高级级别、结构化编辑器、事件参数和真实运行时创建命令。React 只渲染目录，不应再按第三方控件名称硬编码属性。

命令的 `visibility` 可取 `default`、`advanced`、`internal`。`advanced` 命令仍参与已有源码的解析、诊断和生成，但只有用户开启底层 API 显示后才进入补全；`internal` 不进入用户补全。

官方收费模块由 LingBuilder 云端按稳定 `moduleId` 绑定商品，manifest 中的价格或免费标记不可信。第三方模块不得自行绕过主进程 Permit、构建守卫或 AI Bridge 守卫。商业控制不改变源码可复制原则：已经合法导出的 C++、Visual Studio 工程和原生文件不会被追溯加锁。

## 声明设计器容器布局

新增容器控件必须在 `contributes.designerControls[]` 中同时设置 `isContainer: true` 和 `layout`：

```json
{
  "type": "FlowPanel",
  "namespacedType": "example.ui/FlowPanel",
  "label": "流式面板",
  "isContainer": true,
  "layout": {
    "mode": "flow",
    "coordinateSpace": "parent",
    "orientation": "vertical",
    "acceptedDesignerTypes": ["Button", "Label"]
  },
  "defaultProps": { "width": 320, "height": 240 }
}
```

标准模式包括 `absolute`、`flow`、`stack`、`grid`、`dock`、`slots` 和 `single`。粘贴时 IDE 会先计算整个控件树的布局计划，任一节点不兼容就整体取消，不会部分写入。`custom` 只能由受信任适配器或声明式隔离插件实现，不得把函数代码写入 manifest。

分页控件必须使用 `slots`，且页面槽位应使用与标题分离的稳定 ID。`lingbuilder.new_emoji.ui/Tabs` 是参考实现：设计器用 `TabControl` 兼容预览呈现标签头，用页面 ID 保存 `containerSlot`；原生生成时每个页面对应一个独立 Panel，并由 `EU_SetTabsPageElements` 切换显隐。new_emoji Tabs 的页面 Panel 必须与 Tabs 同级并覆盖其内容矩形，不能挂为 Tabs 子元素，因为上游 Tabs 自绘不会自动绘制子树；同时必须明确设置为无边框、0 圆角。绑定外部页面后，`ItemsEx` 的内容字段必须为空白，不能继续让 Tabs 在 Panel 下方自绘标签内容。容器模式必须开启内容区，不能把整个设计高度误作标签头高度。

内置 Win32 容器同样必须在 manifest 中声明布局：`GroupBox` 使用 `absolute` / `win32.groupbox.absolute`，`TabControl` 使用 `slots` / `win32.tab.slots`。布局适配器 ID 必须与 `DesignerContainerLayoutRegistry` 注册值一致，不能依赖打开项目时的 legacy absolute 回退。

## 字符编码命令的字节边界

LingCpp 的 `文本型` 是 Unicode 文本，模块不得把 UTF-8、GBK、UTF-16 等任意原始字节直接伪装成文本返回；原始字节可能包含零字节或非法 Unicode 序列，会造成截断或数据损坏。

真实二进制通道是 `字节集`（binding 类型 `bytes`，跨边界为 `std::vector<unsigned char>`）。需要按编码解释字节时直接用 `编码_字节集转文本(数据, 编码名称)` 与 `编码_文本转字节集(文本, 编码名称)`，不要先把字节摊成文本再猜编码。十六进制文本（`编码_文本转GBK` / `编码_GBK转文本` 一族）只在必须把字节塞进纯文本载体（配置项、命令行、日志、JSON 字段）时才使用。

编码模块的 `contributes.commands` 与 `bindings.commands` 必须一一对应；每种声称支持的编码都必须在目标 C++ 运行时存在真实实现并通过非法输入、BOM、非 BMP 字符和往返转换测试。ANSI 指运行机器当前 Windows 系统代码页，不应宣传为固定 UTF-8 或 GBK。GB2312 输入必须执行严格字节范围校验，不能简单把整个 CP936/GBK 范围都当作 GB2312。

编码名称解析、BOM 检测、代码页编解码和文件解码的唯一实现位于
`electron/src/services/windowDesigner/textCodecsRuntime.ts`（`TEXT_CODECS_RUNTIME`）。任何需要按编码读字节的模块（含第三方模块运行时）都必须复用这份内核，禁止再写一套 `MultiByteToWideChar` 代码页映射或自己维护编码名白名单。

## 表格数据源与 CSV/虚拟表直连

跨 CSV、Excel 和 SQLite 的表格读取共享同一段内核，作者新增数据源或消费方时必须遵守：

- 记录级 CSV 解析（引号内换行、双写引号、CRLF/CR/LF、自定义分隔符、空行跳过）与 `表格数据` 快照句柄注册表只有一份，位于
  `electron/src/services/windowDesigner/tabularSourceRuntime.ts`。禁止在别的运行时片段里再写一个 CSV 状态机。
- 共享内核**不在各模块运行时里拼接**，而由 `generateSharedTableRuntime(enabledModuleIds)` 在装配层（`lingCppWin32Project.ts` 的两处 main.cpp 模板）按启用模块铺设一次。新增消费模块时只需把模块 ID 登记进 `SHARED_TABLE_CHUNKS` 的 `requires`，不得改回字符串前缀拼接——那会让同一个编译单元出现两份定义。
- 快照句柄的名义类型是 `表格数据`（`cppType: 'long long'`），行号与列号统一从 1 起、行号不含表头。新数据源（如 Excel 转表格）必须产出同一份 `表格数据`，让 `数据表_*` 成为唯一消费入口。
- `CSV_打开文件`、`CSV_解析文本` 之类的可选参数，**运行时 C++ 形参必须带默认实参**，且默认值与清单 `defaultValue` 逐字一致：生成器只翻译源码里写出的实参，不会替省略的可选参数补值，缺默认实参会直接编不过（C2660）。
- `SQLite` 模块的 `csv` 虚拟表把同一份记录内核暴露成 SQL 表：`CREATE VIRTUAL TABLE t USING csv(filename='a.csv', schema='(列 INTEGER, 列 TEXT)', header=1, encoding='AUTO')`。它复用 `sqlite3_create_module`/`sqlite3_declare_vtab`/`sqlite3_malloc64`/`sqlite3_mprintf`/`sqlite3_result_text` 这些**可选导出**，缺少时只关闭虚拟表能力、不得让普通 SQL 打开失败；能力状态必须经 `SQLite_取虚拟表支持` 可见。
- 虚拟表相关内存有硬边界：vtab、cursor 和 `zErrMsg` 必须由 SQLite 自己的分配器分配（它会在回调之外 `sqlite3_free`），模块侧 C++ 对象只能挂在 `impl` 指针上、由我们在 `xDisconnect`/`xClose` 里 `delete`。`sqlite3_vtab` 之类的 ABI 结构必须逐字段对齐官方布局，向下取回对象要用首成员偏移为 0 的 `reinterpret_cast`（不是继承，`static_cast` 非法）。
- 编码 `AUTO` 的判定顺序固定为 **BOM → 严格 UTF-8 → GB18030 兜底**，不做启发式猜测；显式指定编码解码失败必须返回失败并给中文原因，禁止静默换一种编码重试。
- 原生验收：`cd electron && npm run smoke:csv-sqlite-native`（Win32/x64 双架构编译 + exe 逐项自检，覆盖 GBK、BOM、跨行字段、分隔符、类型判定、虚拟表 SELECT/入库/JOIN/表头不计入数据行）。

## OpenCV 这类大型原生 SDK 的封装参考

LingBuilder 内置 `lingbuilder.opencv` 采用“用户模块 + 隐藏资产模块”模式，适合体积大、需要独立许可证、只允许固定 ABI 的第三方 C++ 库：

- 用户模块只声明中文 contribution、binding、公开类型、文档、示例和精确 target，不携带上游 C++ API。
- 隐藏的 `lingbuilder.opencv.sdk` 只携带稳定 C ABI 头、导入库、运行时 DLL、许可证和逐文件 SHA-256 清单；项目不能单独启用资产模块。
- 生成代码不得暴露 `cv::Mat`、STL、异常或所有权不清晰的指针。跨 DLL 的对象统一转换为带类型的 64 位受管句柄，文本使用“查询长度 → 调用方分配缓冲区 → 再读取”的 C ABI。
- 包含中文路径的图像文件不能直接依赖窄字符 `imread/imwrite`；参考实现使用 Win32 宽字符文件 I/O 读取/写入字节，再调用 `imdecode/imencode`。
- target 必须准确表达 `windows-msvc-x64`、C++17、动态 CRT 等边界。只有 x64 资产时，不得生成 Win32 配置或等待链接器报错；模块依赖服务应在生成前给出中文阻断诊断。
- 资产清单至少固定上游版本、Bridge 版本/ABI、架构、工具集、CRT、文件大小和 SHA-256。校验时还必须确认所有必要文件都出现在哈希清单中，不能只检查“文件存在”。
- F5、Visual Studio 导出、AI Bridge、原生导出和源码包恢复必须复用同一物化服务。禁止为某个入口直接复制 DLL 或跳过摘要校验。
- OpenCV 参考脚本：`cd electron && npm run module:opencv-sdk -- --install`；原生验收：`npm run smoke:opencv-native`。

## Win32 数据表格 DataGrid（schema v1）

`lingbuilder.win32.common-controls` 从 0.2.5 起提供独立可视控件 `DataGrid / 数据表格`。它不是 ListView 的别名，也不会改变 ListView 现有接口。控件清单使用 `nativeAdapter: "lingbuilder-datagrid"`，属性类型 `dataGridColumns`、`dataGridRows` 只能保存可验证的结构化数据，禁止注入脚本或裸 C++。

进度列由 DataGrid 主 HWND 自绘。轨道高度和圆角按窗口 DPI 缩放，进度文字在完整单元格文本区域内垂直居中，模块或后端适配器不得把文字裁剪到较窄的轨道矩形中。

按钮列按当前原生字体测量完整按钮文字，再按窗口 DPI 计算内边距、间距和点击区域。绘制、悬停和点击必须共用同一布局；仅当整组按钮确实无法放入单元格时显示“更多”，不能用固定像素宽度截断中文按钮名。普通、主操作、危险、禁用、悬停和“更多”按钮统一使用随 DPI 缩放的 4 逻辑像素 GDI+ 抗锯齿圆角填充与描边，保持紧凑工具界面风格，禁止退回直角矩形绘制。

列类型固定为 `text`、`integer`、`decimal`、`date`、`checkbox`、`switch`、`image`、`progress`、`combo`、`buttons`。列和按钮必须使用稳定 ID，行必须使用非空且唯一的稳定行键；运行时通过“行键 + 列 ID”访问单元格。列对齐使用 `left/center/right`，默认 `center`，可通过结构化属性或 `表格_设置列对齐` 修改并同步到原生表头与单元格绘制。组合框把稳定值与显示文字分开，按钮点击事件返回原始按钮 ID，图片支持项目路径和 ImageList。图片显示方式为互斥枚举 `tile/contain/cover/center/stretch`，分别表示平铺、等比完整显示、等比铺满裁剪、原始大小居中和拉伸填充；旧项目未填写时默认 `contain`。

表格命令的唯一目录位于 `electron/src/services/modules/dataGridApiCatalog.ts`，清单作者不得单独复制命令列表。目录会同步产生 `contributes.commands`、`bindings.commands`、Monaco 普通/成员补全和 C++ 符号测试。普通 Win32 后端支持这些命令；new_emoji 后端会在生成 C++ 前阻断 `表格_` 命令。旧 `lingbuilder.new_emoji.ui/Table` 只迁移为统一编辑模型，必须保留其 `namespacedType`、后端和既有 `EU_SetTable*` 生成行为；结构化 `dataGridColumns/dataGridRows` 在 new_emoji 生成时使用 `EU_SetTableData` 的基础列/行 ABI，只有明确为字符串列表的旧 Ex 数据才允许调用 `EU_SetTableColumnsEx` / `EU_SetTableRowsEx`。

当前目录提供 92 条命令。`表格_取进度状态` 返回进度单元格的 `normal/success/warning/error/paused/indeterminate` 状态，`表格_取行是否选中` 按稳定行键读取选择状态。CSV/TSV 接口读写文本；`表格_导入Excel(控件名, 文件路径, 首行为标题)` 与 `表格_导出Excel(控件名, 文件路径, 包含标题)` 直接读写 `.xlsx`，使用 Windows 自带压缩组件和 SpreadsheetML，不要求安装 Microsoft Excel。Excel 首版只处理第一个工作表且仅支持静态模式；图片列导出图片路径文本，不把图片二进制嵌入工作簿。

源码包使用 DataGrid 控件或 `表格_` 命令时必须声明 `requiredCapabilities: ["win32.datagrid.v1"]`，最低生成器版本为 `0.2.5`。

## 键盘输入类模块的作用域说明

键盘输入类模块不得把“查询全局状态”、“向当前前台焦点注入”和“向指定 HWND 投递后台消息”混成一组含糊命令。`contributes.commands[].category` 和中文说明必须同时标明：

- 是全局状态、前台输入还是指定窗口后台消息。
- 是否切换或抢占焦点，实际接收者是顶层窗口还是焦点子控件。
- 是否锁定/独占实体键盘，还是只在系统输入流中与用户按键共享。
- 返回成功是代表系统已接受输入，还是仅代表窗口消息已入队。
- UIPI、安全桌面、Raw Input/DirectInput 和目标程序过滤等平台限制。

内置参考实现为 `lingbuilder.input.keyboard@2.0.0`。普通模块不应公开 `BlockInput`、隐藏低级钩子或按键记录；如确需全局热键事件，必须设计可注销、可回收、有明确处理器生命周期的受管契约。

## 鼠标输入类模块的三类作用域

鼠标输入类模块必须把真实系统输入、指定 HWND 消息和 UI Automation 语义操作分开，不能只用“全局鼠标”一个含糊分类。`contributes.commands[].category`、binding 参数类型和中文说明必须同时标明：

- 全局真实输入（前台）还是指定窗口/UIA 的后台操作；全局查询可读光标但不移动，真实移动和 `SendInput` 按键/滚轮会改变或占用系统鼠标输入流。
- 窗口消息命令的目标参数必须是 `handle`，表示真实 Win32 `HWND`；客户区坐标和屏幕滚轮坐标必须按 Windows 消息定义区分。
- UI Automation 查找命令的窗口参数必须是 `handle`，返回值必须是模块受管元素句柄；不得暴露裸 `IUIAutomationElement*` 或让调用者把元素句柄当作 HWND。
- 每条命令描述必须明确“前台/后台”和“会/不会移动或占用系统鼠标”。`PostMessageW` 成功只表示消息入队，UIA 成功只表示对应 Pattern 调用成功；目标程序仍可以忽略、过滤或因权限隔离失败。
- 相对移动参数只能描述为相对输入增量；Windows 鼠标速度和加速度会影响实际位移，不得承诺严格像素映射。

内置参考实现为 `lingbuilder.input.mouse@2.0.0`，文档为 `electron/docs/modules/mouse/README.md`。生成 Win32/new_emoji 工程时，若启用该模块，必须在 `CoUninitialize` 前清空 UIA 元素表，避免 COM 引用在 COM 运行库卸载后释放。

## 控件参数必须声明为 `controlRef`

模块命令参数引用设计器对象时，不能再使用文本型。完整参数示例：

```json
{
  "name": "控件名",
  "type": "controlRef",
  "controlTypes": ["Button", "Label"],
  "controlKinds": ["visual"],
  "scope": "currentWindow",
  "runtimeRepresentation": "wideName"
}
```

- `controlKinds` 可取 `visual`、`nonVisual`、`resource`；`scope` 可取 `currentWindow`、`project`；`runtimeRepresentation` 可取 `wideName`、`stableId`、`nativeHandle`。三项必须显式声明。
- contribution 的 `insertText` 和 binding 的 `example` 必须插入裸名称，例如 `控件_设置文本($1, "$2")`、`控件_设置文本(操作结果, "完成")`。`控件_设置文本("$1", "$2")` 会被模块校验拒绝。
- 不能通过把参数改名来绕过门禁；“控件名、组件名、图像列表、菜单组件”等明显对象参数若声明为 `wideString` / `utf8String` 会被拒绝。确属普通文本时应使用不会冒充设计器对象的准确参数名和说明。
- 模块 SDK、Monaco、新手编辑器、C++ 生成和 UI 后端消费同一 binding。模块作者不得另写只在某个编辑器生效的控件名解析器。
- `runtimeRepresentation: "stableId"` 和 `"nativeHandle"` 由当前窗口实例解析，生成结果分别传入稳定整数 ID 或真实 `HWND`；模块头文件必须使用与 binding 一致的参数类型。源码型模块的 `wideString` 实参既可能是 `L"字面量"`，也可能是 `控件_取文本` 生成的 `std::wstring`，公开 C++ 函数应接受 `const std::wstring&` 或等价适配层，不能只验证字面量调用。
- 发布前运行 `npm run module:control-ref-audit`、`npm run module:control-ref-migration-check`、模块校验和演示深度验证；全量审计摘要变化必须由真实方法/参数变更解释，不能只更新快照绕过失败。门禁同时扫描模块源目录的原始补全、示例和 snippet，不能依赖加载时自动去引号来掩盖清单源码中的旧写法。

## 函数指针回调、结构化集合与稳定关系

- 原生头文件或 `.def` 对应参数是函数指针 typedef 时，binding 必须声明 `type: "handler"` 并给出完整 `handlerSignature.parameterTypes` 和 `returnType`。`.lcpp` 示例、snippet 和补全统一插入 `&处理器名`；把 callback 声明为 `int`、字符串或缺少签名会被清单校验拒绝。
- 处理器签名必须覆盖原生回调的参数数量、顺序、类型和返回值；跨 DLL 需要 `__stdcall` 等调用约定时由受控 C++ 适配器实现，不能要求用户写裸函数指针、地址或手工转换。
- 可重复结构化属性使用 `recordList`，声明稳定 `recordKey` 和每个字段的类型、默认值、必填、枚举或引用约束。通用集合编辑器、设计器预览、序列化和原生生成共同消费该 schema；模块不得为每个集合在 React 中硬编码专用 JSON 表单。
- dropdown、anchor、popup、submenu、target、container 等跨控件关系必须声明 `controlRef` 的 `controlTypes`、`controlKinds`、`scope` 和 `runtimeRepresentation: "stableId"`。设计器模型保存稳定对象 ID，生成器先创建全部对象，再执行关系 setter；旧数字只有在能唯一恢复时才迁移，`0` 迁移为未绑定。
- `lingbuilder.new_emoji.ui@2.0.0` 是参考实现：93 个控件和 3784 条 contribution/binding 由 `new_emoji.def`、`exports.h`、`element_types.h` 与设计器目录生成。发布前运行 `npm run module:new-emoji:check`，确保临时生成、module-build、已安装模块和 `.lbmod` 的 manifest、文档及文件哈希一致。
- `lingbuilder.new_emoji.fbro-shell@1.0.0` 是外部伴随宿主参考实现，仅支持 `windows-msvc-x64`。`BrowserViewport` 只声明布局/状态占位，真实网页由每标签独立 FBro 句柄和非分层顶层工具窗口 `HWND` 渲染；伴随宿主必须同步占位区屏幕坐标、DPI、显隐、层级和销毁，不能嵌入 `WS_EX_LAYERED` 主窗口。模块文档必须明确依赖、平台阻断、处理器签名和完整 `.lcpp` 示例。完整浏览器外壳模板固定 1180 x 760；发布可分享实例时必须使用 `npm run demo:new-emoji-fbro-shell:export`，并验证输出 `.lcpppkg` 同时携带源码、设计器、x64 配置与受管 SDK 资产。

## 构建生成器、字节集与 Protobuf

模块清单 v2 的 `build.codeGenerators[]` 只能选择 IDE 已注册的受控 Provider，声明输入 glob、输出产物类型、target 和结构化 options。不得声明 `buildSteps`、Shell/PowerShell、任意 exe 路径或 JavaScript。Provider 版本、输入/输出路径和 target 由宿主校验，生成器只返回构建步骤与产物描述；真正进程执行、取消、权限和回滚由 Build Service 负责。

模块使用二进制数据时必须声明 `bytes`，用户可见类型名为“字节集”。`raw` 只用于 opaque 原生值；名称或说明表示真实字节序列的旧 binding 会被迁移诊断阻断。跨 DLL 的 bytes ABI 固定为 `const unsigned char* data + size_t size` 输入，以及调用方先查询长度、再提供缓冲区写出的输出；模块不得跨边界传递 STL 或释放调用方内存。空数据、零长度、长度溢出和所有权必须有测试。

Protocol Buffers 首版模块 ID 为 `lingbuilder.data.protobuf`，Provider 为 `lingbuilder.protobuf.protoc@1.0.0`。SDK 必须离线放置在 `.lingbuilder/toolchains/protobuf`，固定版本为 27.3.0；`runtime-manifest.json` 必须登记 `protoc.exe`、C++ 头文件、导入库和 DLL 的大小与 SHA-256。缺少清单、必要文件、哈希不一致、目标架构不支持或版本不符时，F5、AI Bridge、CLI 和 Visual Studio 导出均必须在编译前阻断，不得使用系统 protoc 或自动联网下载。生成的 `.pb.h`、`.pb.cc`、descriptor set、`.proto` 输入和运行时依赖必须进入可复制导出目录。

Provider 会递归解析本地 `import`，所有 import 文件都参与增量缓存指纹并复制到构建树和可复制导出树。代码生成步骤先写入宿主 staging 目录，只有全部声明产物成功后才原子提交；失败或取消不得留下半成品。

## new_emoji Tabs 页面创建顺序与 Container 尺寸（2026-08-02）

- `lingbuilder.new_emoji.ui/Tabs` 的生成顺序是强制契约：先创建所有页面 Panel、页面内普通控件和外部宿主，再调用 `EU_SetTabsPageElements` 绑定页面；页面切换不能只改可见状态来替代布局初始化。
- `Container` 的设计器宽高不得被 new_emoji 默认 `fill_parent` 覆盖。模块生成脚本必须为 Container 注册 `EU_SetPanelLayout(hwnd, element_id, 0, 0)` 的固定 setter，并公开默认开启的 `flowEnabled` 属性；绝对坐标容器必须显式生成 `EU_SetContainerLayout(hwnd, element_id, 0, ...)`。模块包回归测试同时检查尺寸和流式布局开关。
- 修改 Tabs、页面槽位或 Container runtime mapping 后，必须用真实多页项目验证设计器与 F5/VS 导出的页面位置一致，至少覆盖中间页（例如 17–24）和包含 Container 的页面。

## 声明可由代码创建的可视控件

第三方模块可按同一契约预留运行时控件能力，但当前不强制加入。每个可代码创建的可视 `designerControls[]` 项应声明 `runtimeControl`：唯一 `lingCppType`、C++ 包装类型、创建命令、创建参数角色、两种标记查找命令、有效性命令、允许父级和标记作用域。命令 contribution、binding、运行时实现、模块文档与示例必须同时存在。

创建 binding 的父级必须声明为 `controlRef`，并使用当前后端需要的 `stableId` 或 `nativeHandle`；标记文本和标记整数是尾部可选参数，分别提供空字符串和 `null` 默认值。整数标记必须使用 int32，并保留 `0` 与负数。非空标记必须在当前窗口、具体控件类型和标记类别内唯一。

查找命令必须按具体类型生成并返回该 `lingCppType`，不能返回普通整数、文本或无类型“控件”。控件类型需登记在 `contributes.types[]`，C++ 使用非拥有型 `LingControlRef` 或等价安全包装；窗口/容器拥有实际对象，销毁后引用自动失效。无效引用上的所有操作必须安全失败并记录中文原因。

专属命令的控件参数应声明准确 `controlTypes`。若底层 ABI 使用元素 ID，单一输入 ID 使用 `controlRef(stableId)`；`int*` 输出参数、请求 ID、数据 ID、索引、数量和 ID 数组不得误标为控件。动态事件必须从控件事件目录生成类型化绑定/解绑命令，handler 参数保留完整 `handlerSignature` 和 `&处理器名` 语义。

代码创建对象默认不写回设计器模型。控件引用仅允许局部变量、方法参数和返回值，不得通过模块命令把引用存入全局、记录、数组或工作线程。发布前除常规校验外，应覆盖空标记、`0`、负数、重复、缺失、失效、错误父级、错误类型、事件解绑和 Win32/x64 原生编译。

## 15. Windows DLL 项目开发

Windows DLL 项目使用解决方案模板 `windows-dll` 创建，项目类型标记为 `windows-dll`，不包含窗口设计器运行时。首版会生成以下文件：

- `DllMain.cpp`：最小 `DllMain` 和 `LingBuilder_GetApiVersion` C ABI 示例。
- `include/DllExports.h`：调用方使用 `__declspec(dllimport)` 的公开声明；DLL 导出名由 `exports.def` 统一维护。
- `exports.def`：稳定导出名列表，供链接器生成导出表和导入库。
- `lingbuilder.dll.json`：schema、输出名、公开头文件、源文件、DEF 文件、ABI 和调用约定。
- `<项目ID>.sln`、`<项目ID>.vcxproj`、`<项目ID>.vcxproj.filters`：Win32/x64、Debug/Release 的 Visual Studio 工程。

### DLL 中使用新手模式 `.lcpp`

DLL 模板可以直接在工作台的新手模式编辑 `.lcpp`。模板默认生成 `DllApi.lcpp`，其中的 `获取接口版本()` 返回值会在受控 MSBuild 前被读取并生成到 `DllMain.cpp` 的 `LingBuilder_GetApiVersion()`；例如把 `返回 (1)` 改为 `返回 (2)`，下一次构建的导出函数就返回 `2`。这是一条确定性的示例映射，不代表任意中文过程都会自动变成 DLL 导出 ABI。

DLL 项目没有窗口设计器模型，编辑器仍提供 `.lcpp` 的结构编辑、补全、诊断和 Monaco 专业模式；涉及控件引用或窗口事件的语法在 DLL 项目中没有设计器上下文，应报告诊断而不是伪造窗口。需要界面时，由宿主程序调用 DLL 导出的 C ABI 创建和管理窗口，不能在 `DllMain` 中启动消息循环。

新增公开函数时，先更新头文件、DEF 和清单，再添加实现和测试。跨 DLL 接口必须保持 C ABI；字符串使用明确的 UTF-16/UTF-8 约定，字节使用指针加长度，资源使用不透明句柄和成对的释放函数。不得把 `std::string`、`std::vector`、异常或调用方无法判断生命周期的裸指针放进公开签名。

构建入口由 `ExternalProjectService` 统一调用 MSBuild，输出目录为 `src/<项目ID>/<架构>/<配置>/bin`。服务优先使用 `LINGBUILDER_MSBUILD_PATH`，其次查找 Visual Studio 2019/2022 的标准安装目录，最后才回退到 PATH 中的 `msbuild`。成功的 DLL 构建必须同时产生 `<项目ID>.dll` 和 `<项目ID>.lib`，并在导出或运行前完成架构、CRT、模块资产和文件哈希校验；缺少工具链时只能生成工程和给出中文前置条件诊断。

## Aria2 模块封装要求（2026-08-15）

`lingbuilder.net.aria2@1.37.0` 是一个内置 Windows x64 模块。模块贡献、binding、文档和示例位于 `electron/src/services/modules/aria2Module.ts` 与 `electron/docs/modules/aria2/`；生成器实现位于 `electron/src/services/windowDesigner/aria2Runtime.ts`。模块只允许固定下载 API，不接受任意 aria2 参数或任意可执行文件路径。

启用模块的 F5、原生预览和 Visual Studio 导出必须通过统一原生依赖服务复制并校验 `aria2c.exe`、`COPYING` 与 `NOTICE.md`。运行时只能启动生成程序同目录的 `aria2c.exe`，下载任务必须在结束或取消后调用 `Aria2_释放`。`Aria2_下载` 的进度参数必须声明为可选 `handler`，使用 `&下载进度` 引用；固定签名为 `(Aria2任务, 整数型, 长整数型, 长整数型, 长整数型, 文本型) -> 空`，运行时必须通过受控窗口消息回到创建任务的 UI 线程，禁止下载线程直接调用 LCPP 处理器。速度应优先解析 aria2 `DL:` 输出，文件大小差只能作为回退。原生验收命令是 `cd electron && npm run smoke:aria2-native`，它必须编译 x64 导出工程并完成一次包含回调、非零速度和 Range 续传语义的本地 HTTP 下载。首版不提供跨平台 target；新增 RPC 或其它平台实现时，必须同步更新清单、binding、C++ 运行时、文档、AI 规则和测试。

## 与「项目 DLL 命令声明」的边界

只在单个项目内使用的 DLL 可免封装：项目 `src/项目DLL命令.lcpp` 声明 `DLL命令库` + 导出函数（公开=导出、命令名即导出名），构建期自动生成导入库（lib.exe /def，按实际导出表）并复制 DLL 到 exe 旁，中文命令即声明命令。需要分发、上架市场、带设计器控件或复杂桥接时仍走本手册的完整模块封装。详见 `docs/DLL封装成模块操作手册.md`。
