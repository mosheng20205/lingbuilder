## FBro 弹窗顶层窗口控制三命令 + 浏览器创建形态总览（lingbuilder.fbro.browser 2.13.0）

### 更新内容

**背景**：外部 AI（经灵码 MCP）误报「FBro 模块没有创建独立顶层弹窗的命令」——它只看到 `FBro_后台创建` 无窗口、`FBro_创建` 依赖设计器控件，漏掉了实例族的 `FBro_实例打开原生UI`。用户要求：① MCP 文档强调弹窗链并说明 FBro 浏览器创建的几种形态；② 给 FBro 弹窗加位置/尺寸控制。

1. **MCP_INSTRUCTIONS 第 22 条扩写**（`electron/src/services/aiBridge/mcpServer.ts`）：
   - 新增「FBro 浏览器创建形态总览」：四种创建入口（①设计器控件进程内嵌入＝`FBroBrowser` 控件+`FBro_创建`；②动态内嵌区域＝`FBro_创建区域`；③后台无窗口实例＝`FBro_后台创建`；④独立顶层弹窗＝③+`FBro_实例打开原生UI`），另注多标签独立进程 Host 走 new_emoji 外壳。
   - 新增「反误解红线」：FBro 弹独立顶层窗没有名字带「创建」的命令，形态④是同一条弹窗链的先后两步。
   - 新增弹窗边界命令口径（设置/回读/取 HWND）。
2. **新增三命令**（生成器运行时两后端同步：标准 Win32 窗口类成员函数 + new_emoji 后端自由函数）：
   - `FBro_实例取窗口句柄(实例句柄)` → 长整数型：顶层（承载）窗口 HWND。

## new_emoji Tree 行布局 DPI 修复 + indentWidth/iconWidth/rowHeight 选项（lingbuilder.new_emoji.ui 2.1.0）

### 更新内容

修复 new_emoji `Tree` 控件在高清屏（150%/200% DPI）下「节点 emoji 图标压住文字」的行布局缺陷，并补齐与 ListBox 同构的三个行布局可选项。引擎真源 `T:\github\new_emoji`（element_treeview.h/.cpp），模块 2.0.0→2.1.0。

- **根因**：TreeView 行布局全部是未按 DPI 换算的固定物理常量——图标列 22px 盒 + 24px 步进、层级缩进 18px/级、展开箭头 ±(2~5)px、复选框 14×14、行首偏移 10/14/16/22px；而 `style.font_size` 已含 DPI 缩放（200% 下 13 号字=26 物理像素），emoji 字形 advance ≈1.0~1.2×字号，溢出 22px 图标盒压到文字上（用户实测重叠 3.0 逻辑像素）。
- **修复**：行首全族常量改按 `dpi_scale` 换算（100% DPI 时与历史值逐一相等，零回归）；自动图标列宽 = max(24×DPI, 字号物理值×1.3 + 4×DPI)（emoji advance 之外保底 ≥4 逻辑像素文字间隙）；行高下限 30→30×DPI。
- **新增选项**（逻辑像素，树数据 JSON 根对象或 `NE树_设置选项JSON` 均可传）：`indentWidth` 层级缩进/级（默认 18，钳 8~64）、`iconWidth` 图标列总宽（缺省/0=自动，钳 1~96）、`rowHeight` 行高（缺省/0=随字号=字号物理值×2.25，钳 16~120）；三者原样读回 `NE树_取状态JSON`。节点 JSON 协议（key/label/icon/children/expanded/disabled/tag/badge）不变。
- **已知坑入册**：IDE 树数据编辑对话框回写 treeDataJson 只保留 `{"data":[...]}`，会丢弃选项键——选项要写在代码自拼的 JSON 里或用 `NE树_设置选项JSON` 单独设置（已写进 MCP 第㉓条/规则手册 11.11/newEmojiDataFormats 契约注释）。
