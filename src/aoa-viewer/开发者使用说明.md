# USB 多机投屏群控 · 开发者使用说明

> 适用工程：`aoa-viewer`（MirrorDesk USB 投屏台 v4 · USB 直传专用版）
> 配套手机端：LingBuilder 投屏伴侣 **v1.4.6+**（本工程源码目录内已捆 `lingbuilder-companion-v1.4.6.apk`）
> 读者：把本工程分发给最终用户部署的开发者 / 排查「USB 直连连不上」的人。

---

## 0. 快速上手（TL;DR）

一台全新 Windows + 一台全新 Android，从零到出画面一共五步：

| 步骤 | 机器 | 动作 | 一次性？ |
|---|---|---|---|
| 1 | PC | 安装 WinUSB 驱动（见 §2.1，三种方式任选） | ✅ 每台 PC 一次 |
| 2 | 手机 | 安装投屏伴侣 APK v1.4.3+（微信/QQ/MTP 任意方式发过去） | ✅ 每台手机一次 |
| 3 | 手机 | 打开投屏伴侣 →「开始投屏」→ 系统弹窗「立即开始」 | ✅ 每台手机一次（授权） |
| 4 | 手机 | **保持投屏伴侣在前台**，USB 数据线插上 PC | 每次连接 |
| 5 | PC | 磁贴自动出现 → 排队接通 → 画面上墙 | —— |

日常使用之后只剩第 4 步：**插线即用**，全程无 Wi-Fi、无 adb、无 root、无手抄地址。

## 1. 系统组成

```
┌─ PC（aoa-viewer，本工程 F5 构建）──────────────────────┐
│  设备池（并行数组，槽号=会话内首次见到顺序）              │
│  ├ 自动接入巡检：每 ~2s 扫 AOA_取设备列表，新机入池入队   │
│  ├ 打开队列：一次一台串行 AOA_打开设备（切配件最长 45s）  │
│  ├ 轮询泵 15ms/拍：预算巡游排空 USB 数据通道（≤16 通道/拍）│
│  ├ 帧管线：JPEG 双缓冲落盘 aoa_d<槽号>_0/1.jpg           │
│  └ WebUI：mirrordesk.html（EdgeView file:// 直载）       │
└──────────────┬──────────────────────────────────────────┘
               │ USB：视频帧 LBAC 通道1 / 控制 JSON 通道2 / AOA HID 触控
┌──────────────┴──────────────────────────────────────────┐
│  手机（投屏伴侣 v1.4.3+）                                │
│  MediaProjection 采集 → JPEG（默认缩放 0.5 / 质量 70）    │
│  USB 直传：投屏运行+配件在位 → 自动接通 bulk 通道推帧      │
│  HID 触控：PC 经 AOA HID 注入（免调试免 root）            │
└──────────────────────────────────────────────────────────┘
```

三个部件各司其职，**都不可缺**：

| 部件 | 载体 | 版本要求 | 缺了会怎样 |
|---|---|---|---|
| PC 查看器 | 本工程 F5 构建 / 分享包导入 | — | —— |
| 投屏伴侣 APK | 手机 | **v1.4.6+（硬性）** | ≤1.4.1 无 USB 推帧代码必黑屏；≤1.4.3 无包可见性声明；≤1.4.4 无剪贴板指令；≤1.4.5 无应用列表指令 |
| WinUSB 驱动 | PC | 1.1.0.5（随包 `driver/`） | 设备列表显示「需驱动」，**一台都连不上**（见 §2.1） |

## 2. 全新机器部署（排障请直接跳 §5）

### 2.1 安装 WinUSB 驱动（PC，一次性，最常见失败点）

手机切到配件模式后是一个自定义 USB 设备（`18D1:2D00` 等），Windows **不会**自动给它装 WinUSB——没有驱动，`AOA_打开设备` 直接打不开。验证当前机器是否已装：

```powershell
pnputil /enum-drivers   # 找「原始名称: lingbuilder-aoa.inf」
```

设备管理器里插上手机（配件模式）应出现「**LingBuilder AOA Accessory (WinUSB)**」而不是黄色感叹号。

**方式 A · 离线强配（推荐，随包自带，需管理员）**

```powershell
# 驱动在导入后的工程目录：src\aoa-viewer 同级的模块目录下
# .lingbuilder\modules\lingbuilder.aoahid\driver\
pnputil /add-driver "lingbuilder-aoa.inf" /install
```

INF 已签名（签名者 LingBuilder AOA Driver，1.1.0.5），覆盖四类硬件 ID：
`2717:FF40`（小米普通模式）、`18D1:2D00`（AOA 配件）、`18D1:2D01&MI_00`（配件+调试）、`12D1:107E`（华为配件）。
装完**重插一次数据线**生效。

**方式 B · Zadig 引导（有网机器）**

模块命令 `AOA_安装驱动(序列号)` 会自动下载并拉起 Zadig，分步中文指引写在 `AOA_取错误()`。
红线：Zadig 里的安装动作需人工确认（UAC 提权），命令返回假属正常。
手动等价操作：Zadig → 菜单 Options 勾「List All Devices」→ 下拉选「LingBuilder AOA Accessory / Android Accessory Interface」→ 驱动选 **WinUSB** → Replace Driver。

**方式 C · 检查表（两种方式装完仍不行）**

- 设备管理器该节点是否报错代码：Code 10（CM_PROB_FAILED_START）= 描述符僵死，禁用/启用该设备或换口重插；
- 换一条**数据线**（市场上大量线是纯充电线，无数据脚，枚举不出来什么都白搭）；
- 直插主板后置口，别经过劣质 hub。

### 2.2 安装投屏伴侣（手机，一次性）

APK 在本工程源码目录 `lingbuilder-companion-v1.4.6.apk`（分享包已捆）。微信/QQ/MTP 任意方式发到手机安装（允许「未知来源」）。**旧版三坑：≤1.4.1 没有 USB 推帧代码；≤1.4.3 缺包可见性声明（launchApp 查不到第三方应用）；低版本后台杀恢复差**。务必核对版本（app 标题栏显示 v1.4.4）。

### 2.3 手机侧准备

1. 打开投屏伴侣 →「开始投屏」→ 系统弹窗「立即开始」（MediaProjection 授权，每台一次）。
2. 后台白名单：MIUI 最近任务卡片上锁；鸿蒙 电池-启动管理 改手动允许。MIUI 杀后台是隔夜掉线的第一原因。
3. 手机**不需要**连 Wi-Fi——投屏和触控流量全部走 USB 线，移动数据照常独立使用。

## 3. 日常使用

### 3.1 自动接入（默认开）

- 泵每约 2 秒巡检一次 USB 设备列表；「配件模式+可打开」和「普通模式（有序列号）」的手机自动入池排队。
- 「打开队列」一次一台串行接通：普通模式机型要切配件模式，**每台需 5~45 秒**（界面上队列数字递减）。
- 页面顶栏「自动接入：开/关」可挂起；「全部断开」会同时挂起自动接入（防止立刻被接回去），点「接收全部设备」或磁贴「接通」恢复。

### 3.2 操控

- 磁贴画面：单击=真实点击，按住拖动=真实滑动（AOA HID 硬件级注入）。
- 工具条：接通 / 唤醒 / 主页 / **返回**（AOA 多媒体键）/ 通知栏 / 截图 / **文本输入**（弹窗打字进手机输入框，英文数字）/ 找图点击（识图→坐标映射→真实点击）。
- 底部批量条：**同步操控**（开群控：任一画面的手势广播到目标手机——勾选磁贴=只广播勾选集合，全不勾=广播全部已接通）/ 全部唤醒 / 批量截图 / **启动App**（输入包名批量拉起）。
- **群控的完整方案（分层能力、协议配方、规模守则、路线图）见 §8。**

### 3.3 规模

架构支持几百台槽位。规模化三板斧已内置：轮询预算巡游（每拍最多排空 16 通道）、不可视磁贴 2 秒一帧节流（页面只轮询视口内磁贴）、打开队列串行。真实并发上限取决于 USB 控制器与 **HUB 供电**——多台务必用带独立供电的 Hub。

## 4. 工作原理（开发者视角）

### 4.1 设备池（`项目全局变量.lcpp` + `功能/群控库.lcpp`）

- 并行数组：`池设备[]`（AOA设备 句柄）/ `池序列号[]` / `池通道[]` / `池已开[]` / `池可见[]` / `池待重试[]` / `池错误[]` …，下标=槽号-1。
- 槽号=会话内首次见到该手机的顺序，**整场稳定**；拔线只标「USB 已拔出」不清条目，重插复用。
- 序列号查找一律 `_wcsicmp` 大小写不敏感（MIUI/驱动层回报大小写不稳定，精确比较会重复入池）。
- MIUI 配件模式读不到序列号的机型用产品名占位，模块侧「唯一空序列号配件」兜底打开。

### 4.2 连接状态机

```
巡检发现新序列号 → 入池 → 入队
队列（一次一台）→ AOA_打开设备(序列号)   ← 同步阻塞，切配件最长 45s，禁止并发
  成功 → 池已开 → AOA_打开数据通道 → 发 wakeScreen → 等手机推帧
  失败 → 池错误=原因 → 消费「待重试」标志（防风暴）
会话死（拔出/重枚举）→ 池掉线：关通道+关设备 → 池待重试=真 → 巡检见到设备回来自动重接
```

### 4.3 帧管线（红线）

- 泵 15ms 一拍，**预算巡游**每拍最多排空 16 个通道（空轮询一次约 1ms），泵游标轮转保证每台都被持续排水。
- **手机侧发送端在 PC 停止收帧时会阻塞**——所有已开通道必须被持续读取，不许只挑着收；`AOA_数据通道收帧` 超时**禁传 0**（libusb 0=永久等待）。
- 帧判别：首字节 255=JPEG（>1KB 才收），否则=控制 JSON（env 心跳 / 指令回执 / screenInfo，UTF-8 经 std.buffer 解码）。
- 落盘：`帧基址`（exe 目录）+ `aoa_d<槽号>_0/1.jpg` 双缓冲；可视槽每帧写，不可视槽 2 秒一帧（页面 IntersectionObserver 上报名单 `{action:'visible', list:"1,3,7"}`）。
- 页面解析顺序（全便携）：exe 同目录 → CWD → 从 exe 目录向上 ≤6 级找 `src\aoa-viewer\mirrordesk.html`。**源码里禁止出现本机绝对路径回退**（分享包在别的机器必死）。

### 4.4 手机侧 USB 直传触发条件（APK 1.4.3）

1. 投屏会话运行中检测到配件附着（ATTACHED 广播）→ 自动接通；
2. 投屏会话启动完成且配件已在位（`accessoryList` 兜底）→ 自动接通；
3. 主界面轻量通道在投屏运行时自动让位（前台持有 fd 会锁死服务通道——1.4.3 修复）；
4. 失败原因直接显示在 app「USB 直传」按钮上（失败(原因)），不再静默；
5. 手动按钮保留：手机上点「USB 直传」可强制开/关。

### 4.5 坐标回映射（找图点击）

`queryScreen`（需伴侣 v1.4.0+）→ `screenInfo{realWidth,realHeight,frameWidth,frameHeight}` →
手机坐标=帧坐标×realWidth/frameWidth → HID 逻辑坐标=手机坐标×32767/realWidth。
实现全在 `功能/坐标映射.lcpp`，未校准时换算一律返回 -1，调用方必须判负。

## 5. 故障排查手册（按症状）

### 5.1 插上手机，墙上完全没反应

按顺序查：

0. **看页面顶部橙色横幅**（v4.1 起）：软件会自动检测两类「插了但接不上」的障碍并提示——
   「USB 调试开启 N 台」（MIUI 的 FF48 复合设备，免调试链路无法接管，手机上关闭「USB 调试」后重插）
   和「缺 WinUSB 驱动 N 台」（按 §2.1 装随包驱动）。旧版包无此横幅时按下面顺序手工排查。
1. **线**：换一条确认能传数据的线（充电线枚举不出来，占此故障的大头）。
2. **手机上选 USB 用途**：部分机型插线弹「仅充电/传输文件」，选**传输文件（MTP）**。
3. **列表里有没有它**：`viewer.log` 或页面控制台看 `AOA_取设备列表`——行格式 `序列号|产品名|模式|驱动状态`：
   - 有行但「序列号|产品名」双空、模式=普通模式 → **手机开着 USB 调试（FF48 复合设备）**，
     用户态驱动无法接管且被自动过滤——症状就是「插了但零设备且无任何提示」；关闭手机「USB 调试」重插即解；
   - 完全没有该机 → 线/口/手机 USB 模式问题；
   - 有，但模式=配件模式、驱动状态=**需驱动** → §2.1 装驱动；
   - 有，模式=普通模式 → 正常，自动排队切配件（等待即可）。
4. **USB 调试是否开着**：开着 = `2717:FF48` 复合设备，Windows 拒绝用户态驱动接管，三路全堵。**目标形态必须关闭 USB 调试**（装了 UsbDk 时模块有后备通道，但不要依赖）。
5. **adb/scrcpy 是否在跑**：libusb 与 adb 互斥，打开前必须退出 adb、scrcpy/QtScrcpy。

### 5.2 `AOA_打开设备` 失败文案对照表

| 文案（viewer.log / 磁贴） | 含义 | 处置 |
|---|---|---|
| 手机未保持配件模式（设备已回退） | 切换成功但手机退回了普通模式 | **多为投屏伴侣没在运行**——解锁手机打开 app，或重插（app 活着时重插会自动接通） |
| 配件设备驱动绑定未完成 | 配件节点出现了但驱动没绑上 | 等 30 秒自动重试；仍不行 → §2.1 重装驱动 |
| 等待配件设备重枚举超时（45 秒预算用尽） | 手机拒绝/忽略 AOA 切换 | 重插一次（手机保持解锁）；重插仍失败 = 机型限制（见 §5.6） |

### 5.3 磁贴显示「USB 已通 · 等手机侧投屏」

USB 链路已通，手机侧投屏会话不在跑：解锁手机 → 打开投屏伴侣 →「开始投屏」。伴侣 v1.4.3+ 装好后这一步之后是全自动的。隔夜后普遍发生（MIUI 杀后台）。

### 5.4 手机上「USB 直传：失败（…）」

1.4.3 起失败原因直接显示在 app 按钮上。常见：
- 「未找到 USB 配件」→ 手机不在配件模式（PC 端还没打开它）→ 重插一次线，让 app 收到配件附着事件；
- 「打开 USB 通道失败」→ 多半 PC 端会话还没建立或刚断，等自动重试；
- 更多细节点 app 里「日志（排查通道问题）」（最近 300 条环形日志）。

### 5.5 画面卡住 / 一动就断

- **熄屏会暂停 MediaProjection**：点磁贴「唤醒」；
- MIUI 冻结后台服务：投屏中尽量让伴侣留在前台或上后台锁；
- 触控首次点击被吃：Android 输入设备挂载竞态，连点两次即可；
- MIUI 弹「已拦截 USB 输入设备」：必须在手机上点允许（磁贴「通知栏」按钮可远程拉下通知栏去点）。

### 5.6 投屏画面里键盘不显示（键盘区域黑屏）

**症状**：手机上弹出输入法键盘，投屏画面里键盘所在区域是黑的，键盘收起后该区域恢复正常；画面其他部分（状态栏、按钮、导航键）始终正常。

**原因**：这是 **Android 系统隐私机制，不是 PC 软件或 APK 的 bug**。录屏管线（MediaProjection）会自动排除被标记为「安全窗口」（FLAG_SECURE）的图层——标记了 secure 的窗口在录屏流里被系统抹成黑块。MIUI 自带输入法（搜狗小米版等）出于防键盘记录/密码窃取的隐私设计，把键盘窗口标记成了安全图层，所以 PC 端收到的原始帧里本来就没有键盘。

**处置**：

1. **换输入法**（最直接）：手机 设置 → 更多设置 → 语言与输入法 → 换成 Gboard、讯飞通用版、百度输入法等不设安全标记的输入法，键盘即出现在投屏画面里。
2. 搜狗小米版可先查输入法设置里有无「安全键盘/隐私模式」开关，关掉试试（部分版本该行为固定，关不掉就换输入法）。
3. **业务上要往手机里打字时，正确姿势不是看键盘**：走 AOA 键盘注入（模块命令 `AOA_键盘输入`/`AOA_键盘按键`），直接向手机当前焦点输入框打字，不依赖输入法界面（查看器磁贴「键盘」工具按钮为下一版占位）。

### 5.6b 「启动App」点了没反应（手机不打开目标应用）

指令已送达手机但启动被系统拦截——**Android 10+ 的后台启动限制（BAL）+ MIUI「后台弹出界面」权限**：投屏伴侣在后台（手机停在桌面）时无权直接拉起其他 App。

**另一个独立坑（易混）**：若回执是「**未安装或无启动入口：包名**」——应用明明装了还报这个 = 伴侣 ≤v1.4.3 缺包可见性声明（targetSdk 34 命中 Android 11+ 包可见性过滤，第三方应用对伴侣隐形），**升级伴侣 v1.4.4+ 即解**；与应用安装状态无关。

**处置（手机上授权两处，一次性）**：
1. 设置 → 应用设置 → 应用管理 → 投屏伴侣 → 「显示在其他应用上层」→ 允许；
2. MIUI 额外一道：安全中心 → 应用管理 → 权限 → 应用「投屏伴侣」→ **后台弹出界面** → 允许。

授权后重新点「启动App」即生效。软件侧已同步：指令回执（成功/失败原因）会显示在状态栏与横幅——再遇「拉起被系统拒绝…」一眼可见，不再静默。package 名写错会回执「未安装或无启动入口」。

### 5.7 机型限制（定案，勿再排查）

| 机型 | 状态 | 原因 |
|---|---|---|
| 小米 8（MIUI 免调试） | **不可用** | MIUI 拒绝 AOA 配件切换（重枚举 45s 超时，与 PC/APK 无关），升级系统才可解 |
| 小米 10 / 华为 Mate40 Pro | ✅ 全链验证通过 | —— |

### 5.8 日志采集

- **PC 侧**：`viewer.log`（exe 工作目录）。关键行：`入池 槽N [序列号] 产品名` / `槽N open [...]` / `槽N ch=N`（通道句柄）/ `槽N openfail 原因` / `槽N 掉线 原因` / `槽N 待重试自动重接` / `槽N 拔线`。

## 7. FAQ

**Q：必须关 Wi-Fi 吗？**
不需要。USB 链路自成一体，手机连不连 Wi-Fi 都不影响；文档强调「不连」是因为这套形态专为零网络环境设计。

**Q：几十台上百台怎么接？**
带独立供电的 USB Hub（每台手机 0.5~1.5A）。软件侧已做预算巡游+可视区节流，几十台无感；上百台建议分控。

**Q：第一次接某台手机时手机弹「允许 USB 配件访问？」**
点允许（可勾默认）。这是 Android 配件权限，装驱动/重插后可能再弹一次。

**Q：手机需要 root / USB 调试 / 厂商授权吗？**
都不需要。三不原则（免调试/免 root/免辅助功能）是本方案的设计前提；反过来，**开着 USB 调试反而连不上**（FF48 复合设备），见 §5.1-4。

**Q：为什么插上后「接通中」要好几秒？**
普通模式 → 配件模式的切换是手机端重新枚举 USB，模块预算最长 45 秒（典型 5~7 秒）。切过一次之后，手机保持配件状态，重连是秒级。

## 8. USB 群控方案

> 目标：一套 PC 同时操作 N 台手机（点按、滑动、启动应用、输入文字、条件化动作）。
> 本节按「能力分层」组织：每层标注 **已落地 / 协议已有未接 UI / 需开发**，按业务需要逐层取用。

### 8.0 能力矩阵总览

| 能力 | 状态 | 载体 | 说明 |
|---|---|---|---|
| 手势同步群控（点/滑广播） | ✅ 已落地 | 底部「同步操控」开关 | 手势三段广播到目标集合：**磁贴勾选框限定范围**（全不勾=全部已接通） |
| 批量唤醒 | ✅ 已落地 | 「全部唤醒」按钮 | 控制通道发 `wakeScreen`（MIUI/鸿蒙熄屏会暂停录屏） |
| 批量截图 | ✅ 已落地 | 「批量截图」按钮 | 每台当前帧存 exe 目录 |
| 批量打开 App | ✅ 已落地 | 批量条「启动App」 | 输入包名广播 `launchApp` 到全部已接通槽位（APK 1.2.0+） |
| 主页键 | ✅ 已落地 | 控制通道 `goHome` | —— |
| 返回键 | ✅ 已落地 | AOA_多媒体键 | Consumer 页 0x224（AC Back）经 HID 注入，不依赖 APK 协议；磁贴「返回」即此路径 |
| 文本输入 | ✅ 已落地 | 磁贴「键盘」按钮 | 弹窗输入→AOA_键盘注入（ASCII）；**中文走「粘贴中文到剪贴板」按钮**：写入手机剪贴板（APK 1.4.5+ `setClipboard`）→ 点磁贴「粘贴」发 Ctrl+V（§8.3） |
| 找图条件操作 | ✅ 单机闭环 | 找图点击按钮 | 识图→坐标映射→注入点击；批量=按槽循环（§8.4） |
| 操作录制回放 | ✅ 已落地 | 批量条「录制/回放/停止」 | 录制进程级单例（群控剧本.csv），回放对全部已接通设备异步执行，进度显示在页面横幅（§8.5） |
| 模块级同步组 | ⚠️ 命令已有 | `AOA_创建同步组` 族 | 组内独立线程按同一目标时刻并行派发，**实测偏差 0~3 毫秒**（§8.3） |

### 8.1 第一层 · 手势同步群控（已落地，零开发）

底部批量条点「同步操控」开启后，在**任一磁贴画面**上的点按/拖动会广播到全部已接通触控的槽位。

- 坐标是 0~32767 **归一化逻辑坐标**（按画面比例落点）——同版本、同布局的 App 表现一致；不同分辨率机型混挂时，按比例对齐而非按像素。
- **目标集合**：磁贴标题行勾选框可限定广播范围——勾选 N 台=只广播勾选集合；全不勾=广播全部已接通。集合在页面勾选时实时上报（`syncSet`）。
- **分组持久化**：批量条「分组」按钮 → 按手机**序列号**保存/应用/删除命名分组（localStorage，重插重启不漂移）。分组对所有批量动作生效：同步操控/启动App/唤醒/截图/回放/粘贴/文本输入。
- 广播实现是 PC 侧逐槽串行派发：几台到十几台无感；**几十台以上起手势会逐台错开**（每台一次 HID 控制传输），对齐精度要求高时改用 §8.3 的模块同步组。
- 适用场景：批量刷短视频/翻页、批量点同一位置的按钮（如签到、同意弹窗）、批量滑动验证。

### 8.2 第二层 · 指令群控（协议即用，建议第一批接入）

控制通道（LBAC 通道 2）的指令协议，APK 1.2.0+ 已支持：

| 指令 JSON | 作用 | 备注 |
|---|---|---|
| `{"cmd":"wakeScreen"}` | 点亮屏幕 | 熄屏会暂停 MediaProjection，先唤醒再投 |
| `{"cmd":"goHome"}` | 回主页 | 依赖「显示在其他应用上层」权限（BAL 豁免） |
| `{"cmd":"launchApp","package":"com.xxx"}` | 启动指定包名 App | **需要权限**：手机必须给投屏伴侣授予「**显示在其他应用上层**」+ MIUI「**后台弹出界面**」，否则系统静默拦截（查看器状态栏/横幅会回显失败原因，见 §5.6b） |
| `{"cmd":"queryScreen"}` | 回屏幕真实/帧尺寸 | 坐标回映射用（v1.4.0+） |

批量配方（viewer 侧按池循环即可，`批量唤醒` 按钮已是现成样板）：

```
计次循环首 (群控库.池数量(), 序号)
    群控库.发槽指令(序号, "{"cmd":"launchApp","package":"com.ss.android.ugc.aweme"}")
计次循环尾 ()
```

批量条「**启动App**」按钮已接本指令：输入包名（localStorage 记忆上次输入）→ 按目标集合广播（点「**拉取**」从第一台在线手机拉取已装应用列表，输入框变下拉选择，需伴侣 v1.4.6+）。

典型组合：**每日开机流程 = 全部唤醒 →（等 3 秒）启动App 目标应用 → 同步操控刷内容**。

### 8.3 第三层 · HID 程序化群控（注入类）

绕过 App 层，直接硬件级注入，按池循环调用 AOA 模块命令：

- `AOA_单击(设备, x, y)` / `AOA_滑动(设备, x1,y1,x2,y2, 时长毫秒)` / `AOA_双击 / 长按 / 捏合`
- `AOA_键盘输入(设备, 文本)`：向当前焦点输入框逐字符输入，**仅 ASCII**——中文会被拒绝并给中文原因。
  中文输入（✅ 已通，APK 1.4.5+）：磁贴「⌨」弹窗输入中文 → 点「**粘贴中文到剪贴板**」→ 文本经控制通道写进手机系统剪贴板（`setClipboard` 指令）→ 点磁贴工具条「**粘贴**」按钮 → PC 注入 Ctrl+V（HID 组合键）完成粘贴。两条动作可对单台或广播全部。
- `AOA_键盘按键(设备, 键码)` / `AOA_键盘组合` / `AOA_多媒体键`：Enter(0x2C)、Escape(0x29) 等键码注入；多媒体键含 **0x224 返回**（磁贴「返回」按钮的实现路径）。
- **文本输入已接 UI**：磁贴「⌨」按钮 → 弹窗输入（可勾选「同时发送到全部已接通设备」）→ `inputText` 动作按池注入。

**模块级同步组（多机对齐正解）**：

```
组ID = AOA_创建同步组()
AOA_组加入设备(组ID, 设备A)   // 循环加入全部目标设备
AOA_组加入设备(组ID, 设备B)
AOA_组单击(组ID, x, y)        // 组内独立线程按同一目标时刻并行派发，实测偏差 0~3 毫秒
AOA_组滑动(组ID, ...)
```

适用：几十台以上、要求手势「同时」发生的场景（同屏抢购、同步翻页计时类）。设备关闭会自动从组内摘除，可重复加入。

### 8.4 第四层 · 找图条件群控（业务闭环）

手势/指令是「无脑广播」，业务上常见「**命中才操作**」（关闭弹窗、等页面加载完再点）：

1. 每台循环：取槽帧文件 → 读字节集 → `识图_模板匹配字节集`（可带区域限定提速）；
2. 命中 → `坐标映射` 帧坐标→手机坐标→HID 逻辑坐标 → `群控库.注入槽点击(槽)`；
3. 未命中 → 该台本轮跳过。

现成样板：磁贴「找图点击」按钮的完整闭环（`MainWindow.lcpp` 的 执行找图点击）。把「自截模板」换成业务目标小图（如弹窗的关闭叉），就是批量弹窗自愈。模板按机型分套维护（分辨率/布局不同时模板不通用）。

### 8.5 第五层 · 录制回放（✅ 已落地）

- **录制**：批量条「录制」按钮 → 本进程**所有** AOA 注入动作录成 `群控剧本.csv`（exe 目录，UTF-8 CSV，时间戳相对开始时刻，格式见模块 docs/剧本格式.md）；再点一次停止。
- **回放**：批量条「回放」按钮 → 设倍速（1=原速）与循环次数 → 对**全部已接通设备**异步执行（每台一个后台任务，进度显示在页面顶栏横幅，约 1 秒刷新）；「停止」按钮协作式中止（当前步执行完退出）。
- 工作流：磁贴上手动做一遍操作（开录制）→ 停止 → 回放批量执行。适合重复性强的固定流程；带条件判断的流程用 §8.4 找图闭环。
- 红线：录制会话内回放产生的动作不会录进去；每台设备同时只能有一个回放任务。

### 8.6 规模与稳定性守则

1. **同一台 PC 只跑一个查看器实例**：USB 设备被进程独占，第二实例里手机显示「需驱动」或不出现（本机双开调试踩过）。
2. 单控制器建议 **≤16~32 台**（USB 控制器带宽 + HUB 供电，每台 0.5~1.5A）；更多分控多 PC。
3. HUB 必须带独立供电；劣质/纯充电线是接入故障第一大户（§5.1）。
4. 手机后台白名单 + 投屏中尽量前台（MIUI 杀后台=隔夜掉线第一原因）；熄屏先「全部唤醒」。
5. 批量动作的目标集合=「勾选分组 ∩ 已接通」（全不勾=全部已接通），分组按序列号持久化（§8.1）。
